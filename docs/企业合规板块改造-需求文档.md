## 1. 背景与问题（v1.0 原文，保留）

「企业合规」板块目前是**知识星球文档库下的一个分类**（路由 `/knowledge-planet/enterprise-compliance`，由通用组件 `KnowledgeDocList` 渲染），本质是**文档文件列表**：仅展示标题、格式、分类、版本、上传人、下载次数、更新时间、状态，无结构化事项展示、无待办机制。

实际使用中，该板块存放的是带强执行约束的合规要求类文件（如《君实合作注意事项》，31 行事项，覆盖立项→财务流程→执行→会后核销→特殊问题全生命周期，含"会后提供核销资料后方可付款"等硬性先后约束）。未来同类文件会持续增加，重要事项将淹没在文档堆里，靠人工翻文件找"下次要做什么"成本高、易遗漏。

**核心痛点**：合规事项看不见、不提醒、不追踪。

> **v2.0 补充背景**：不同员工关注的文档不同，全局统一看板无法回答"我该做什么"。因此引入**个人关注驱动待办**：员工通过收藏（关注）文档，自动获得该文档全部事项的个人待办，可自行跟踪进度、设提醒、加备注——既保留全局结构化看板（维护人维护），又让每个人拥有自己的待办视图。
既保留全局结构化看板（维护人维护），又让每个人拥有自己的待办视图。

> **v3.0 补充背景**：纯"关注驱动"仍有两个缺口——① 被全局事项指为**责任人**的员工，即使不收藏文档也应自动获得待办；② 文档**跨版本更新**（如《君实合作注意事项》v2 更新解析）时，事项与个人进度如何稳定衔接、不丢不乱。v3.0 补齐这两块，同时强化个人记录生命周期、提醒幂等健壮性、事项修改历史与维护人对责任人进度的可见性。

## 2. 目标与非目标

### 目标（v1.0 原文 + v2.0 修订）

1. 将合规文档中的**事项结构化**（自动解析 + 手动兜底），以看板形式直接展示；（保留）
2. 提供**待办提示**（板块内待办卡片 + 站内消息中心推送）；（v2.0 修订：待办改为**个人关注驱动**——我的待办=我关注文档的事项合集，含个人进度/提醒/备注）
3. 支持**责任人 + 状态 + 可选到期日期**的轻量追踪；（v2.0 修订：全局字段由维护人维护；新增个人跟踪状态三档）
4. 与文档生命周期严格对齐，不产生"文档没了事项还在"的脏数据；（保留）
5. 为未来与**项目管理板块联动**预留扩展位；（保留）
6. **（v2.0 新增）个人数据自治**：个人进度/提醒/备注仅自己可见，取消关注后记录保留。

### 非目标（本轮不做）

- 不做完整事项管理的审批流、独立菜单、复杂权限体系；（保留）
- 不做外部触达（企微/邮件等主动推送）；（保留）
- 不做项目管理板块的双向强联动（仅预留字段）；（保留）
- 不新增独立权限码（复用 `knowledge:maintain` + 责任人自校验）；（保留）
- **（v2.0 新增）普通用户不直接修改全局事项**（仅维护人可改全局；个人修改走个人进度通道）。

## 4. 用户画像与核心场景（v1.0 原文 + v2.0 修订）

- **维护人**（KNOWLEDGE_MAINTAINER / 具备 `knowledge:maintain`）：上传合规文档、确认解析草稿、维护全局事项字段（阶段/优先级/责任人/时间要求/到期）、管理全局看板；
- **责任人**（全局事项被指派者）：查看自己负责的事项；v2.0 起全局状态修改收归维护人，责任人个人跟踪通过"我的待办"完成；
- **普通员工**（登录即可）：收藏（关注）文档 → 我的待办自动汇总该文档事项；改个人进度、设提醒、加备注（仅自己可见）。

典型场景（v2.0 修订）：
1. 维护人上传《君实合作注意事项.xlsx》→ 系统自动解析出 31 条事项草稿 → 维护人确认发布 → 全局看板按文档分组展示，同时**自动同步到已收藏该文档用户的我的待办**；
2. 员工进入企业合规页，顶部看到"待办 7 / 近3天到期 1 / 已过期 1"，表格按到期升序、高优置顶列出自己的待办事项；
3. 员工将某事项进度改为"处理中"，追加个人备注"已联系客户负责人确认函件"——仅自己可见；
4. 员工收到站内通知"《君实合作注意事项》事项『现场照片采集』3 天后到期（个人提醒）"，进入页面处理；
5. 员工取消收藏某文档 → 该文档事项移出我的待办，但个人进度/备注/提醒记录保留，重新收藏后恢复并继续自动同步；
6. 文档更新版本 → 重新解析生成草稿 → 确认后替换旧事项，关注者待办自动同步更新；文档下架 → 事项隐藏；永久删除 → 事项删除。

## 5. 功能需求

### FR1 自动解析与草稿确认（v1.0 保留 + v2.0 补充）

- 上传/更新合规文档时，后端同步解析内容：
  - **xlsx/xls**：按表头映射配置解析（列名如 时间节点/项目/内容/备注），映射规则代码级可配；
  - **PDF/DOCX**：文本抽取 + 规则解析（格式多样，需持续维护规则，允许部分失败）；
  - **图片等其它格式**：暂不自动解析，提示手动录入。
- 解析结果生成**待确认草稿事项**（is_draft=1）；
- 上传弹窗提示"已解析 N 条事项，请确认后发布"；
- 解析失败或表头不匹配：静默跳过自动解析，允许维护人手动录入事项；
- 手动录入为兜底能力，任何文档均可手动新增事项。
- **（v2.0 补充）草稿确认发布后**：该文档的全局事项对全员只读可见；**已收藏该文档的用户，其我的待办自动同步新增/更新事项**（关注期间自动同步）。

### FR2 全局事项看板（v2.0 修订：仅维护人可见）

- 入口：板块内"维护人全局看板"按钮，**仅具备 knowledge:maintain 的用户可见**；普通用户不渲染该界面；
- 两种视图切换：**按来源文档分组** / **全部事项聚合**（阶段 + 优先级排序，标注来源文档）；
- 支持搜索（标题/要点内容关键字）与筛选（阶段/状态/优先级）；
- 事项展示字段：标题、要点内容、阶段、时间要求、到期日期、优先级、责任人、全局状态、最后更新人；
- 维护人可编辑全部字段、批量确认草稿、新增/删除事项。

### FR3 我的待办（v2.0 新增，替代原 v1 FR3 全局待办卡片区）

- **口径**：我的待办 = 我收藏（关注）的全部文档 × 该文档已发布（非草稿）的全局事项合集；
- **入口两处**：① 企业合规板块内顶部区块；② 个人中心入口（我的待办）；
- **展示形态**：
  - 顶部统计卡：**待办 N**（我的进度≠已完成）/ **近3天到期 N**（0≤到期距今天数≤3 且未完成）/ **已过期 N**（到期已过且未完成）；
  - 表格列表：事项 / 来源文档 / 阶段 / 优先级 / 时间要求 / 到期 / **我的进度** / 操作；
  - **排序**：按到期时间升序、高优置顶（优先级高在前，同优先级内到期早在前，无到期排后）；
- 每条待办支持：切换**我的进度**（未处理/处理中/已完成 三档，仅本地个人数据）、设**个人提醒**、加**个人备注**。

### FR4 状态管理与责任人（v2.0 修订）

- **全局状态**（未开始/进行中/待确认/已完成）：仅维护人可改，普通用户不直接改全局；
- **个人进度**（未处理/处理中/已完成 三档）：每位用户对每个事项一份，仅自己可见、可改，**不影响全局状态与其他用户**；
- 全局责任人（compliance_item_assignee，多人）：由维护人维护，作为全局字段展示；
- 普通用户只读可见全局事项，可操作自己的个人进度。

### FR5 消息推送（v2.0 修订）

- 新增消息类型：事项发布 `compliance_published`、事项更新 `compliance_updated`、到期提醒 `compliance_due`（个人提醒与全局责任人提醒共用）；
- **发布通知**：草稿确认发布后，推给维护人 + **已收藏来源文档的用户**（复用 `notifyFavoriters` 逻辑）；
- **个人提醒（v2.0 新增）**：对每条我的待办**默认开启**，规则 = 到期前 3 天提醒一次 + 到期当天再提醒一次；每项可**单独关闭 / 调整提前天数**（如提前 7 天）；提醒以站内消息中心推送；
- **全局责任人提醒（保留）**：全局到期提醒推给责任人（维护人可配置提前天数）；
- 状态变更通知：推给维护人；
- 前端 `MessageCenter.vue` 的 TYPE_LABELS 需同步补充新类型映射。

### FR6 生命周期联动（v2.0 修订）

- 文档更新（版本+1）：重新解析生成草稿，维护人确认后**替换**旧事项；**关注者我的待办自动同步**；
- 文档下架：事项同步**隐藏**（数据保留），我的待办中对应事项不再展示；
- 文档永久删除：事项**一并删除**，个人进度记录保留（孤儿数据，UI 不展示）；
- 待办去重：`last_due_notified` 记录最近推送日期，避免每日重复推送（个人维度与全局维度各一份）。

### FR7 手动维护（v1.0 保留）

- 支持维护人手动新增/编辑/删除事项，字段同解析产物；
- 事项表记录 `update_by / update_time`，页面展示"最后更新人"。

### FR8 收藏=关注与取消关注（v2.0 新增）

- **收藏即关注**：复用现有知识文档收藏功能（收藏/取消收藏按钮），收藏后该文档全局事项自动进入我的待办；
- **取消收藏**：该文档事项移出我的待办，**个人记录（进度/备注/提醒）保留**；重新收藏后恢复，并继续自动同步（文档新版本解析、新事项发布）；
- 关注期间文档更新（新版本解析、新事项确认发布）自动同步到我的待办；
- 收藏状态与我的待办在**同一页面可联动操作**（文档库区展示收藏按钮，收藏后事项进我的待办）。

### FR9 责任人自动获得待办（v3.0 新增）

- **我的待办口径扩展**：我的待办 = 我收藏（关注）文档的已发布事项 ∪ **责任人是我的事项**（两条路径均进入待办，自动去重）；
- 普通用户即使未收藏文档，只要被维护人设为某事项责任人，该事项即自动出现在其我的待办中；
- 取消收藏不影响责任人路径（仍作为责任人出现在待办）；
- 新事项发布 / 责任人变更时，新责任人自动获得待办并收到消息中心通知"你被设为 XX 事项责任人"。

### FR10 事项跨版本稳定标识与匹配（v3.0 新增）

- 每个事项带 **item_code**（跨版本稳定标识）：首次解析生成后固定不变，文档更新重解析时用于识别"同一事项"；
- 记录 **document_version_id / previous_item_id / change_type**（新增/修改/删除/不变），形成事项版本血缘；
- **匹配规则**（文档更新重解析时执行）：
  1. 标题完全相同 → **自动匹配**，继承个人进度/备注/提醒记录（不丢）；
  2. 标题归一化（去标点/空格/前后缀）相同 或 文本相似度 ≥80% → **待维护人确认匹配**，确认前个人记录保留在旧对应事项上；
  3. 其余 → 视为**新增事项**（草稿）或旧事项**停用**；
- 草稿确认页**可视化显示匹配结果**："自动匹配 N 条 / 待确认 M 条 / 新增 X 条 / 停用 Y 条"，维护人可手动纠正；
- 匹配确认动作写入事项历史（审计）。

### FR11 个人记录生命周期（v3.0 修订）

- **彻底分离**：收藏关系（knowledge_favorite，决定展示）与个人事项记录（compliance_user_progress，业务历史）互不删除；
- 文档下架 / 事项停用 → 当前待办隐藏对应事项，**个人记录保留**；
- 文档恢复 / 事项恢复 / 重新收藏 → 进度恢复展示，继续自动同步；
- 事项被跨版本替换 → 个人记录随 item_code 自动迁移到新事项（自动匹配场景），或保留在旧事项上（待确认场景）；
- 取消收藏 → 个人记录保留；重新收藏 → 恢复；
- 本轮只完成**数据链路**，不新增"历史待办"UI（下轮实现）。

### FR12 维护人查看责任人进度（v3.0 新增）

- 维护人可按**事项**查看该事项所有责任人的个人进度（只读，**不可修改**个人备注）；
- 维护人可按**责任人**聚合查看某人全部事项的个人进度；
- 个人进度增加可选字段 **阻塞原因**（block_reason）：预设选项（等待外部资料 / 等待其他部门 / 等待客户确认 / 其他原因）+ 自定义文本；
- 标记阻塞时个人进度仍按"处理中"语义参与统计，但单独展示阻塞标识；
- 所有责任人个人进度均"已完成"时 → 给维护人推送消息中心提醒"可评估是否更新全局状态"（**不自动改全局状态**，由维护人决策）。

### FR13 提醒健壮性（v3.0 新增）

- 新增 **compliance_reminder_log** 提醒记录表：每次计划/发送都落库，唯一约束 user_id+item_id+reminder_type+scheduled_time 保证幂等；
- 提醒时间按**自然日**计算；表结构预留工作日计算字段（工作日提醒下轮实现）；
- **异常场景矩阵**（全部生效）：
  - 事项已完成 → 停止提醒；
  - 事项停用 / 删除 → 停止提醒；
  - 到期日期修改 → 按新日期重算，不重复发旧节点；
  - 用户取消收藏 → 暂停个人提醒；重新收藏 → 恢复；
  - 用户关闭提醒 → 不再推送；
  - 定时任务重复执行 / 并发 → 同一提醒节点只发一次（幂等）；
  - 消息发送失败 → 允许重试且**有上限**（retry_count 上限，不无限循环）。

### FR14 事项修改历史（v3.0 新增）

- 新增 **compliance_item_history** 记录关键字段变更：标题 / 阶段 / 优先级 / 责任人 / 时间要求 / 到期日期 / 状态；
- 记录审计动作：草稿发布 / 下架 / 恢复 / 删除 / 匹配确认；
- 每条历史含：变更字段、旧值、新值、操作人、操作时间、变更原因（可选填）；
- 责任人变更时：写历史 + 通知**新责任人**（"你被设为 XX 事项责任人"）；**旧责任人**记录保留但不通知。

## 7. 验收标准（v2.0 修订）

1. 上传《君实合作注意事项(2).xlsx》→ 自动解析出 31 条草稿 → 维护人确认后，全局看板按文档分组展示；
