## 一、需求一：项目详情页「项目进度」块置顶

### 1.1 背景

项目详情页（`frontend/src/views/project/ProjectDetail.vue`）当前自上而下卡片顺序为：

```
操作区（返回 / 编辑 / 取消等按钮，固定在顶部）
→ 基本信息
→ 预算 vs 实际
→ 项目进度（阶段页签）
→ 专家名单
→ 供应商名单
→ （其余卡片）
```

「项目进度（阶段页签）」是项目全生命周期最核心的信息，当前排在第 4 位，用户每次打开详情页需要向下滚动才能看到当前阶段、模板材料与推进/回退入口，信息获取效率低。

### 1.2 需求描述

将「项目进度（阶段页签）」卡片整体上移至「基本信息」卡片之前；页面顶部操作区保持最顶不动。

变更后顺序：

```
操作区（保持最顶）
→ 项目进度（阶段页签）【置顶】
→ 基本信息
→ 预算 vs 实际
→ 专家名单
→ 供应商名单
→ （其余卡片保持原相对顺序）
```

### 1.3 验收标准

1. 打开项目详情页，顶部第一屏依次为操作区、「项目进度（阶段页签）」卡；
2. 基本信息、预算等卡片顺序正确、内容完整无丢失；
3. 阶段页签的选中态（当前阶段高亮）、模板渲染、推进/回退按钮功能不受影响。

## 二、需求二：立项阶段文本保存报错修复（全量加固）

### 2.1 问题现象

在项目详情页「立项」阶段点击「编辑文本」→ 输入内容 → 点击「保存文本」，保存失败报错（`NumberFormatException: For input string: "null"`），文本无法保存。

### 2.2 根因分析（已代码级核实）

1. 前端 `editRich(phaseId)` 调用 `saveRichText(projectId, { phaseId, content })`，**未携带 templateId**；
2. `frontend/src/api/project.js` L111-112 将请求体原样 `PUT /project/{id}/docs/richtext`；
3. 后端 `ProjectController.saveRichText` 使用 `Long.valueOf(String.valueOf(body.get("templateId")))` 解析模板 ID——字段缺失时 `String.valueOf(null)` 得到字符串 `"null"`，`Long.valueOf("null")` 抛出 NumberFormatException；`phaseId` 存在同型风险。

### 2.3 同类风险范围（全量加固对象）

全后端共 **9 处** `Long.valueOf(String.valueOf(...))` 同型代码：

| 位置 | 数量 | 涉及参数 |
|---|---|---|
| ProjectController | 6 | changePhase.phaseId、addExpert.expertId、addSupplier.supplierId、saveRichText.phaseId、saveRichText.templateId、saveExpertFee.expertId |
| NotificationController | 1 | 待核实参数 |
| ApplicationService | 1 | 待核实参数 |
| ParamUtils | 1 | 待核实参数 |

### 2.4 方案（已确认：全量加固 b）

1. 在 `ParamUtils` 新增安全解析工具（如 `parseLong(Object, Long)`）：null / 空串 / 非数字安全返回默认值，不抛异常；
2. 全量替换上述 9 处同型代码，缺参时按业务语义返回明确业务异常或默认值，禁止 500；
3. 前端 `editRich` 补传当前模板 `templateId`，作为第一道防线（后端加固为根治兜底）。

### 2.5 验收标准

1. 任意阶段（含立项）富文本编辑保存成功、无报错；
2. 保存后刷新页面，内容持久化存在；
3. 9 处加固点逐一验证：缺字段 / 空串 / 非数字时不抛异常，行为符合业务预期；
4. 正常调用（带全字段）行为完全不变。

## 三、需求三：阶段回退增强（权限放开 + 跨级回退 + 历史表）

### 3.1 现状（已代码级核实）

- 阶段模型：`project_phase` 表（id / name / sort / isActive / createTime），种籽数据：立项 1 ~ 已完成 6；`project.phase_id` 即当前阶段（项目状态）；
- 当前 `changePhase` 逻辑：权限 `isOwnerOrExecutor`（超级管理员 / 负责人 ownerId / `project_executor` 表中执行人）；目标阶段存在且未停用；**仅允许相邻阶段推进或回退**；推进时校验当前阶段必填模板（`missingRequiredTemplates`）；变更后写 `operation_log`；
- 前端回退按钮显示条件：`detail.canAdvance && hasPrevPhase`。

### 3.2 需求

1. **回退权限放开**：后端详情接口新增独立字段 `canRollback`（负责人 / 执行人 / 管理员为 true）；前端回退按钮显隐改由 `canRollback` 控制，语义上与推进权限 `canAdvance` 解耦；
2. **跨级回退**：允许从任意阶段回退到任意更早阶段（目标 sort < 当前 sort 且非相邻）；前端二次确认弹窗 + **回退原因必填**；后端同样校验原因非空；
3. **推进逻辑保持不变**：仅相邻推进 + 必填模板校验；
4. **阶段历史表**：新建 `project_phase_history`，记录推进 / 回退（含跨级）动作，形成可追溯的阶段变更历史。

### 3.3 验收标准

1. 负责人与执行人均可回退（含跨级），普通员工看不到回退按钮；
2. 跨级回退弹出二次确认且原因必填；取消则系统零变更；
3. 回退成功后当前阶段更新，历史表新增一条记录（from / to / action / reason / operator）；
4. 相邻推进行为不变（必填材料校验仍生效）；
5. 历史表数据落库可查（详情页 UI 展示可后续迭代）。
