## 1. 产品判断

文档应承载长期适用的规范，员工应管理“本次使用这份规范要做什么”。现在的公共事项同时保存统一到期日、优先级、全局完成状态；个人记录又只有一份，无法区分六月和十月两次执行。仅把三个字段搬到个人表，仍解决不了反复复用。

建议采用：合规文档 → 已发布规范模板 → 每次使用创建独立执行清单 → 清单内的个人执行任务。收藏用于保存入口和接收版本动态；“用于本次项目”才创建待办。

## 3. 核心概念与字段归属

| 概念 | 含义 | 谁配置 |
| --- | --- | --- |
| 规范模板 | 某文档版本对应、可以反复使用的执行指导 | 上传人编写草稿，维护人审核发布（建议） |
| 规范细项 | 如“协会选择”，包含说明、候选选项、判断条件、材料与验收标准 | 模板编写者 |
| 执行清单 | 员工为某个项目或个人用途创建的一次独立使用记录 | 当前员工 |
| 执行任务 | 从模板细项生成的本次行动及实际填写结果 | 清单所有人 |
| 规范时限 | 原文明确的“会前7天提交”等要求，属于规则内容 | 模板编写者忠实维护 |
| 计划到期日 | 本次执行计划何时完成；可参考规范时限 | 员工确认 |
| 本次进度 | 未开始、进行中、已完成，表示该次执行 | 员工；替代容易混淆的“全局状态” |
| 模板发布状态 | 草稿、已发布、已停用；与任何项目是否完成无关 | 维护人 |

字段明确分工：
- 模板：名称、适用说明、阶段、细项分组、操作指引、候选选项、材料要求、验收标准、来源页码/章节、规范时限、是否必做；不设置某员工到期日、个人优先级或“大家都完成”。
- 执行任务：本次选择/填写结果、计划到期日、个人优先级、进度、私人备注、等待跟进、提醒、完成时间。
- 清单整体进度由任务聚合，不另加一套可随意修改的“全局完成状态”。
- 原文的硬性时限与员工计划日期同时可见；员工调整计划不能修改原规范。若计划晚于规范建议日期，给出清晰提示，是否强制拦截待业务确认。

## 4. 信息架构与页面

企业合规页采用三个页签，默认“我的执行”：
1. 我的执行：进行中清单和个人任务，按项目/清单分组，明确“哪个项目、哪次使用”。顶部统计仅计算本人活跃任务。
2. 规范文档库：文档预览、来源版本、适用范围、收藏、使用模板、新版本提示。收藏列表提供“一键用于项目”。
3. 模板维护：仅有权限者可见，上传后进入草稿编辑器，左边原文、右边结构化细项；普通上传者只见自己的草稿，不因上传获得全库维护权限。

不再把维护人看板完整堆在员工待办与文档库之间。维护看板聚焦模板是否完整、草稿待审核、版本待发布，而不是给所有员工统一配置进度。

任务列表建议字段：完成勾选 / 事项与本次选择摘要 / 项目·清单名 / 计划到期日 / 优先级 / 本次进度 / 备注摘要·条数 / 更多。
任务详情侧栏：规范要求与来源 → 本次填写 → 本次计划 → 私人备注与操作历史。来源只读，编辑区域标明“仅影响这一次执行”。

## 5. 功能需求

### FR01 上传后编辑规范细项（P0）
- 上传、解析成功后先保存草稿，不立即生成全员待办。解析失败仍保留文档，允许手动编写；不得以“解析成功”等同内容准确。
- 支持分组/子项、排序、增删、必做标识、操作说明、适用说明、材料清单、完成判定、原文引用。优先富文本说明配合结构化输入，不只扩大原来的三行文本框。
- 首期输入类型：说明/检查项、单选、多选、文本填写。组合复杂表格、任意脚本条件或公式引擎不进入首期。
- “协会选择”示例：上传人配置可选协会A/B及各自适用条件、联系人职责说明、需准备材料；员工在本次清单里选择A并记录选择依据。不要把选项写成上传人的“这次已经选好了”。
- 可选简单分支：选择A显示A相关子项；只允许同版本合法选项ID、无循环依赖。默认不适用分支折叠，切换选择不能静默删除已填信息。
- 预览“员工实际填写效果”，支持保存草稿/发布前校验。正文未提供的条款不得由解析器编造为强制规则。

### FR02 从文档开始本次使用（P0）
- 收藏成功只提示“已收藏；需要执行时创建清单”，同时提供“用于项目”。收藏不产生到期任务或默认催办。
- 创建清单三步：选择系统项目（优先显示本人有权访问的项目；可选“个人用途”）→ 选择模板与适用项 → 确认名称、计划日期、提醒并开始。
- 清单可用“君实·6月项目·协会与材料”命名；已选项目自动带名称候选，可修改。无项目时名称必填。
- 一个项目可以有多份文档清单；同一文档也可被同一员工多次使用。检测相同项目/模板的活跃清单后提示“继续已有/仍新建”，不武断阻止合理重复。
- 首期清单为个人执行，关联项目仅提供上下文和跳转，不自动让整个项目组、模板维护人看到私人备注或代改状态。团队协作清单另行设计。
- 创建使用请求需防重复提交；尚未确认开始的草稿不入待办、不发提醒。

### FR03 重复使用与清单版本（P0）
- “再次使用”创建新清单ID，可选最新已发布模板（默认）或仍允许使用的历史版本；必须展示版本。
- 六月清单保留完成记录，十月清单从未开始起步。两次日期、选择、备注、进度和提醒互不覆盖。
- 复制旧清单时：默认只继承适用项选择；日期、完成状态、完成时间、提醒发送记录、个人备注均重置。候选值变化/选项已失效须重新确认。复制执行答案为可选明确勾选，不默认继承。
- 模板更新只提示差异，不自动改变活跃或已完成清单。升级为显式操作，列出新增/删除/修改细项，保留本次结果；首期若未实现安全升级则仅支持新建新版本清单，不能伪装自动同步。

### FR04 员工自行配置本次计划（P0）
- 每项可设/清空计划到期日、优先级、高中低、本次进度及提醒，支持清单内批量设置。默认优先级中、日期未设置。
- 未设置日期的项目明确显示“待排期”，不算逾期、不发到期提醒；有日期且启用提醒才产生节点。相对时限生成的是建议日期，需员工确认。
- 清单完成条件：所有当前适用的必做任务已完成；非适用任务不计入分母。可选任务未完成时，关闭清单需明确选择“不再执行”并记录原因。
- 已完成任务重新打开不会重置其他任务；跨项目复用使用“再次使用”，不要让员工靠“重新打开全部”覆盖上次历史。

### FR05 已完成自动收纳（P0）
- 默认“待处理”仅包含未开始/进行中的适用任务；已完成不占顶部位置、不进入待办/临期/逾期统计。
- 完成后短暂展示“已完成，已移入完成记录”，可在5秒内撤销；服务端成功后更新计数，失败恢复原行且说明原因。
- “已完成”页签随时可查，按完成时间倒序，可按项目/清单/文档/日期筛选；显示原备注、结果、完成时间和模板版本。不物理删除已完成记录。
- 清单整体完成后移入“历史清单”；用户可继续查看六月项目，不影响十月项目的活跃待办。

### FR06 备注清晰可见（P0）
- 行内显示最近一条备注摘要（两行内）、更新时间及备注入口；无内容显示“添加备注”，有内容显示“备注·最近更新”。鼠标悬停不能作为唯一读取方式。
- 详情中“私人备注”独立区域，支持换行、明确保存状态；保留编辑历史。保存失败保留输入，离开未保存给提示。
- “规范说明”与“我的执行备注”视觉分区，不再把规范全局备注与私人记录混排。个人备注默认仅本人可见，不因为有项目ID或维护权限就开放。
- 证据附件、@他人和协作评论列为二期，避免把备注临时扩成没有权限规则的聊天系统。

### FR07 把阻塞改为可执行的等待跟进（P1）
- 从主操作区移除“阻塞?”按钮；在“更多”提供“设置等待跟进”。本次进度仍为进行中，等待是辅助标记，不再增加平行状态机。
- 设置时写“在等什么”和“下一步行动”，可填跟进日期；等待对象可自由文本，不要求选择公司用户，不自动向他人发送消息。
- 行内展示“等待客户确认 · 11月8日跟进”；到复查日进入“需跟进”筛选，提供“继续处理/延后跟进/清除等待”。
- 完成任务自动解除等待提醒，但保留历史。无实际协作需求的员工可完全不使用该能力。

### FR08 排序、筛选与交互一致性（P0）
- 默认排序：已逾期 → 今天到期 → 未来3天 → 其他已排期 → 未排期；组内按高优、到期、稳定ID。已完成仅在完成页，不参与此排序。
- “待办/未来3天/逾期/待排期/需跟进”可点击过滤；清单和项目选择保留。明确区分统计是在当前筛选范围还是所有本人清单，本方案推荐统计跟随项目/清单/搜索，但不随状态快捷卡自身变化。
- 收藏、创建、完成、备注、提醒设置成功后同步列表/统计；失败不伪装成功。分页、空态、加载失败与重试分别设计。
- 消息点击直接到具体执行任务并展开侧栏；无权或已归档时给出解释及历史入口，而不是回到页首。

### FR09 提醒与生命周期（P0）
- 提醒属于个人执行任务；计划日期存在且开启时，默认提前3天和当天各一次，支持关闭/改提前天数。无日期不发；日期清空/完成/归档/权限撤销立即取消未发送节点。
- 清单草稿、历史已完成项目、被判不适用子项不提醒。重新使用创建全新提醒节点，不继承六月的已发送状态。
- 创建/改期发生在某提醒节点之后，不补发过去的提前提醒；过期任务在列表标红，由员工明确配置新的跟进日期，不每天重复催办。
- 取消收藏只取消入口收藏和文档动态订阅，不取消已经开始的执行任务。暂停执行通过清单明确操作，禁止以“取消收藏”暗中终止项目工作。
- 普通下架/停用：阻止新使用，已有清单显示“来源已停用，请核对”，保留个人任务与历史；权限撤销/敏感内容删除：禁止继续读取受限模板/文件/快照，暂停相关提醒并展示脱敏占位。不能借快照绕过原权限。

## 6. 六月与十月完整示例

1. 上传人上传君实规范v1，在“协会选择”中维护可选方案、适用条件、材料说明和来源章节；维护人发布。
2. 员工收藏文档；六月选择项目P06，建立个人清单R06，选择协会A、设置本次到期日/优先级、记录联系结果；完成后进入历史。
3. 十月从同一文档点击“再次使用”，选择P10或个人用途，建立R10。R06保持原样，R10未开始且等待排期；可以明确选择复制先前选项，但不得带入完成结果。
4. 文档更新到v2，R06仍能知道当时依据v1；R10收到版本差异提示，员工决定新建v2清单或执行后续经评审的升级流程，系统不静默迁移状态。
5. 另一员工同时使用同一模板，拥有自己的清单/计划/备注；不能改写该员工的六月记录。

## 7. 与旧规则的冲突及待审核决策

| 决策 | 建议 | 影响/需确认 |
| --- | --- | --- |
| D01 使用入口 | 优先系统项目+可选个人清单 | 已由用户确认 |
| D02 收藏含义 | 收藏不等于自动启动执行 | 替代旧FR3/FR8与ADR-016相关口径，需评审 |
| D03 字段归属 | 模板取消公共执行日期/优先级/完成状态 | 旧FR4/ADR-015与全局看板须同步改造 |
| D04 清单隐私 | 首期个人清单，项目关联不扩大权限 | 不保留模板维护人自动查看所有个人执行状态；团队协作二期 |
| D05 上传者权限 | 自己的草稿可编辑，发布沿用维护人审核 | 不等同“任何上传者都成为维护人”，需批准新的对象权限 |
| D06 文档生命周期 | 普通停用不抹除执行，撤权限制读取 | 替代旧FR6/FR11，需业务与安全评审 |
| D07 规范时限 | 保留原规范，员工安排本次日期 | 是否允许违反硬性时限、是否要审批例外，需明确 |
| D08 历史切换 | 原数据按“历史执行”保留，用户确认后再关联项目 | 不自动把旧全局状态推断成每人完成，也不猜项目归属 |

## 8. 范围与优先级

首期闭环：结构化模板、个人执行清单、项目可选关联、字段归属迁移、完成收纳、可见备注、实例级提醒、历史兼容与资源授权；简单选项分支可随首期实现，复杂条件不做。
次期：团队共享分工、证据附件、跨版本原清单升级、自动相对日期计算、复杂分支/法规例外审批。等待跟进可P1追加，首期先去掉无行动价值的突出“阻塞?”。
本次交付仅需求/技术文档，不含上述功能实现。
