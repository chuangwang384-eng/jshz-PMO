# 客户信息列表与详情抽屉改造需求

日期 2026-11-07 · 状态：已评审（Owner 决策确认） · 版本 v1.1

适用于知识星球板块下的客户信息页（`CustomerInfo.vue` 列表页 + `CustomerDetail.vue` 详情页）。改造为**紧凑工具栏 + 客户列表 + 详情抽屉**的三层结构，不新造独立页面体系，现有路由（customer-info / customer-detail / 关系网络 / 关系类型管理）全部保留。

## 1. 现状事实（已核实，2026-11-07）

| 项 | 现状 | 位置 |
| --- | --- | --- |
| 列表列 | 10 列：客户姓名/工作单位/工作职位/工作职级/现任职务/客户喜好/备注/创建人/创建时间/操作（含详情+编辑+删除，已删除视图含恢复） | `CustomerInfo.vue` el-table |
| 详情 | 点击「详情」跳转整页 `customer-detail/:id`（582 行独立页） | `CustomerDetail.vue` |
| 关联关系 | 后端已有完整体系：`customer_relation`（from/to/关系类型）+ 6 个内置关系类型（介绍关系/上下级/同事/业务伙伴/亲友）+ 2 个自定义「客户介绍」；关系 CRUD 接口齐备；关系网络可视化页已有 | `CustomerRelationController` 等 |
| **数据建模问题** | 4 条客户（页面标注"布局演示"）中 3 条的 **work_level（工作职级）字段存的是"妈妈/爸爸/儿子"**——属于人物关系/身份标签，不是职级；而关系表 `customer_relation` **0 条记录** | 生产库实测 |
| 更新时间 | `customer.update_time` 列存在且非空约束，实体有 `updateTime`；列表未展示 | 实测 |

## 2. 目标与非目标

**目标**：降低列密度、突出关键信息；减少页面切换（详情抽屉）；把人物关系归位到关系体系，为关系网络提供正确数据。

**非目标（本期不做）**：
- 不改新增/编辑弹窗字段与审批/权限模型（`customer:manage` 规则不变）。
- 不改关系网络可视化页与关系类型管理页。
- 不做列表列的自定义配置（固定默认列）。
- 不做附件相关改造。

## 3. 需求范围

### P0 列表字段重新规划（默认列）

| 列 | 宽度 | 内容 |
| --- | --- | --- |
| 客户姓名 | 160px | 圆形首字占位头像 + 姓名（客户无头像字段，首字+底色） |
| 工作单位 | 240px | 超长截断（show-overflow-tooltip） |
| 现任职务 | 180px | `currentDuty`（即 Owner 所述"当前职务"） |
| 工作职级 | 120px | `workLevel`，可空显示"—" |
| 关联关系 | 160px | 该客户的关系数量摘要（如"3 条关联"），点击抽屉内查看明细 |
| 最近更新 | 130px | `updateTime` 统一格式（YYYY-MM-DD） |
| 操作 | 100px | 详情 + 更多（编辑/删除/恢复收纳进 el-dropdown，权限规则不变） |

**移出列表、归入详情抽屉/详情页**：客户喜好、备注、创建人、完整创建时间、工作职位（workPosition 保留为编辑字段与抽屉展示，不再占列表列）。

### P0 详情抽屉（替代整页跳转）

1. 点击客户行/「详情」打开**右侧抽屉**（el-drawer，宽 520px，440~560px 规范区间）：客户头部（首字头像+姓名+单位·职务）、基本资料（单位/职务/职级/喜好——喜好在抽屉内显示）、关联人物（该客户的关系列表：对方姓名+关系类型，尾部「查看关系网络」入口）、底部操作（编辑=快速编辑抽屉内表单 / 打开完整档案=跳转既有 customer-detail 页）。
2. 快速编辑：抽屉内直接编辑基础字段（姓名/单位/职务/职级/喜好/备注），保存走既有接口与权限；喜好/备注等长文本在抽屉内完整可编辑。
3. 已删除视图下的抽屉为只读 + 恢复按钮。
4. 「打开完整档案」保留既有 customer-detail 整页（历史职务等完整信息仍在该页），本期不改其内部。

### P1 关联关系列数据

列表接口返回每个客户的关系数量摘要（后端聚合 customer_relation），0 条显示"—"。

### P1 数据建模修正（work_level 误存关系）

`work_level` 中的"妈妈/爸爸/儿子"为演示数据错录（关系表 0 条佐证）。修正方式见决策点：把三条关系迁移到 `customer_relation`（类型=亲友，方向按 Owner 指定）并清空对应 work_level，或由 Owner 在界面自行调整。

## 4. 交互规则

| 场景 | 预期 |
| --- | --- |
| 搜索/重置/已删除视图 | 行为与现状一致，作用于新列表 |
| 点击行/详情 | 打开右侧抽屉（不再跳整页）；整页入口保留在抽屉内 |
| 抽屉内快速编辑保存 | 走既有 update 接口与 `customer:manage` 权限；失败保留编辑内容 |
| 关联关系列点击 | 打开抽屉并定位到关联人物区块 |
| 删除/恢复 | 仍在列表操作（更多菜单），确认弹窗文案不变 |

2. **「工作职位 workPosition」列**：默认列表不含（移入抽屉展示与编辑），确认。
