## 3. 背景与目标

### 3.1 业务背景

现有 OA 系统项目详情页存在以下问题：

1. **视觉层级不清晰**：页面区块堆叠，缺少统一的信息架构，主次不分。
2. **项目阶段展示简陋**：阶段用 `el-tabs` 页签表达，未体现生命周期推进关系，无法直观区分已完成/当前/未开始。
3. **基本信息表格化严重**：使用密集边框表格（`el-descriptions`）罗列字段，阅读负担重。
4. **预算信息展示不直观**：仅三栏数字，无预算余额、无使用率、无进度可视化。
5. **页面空间利用率低**：无辅助信息栏，动态/成员/待办/附件信息分散或缺失。
6. **页面标题重复**：「我的申请」页顶部导航栏与内容区重复显示同名标题；全局抽查另有 10 个页面存在同类问题。

### 3.2 产品目标（SMART）

1. 项目详情页形成"概览头部 → 核心数据 → 生命周期 → 阶段任务 → 基本信息 → 预算 → 业务明细 + 右侧辅助栏"的清晰信息架构。
2. 项目生命周期以横向 Stepper 可视化，一眼可辨已完成/当前/未开始三态。
3. 预算展示包含总额、实际支出、余额、使用率，并以进度条呈现。
4. 「我的申请」及全局 10 个重复标题页面完成标题去重，统一"顶栏负责页面名、内容区负责业务说明"规范。
5. 全部为纯前端 UI 改造，不修改后端接口契约、数据库字段、阶段流转规则与权限逻辑。
6. 所有展示数据取自真实接口，不伪造数据。

### 3.3 设计参考

- 现代 SaaS 企业管理系统风格（参考 Linear、ClickUp）。
- 主色调：蓝色（沿用 Element Plus 默认蓝 `#409EFF`）。
- 背景：浅灰白；卡片：白色、弱边框、适当阴影；统一圆角、间距、字体、按钮、状态徽标。
- 适配常见桌面分辨率（1920 / 1440 / 1366），内容容器最大宽度 1440px，避免内容过度拉长。

## 5. 用户角色与权限

权限沿用现有后端返回字段，不做任何改动：

| 字段 | 含义 | 可见/可用场景 |
|------|------|---------------|
| `canManage` | admin 或含 `project:manage` 权限 | 编辑项目、调派专家、登记劳务费、移出专家、新建专家卡、关联供应商 |

## 6. 功能需求

### FR-1 项目概览头部

- 展示：项目名称、项目状态（生命周期阶段徽标 + 有效/已取消状态）、项目大类、项目类型、项目负责人、计划时间。
- 不展示项目编号：当前数据模型无编号字段，按"如果已有"原则处理，不为新增字段。
- 操作按钮分组：
  - 主操作：**推进下一阶段**（主要按钮，`canAdvance && hasNextPhase` 可见，必填未完成时禁用并提示原因）。
  - 次要操作：**编辑项目**（`canManage`）。
  - 更多操作（下拉）：**回退阶段**（`canRollback`）、**取消项目**（`canAdvance`，点击后二次确认弹窗，取消原因必填）。
- 已取消项目：显示取消原因与取消时间。

### FR-2 项目核心数据卡

- 使用数据卡片展示 **4 项财务数据**（负责人、计划周期已在概览头部展示，不重复）：
  1. 项目预算总额（`budgetAmount`）
  2. 实际支出（`actualTotal` = 专家劳务费 + 供应商费用）
  3. 预算余额（前端计算：`budgetAmount - actualTotal`）
  4. 预算使用率（`actualTotal / budgetAmount`，进度条呈现）
- 所有数据取自真实接口，不伪造。

### FR-3 项目生命周期 Stepper

- 将现有阶段标签改造为横向 Stepper，阶段顺序：**立项 → 预算 → 筹备 → 进行中 → 结算 → 已完成**（按 `project_phase.sort` 排序）。
- 状态三态：
  - 已完成阶段：绿色勾选；
  - 当前阶段：蓝色高亮；
  - 未开始阶段：灰色。
- 交互：
  - 点击任一阶段，下方内容区切换显示该阶段内容；
  - 区分"当前项目阶段"与"用户正在查看的阶段"两种状态，避免状态混乱（当前阶段高亮，查看阶段另有视觉标识）；
  - 已完成阶段可点且只读（隐藏编辑/上传/删除按钮）；
  - 当前阶段完整可操作；
  - 未开始阶段可点击，内容区显示空状态提示「该阶段尚未开始」。
- 阶段切换仅影响展示层，不触发任何阶段流转。

### FR-4 阶段任务区域

- 位于 Stepper 下方，分为两层：
  1. **阶段任务卡**（上）：阶段名称、阶段完成状态、必填配置（已完成数/总数）、待处理任务、阶段负责人、阶段操作入口。
  2. **阶段资料区**（下）：展示所选阶段的模板内容（附件 FILE / 富文本 RICH_TEXT / 预算 BUDGET / 专家 EXPERT / 供应商 SUPPLIER），沿用现有数据结构。
- 数据口径：
  - 必填配置：来自 `project_phase_template_rel.required`，按类型展示；
  - 待处理任务：= 当前阶段未完成的必填配置项清单（如"登记预算金额""上传附件""调派至少 1 名专家"），每项带**解决入口**直达对应操作（登记预算弹窗 / 上传附件 / 调派专家等）；全部完成时显示"本阶段必填配置已完成"；
  - 阶段负责人：系统**不存在阶段级负责人配置**，展示为项目负责人 + 项目执行人，标注"项目级"；
  - 操作入口：推进下一阶段、回退阶段等，遵循现有权限。
- 未完成必填项时，展示明确的**阻塞原因**（复用后端 `missingRequiredTemplates`）及解决入口。

### FR-5 基本信息分组

- 废弃密集边框表格（`el-descriptions`），改为分组信息卡片：
  - **项目属性**：项目名称、项目大类、项目类型；
  - **项目人员**：项目负责人、执行人（人员标签或头像组展示）；
  - **项目时间**：计划开始时间、计划结束时间；
  - **项目状态**：当前阶段、生命周期状态（有效/已取消）。
- 字段内容与现有数据一致，仅改变展示形式。

### FR-6 预算与实际支出

- 财务数据概览：预算总额、实际支出、剩余预算、预算使用率。
- 使用进度条展示预算使用情况；使用率超过 100% 时以警示色呈现。
- 未登记预算（`budgetAmount` 为空/0）时展示**空状态**及登记入口（`canAdvance` 可见）。
- 余额 = 预算总额 - 实际支出，由前端计算，不改后端。

### FR-7 右侧辅助区域

- 布局：主内容区 + 右侧固定辅助栏（约 320px），适配常见桌面分辨率。
- 辅助栏内容（数据源均为现有接口返回）：
  - **项目动态**：`operation_log`（target_type=PROJECT）倒序，同现有时间线；
  - **项目成员**：项目负责人 + 执行人列表（`project_executor`）；
  - **当前待办**：未完成必填配置项清单；
  - **相关附件**：`project_doc` 文件列表（下载入口保留）。

### FR-8 业务明细区（保留原有功能）

- 专家名单、供应商名单、结算合同、项目时间线四个区块**全部保留**，作为详情页"业务明细"区放在基本信息/预算之后。
- 数据、列、操作按钮、权限逻辑完全不变，仅统一视觉容器（卡片、表格样式 token 化）。
- 项目时间线与右侧"项目动态"数据同源，可保留展示（历史信息完整），避免功能删除。

### FR-9 「我的申请」页面标题去重

- 保留顶部导航栏页面标题「我的申请」。
- 删除内容区域重复的「我的申请」大标题。
- 保留原说明文字"查看我提交的全部申请及审批进度（专家修改 / 新增等）"，作为内容区顶部辅助描述，采用较小字号、浅灰色。
- 状态筛选器与数据表格的功能、字段、交互和数据逻辑全部保持不变。
- 适当压缩页面顶部留白，让表格获得更多垂直展示空间。

### FR-11 状态设计

- 空数据：表格/列表展示 `el-empty` 空状态并给出引导文案（如"本阶段尚未开始""尚未登记预算"）。
- 加载中：保留骨架/loading 态，不闪白。
- 接口异常：展示错误提示与重试入口，不清空已加载数据。

### FR-12 多分辨率适配

- 适配 1920 / 1440 / 1366 宽度；内容容器最大 1440px 居中。
- 右侧辅助栏在 1366px 以下可收窄（约 300px）或按断点降级为区块下移，不出现横向滚动。
- 卡片网格（数据卡/分组/任务卡）按容器宽度自动换行。
