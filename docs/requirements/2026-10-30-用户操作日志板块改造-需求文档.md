# jshz-PMO 用户操作日志板块改造 — 需求文档

| 项目 | 内容 |
|---|---|
| 项目 | 景帅会展专家库系统（jshz-PMO） |
| 模块 | 用户操作日志（超级管理员审计板块） |
| 文档版本 | v1.0 |
| 日期 | 2026-10-30 |
| 状态 | 已确认（经需求拷问逐轮澄清） |

---

## 1. 背景与现状

超级管理员账号可访问「用户操作日志」板块（前端页面 `frontend/src/views/DownloadAudit.vue`，路由 `/admin/audit/downloads`，接口 `GET /api/audit/operations`），用于查看系统内的用户操作留痕。经只读核查，现状如下：

| 现状项 | 结论 |
|---|---|
| 登录/登出留痕 | 已写入：`AuthController` 埋点 `ACTION_LOGIN / ACTION_LOGOUT`，登录登出记录高频产生，占据日志列表大量空间 |
| 供应商管理留痕 | **完全缺失**：`SupplierController / SupplierService / SupplierImageService` 均无 `operationLogService` 引用，档案增删改、行价、绑定关系零留痕 |
| 项目管理留痕 | **已基本覆盖**：`ProjectService` 约 20 处手动埋点（创建/修改/删除/取消/阶段/专家调派/供应商关联/预算/合同等） |
| 前端类型标签 | **缺口**：`actionTypeMap` 仅覆盖旧枚举，项目管理新类型与供应商类型无法在下拉筛选 |
| 日志机制 | 纯手动埋点，无 AOP 注解/切面（`pom.xml` 无 spring-boot-starter-aop） |
| 访问权限 | `audit:view` 权限码：SUPER_ADMIN 代码内全权；**ADMIN 角色显式绑定** |

---

## 2. 需求必要性评估

### 2.1 需求一：登录、登出操作信息不展示 — 必要性：高（采纳）

- **现状问题**：登录/登出为高频会话事件，每次登录登出均产生一条日志，严重稀释操作日志的审计价值，管理员难以聚焦真正的业务敏感操作。
- **审计价值低**：现有 `LOGIN/LOGOUT` 记录仅含用户名/IP/时间，缺少失败尝试、来源设备、Token 生命周期等安全审计关键信息；真正的会话安全审计应由安全日志独立承载，不属于本板块职责。
- **处置建议**：采用**后端分页查询排除**（默认不展示），历史数据保留在 `operation_log` 表供安全追溯，避免数据清洗风险。采纳。

### 2.2 需求二：供应商管理敏感操作留痕 — 必要性：高（强烈建议采纳）

- **现状问题**：供应商模块（档案、行价、酒店-打印店绑定）是会展业务的核心敏感数据，当前**完全无操作审计**。
- **风险场景**：
  - 供应商档案被误改/恶意篡改后无法定位责任人；
  - 行价被调整后无记录，影响结算与对账追溯；
  - 酒店-打印店绑定关系变更影响业务链路，无留痕无法追责。
- **处置建议**：引入留痕机制，记录档案新增/修改/删除、行价保存、绑定/解绑共 6 类敏感操作。强烈推荐采纳。

### 2.3 项目管理敏感操作 — 必要性：中（后端已覆盖，需补齐前端展示）

- 后端埋点已覆盖敏感操作，主要缺口是**前端 `actionTypeMap` 未补齐对应类型标签**，导致新日志无法按类型筛选、仅以原始枚举兜底显示，体验断裂。
- 处置建议：补齐前端标签，属低成本高收益改动。采纳。

**总体结论**：需求整体成立，必要性排序为「供应商留痕 > 登录登出隐藏 > 前端标签补齐」。本次改造不改变现有项目管理日志逻辑（零回归）。

## 3. 功能需求

### FR1 登录/登出不展示

- 用户操作日志分页查询**默认排除** `LOGIN / LOGOUT` 两种类型（后端查询排除，非前端过滤、非删除数据）。
- 历史 `LOGIN/LOGOUT` 数据保留在数据库，仅供安全审计直接查库追溯。
- 本期**不提供**"包含登录/登出记录"的查看开关（后续需要时另行开启）。

### FR2 供应商管理敏感操作留痕

对供应商模块以下操作写入操作日志（`targetType=SUPPLIER`，操作级留痕，不记录字段级变更 diff）：

| 操作 | actionType | 描述示例 |
|---|---|---|
| 新增供应商档案 | `SUPPLIER_CREATE` | 新增供应商：{name} |
| 修改供应商档案 | `SUPPLIER_UPDATE` | 修改供应商：{name} |
| 删除供应商档案 | `SUPPLIER_DELETE` | 删除供应商：{name} |
| 保存行价 | `SAVE_SUPPLIER_PRICE` | 保存行价：{supplierName} |
| 酒店-打印店绑定 | `BIND_SUPPLIER` | 绑定供应商：{name} |
| 解绑 | `UNBIND_SUPPLIER` | 解绑供应商：{name} |

不记录：图片增删/主图设置、供应商评价（噪音大、敏感度低）。

### FR3 前端操作类型标签补齐

- 补齐 `actionTypeMap`：项目管理全部已有类型（`CREATE_PROJECT / UPDATE_PROJECT / DELETE_PROJECT / CANCEL_PROJECT / CHANGE_PHASE / ASSIGN_EXPERT / REMOVE_EXPERT / ASSIGN_SUPPLIER / REMOVE_SUPPLIER / UPLOAD_DOC / DELETE_DOC / REGISTER_BUDGET / CREATE_CONTRACT / UPDATE_CONTRACT / SYNC_EXPERT_SENSITIVE / CREATE_TEMPLATE / SUBMIT_CONTRACT_APPROVAL / CREATE_ANNOUNCEMENT`、`RELIST_DOC / WECOM_SYNC / WECOM_BIND`）与供应商新增 6 类。
- 新类型可在下拉筛选器中正常选择，并渲染对应标签样式。

### FR4 访问收紧为仅超级管理员

- 前端：「用户操作日志」菜单与路由对非 SUPER_ADMIN 角色隐藏（`hasRole('SUPER_ADMIN')`）。
- 后端：`AuditController` 接口增加 SUPER_ADMIN 角色校验，非超管访问返回 403。
- 数据：移除 ADMIN 角色绑定的 `audit:view` 权限（幂等 SQL 迁移）。

### FR5 引入统一 AOP 日志注解机制（本次仅供应商模块启用）

- 新增自定义注解 `@OperationLog` 与切面 `OperationLogAspect`，通过 `@annotation` 切点仅拦截标注方法。
- 注解支持：`actionType`（类型）、`actionDesc`（SpEL 描述模板）、`targetType`、`targetId`（SpEL 表达式）。
- 本次仅应用于 `SupplierController` 的 6 个敏感方法；**现有手动埋点保持不动**（共存，不迁移）。
- 切面内写日志失败仅 warn 降级，不影响主业务流程（沿用 `OperationLogService.record` 容错策略）。

## 4. 非功能需求

| 维度 | 要求 |
|---|---|
| 容错 | 日志写入失败不影响业务主流程（try-catch 降级 + warn） |
| 兼容 | 现有 `operation_log` 表结构不变；历史数据不迁移不清理 |
| 性能 | 日志查询增加类型排除条件，走现有 `idx_action_type` 索引 |
| 安全 | 接口层角色校验与前端菜单隐藏双保险，防止越权直调 |
| 幂等 | SQL 迁移幂等可重复执行；AOP 与手动埋点零重复记录 |

## 5. 验收标准（逐条）

| # | 验收项 | 验收标准 |
|---|---|---|
| A1 | 登录/登出隐藏 | 超级管理员登录后，用户操作日志列表默认**不出现** `LOGIN / LOGOUT` 记录；数据库历史数据仍在 |
| A2 | 供应商留痕 | 对供应商执行新增/修改/删除档案、保存行价、绑定/解绑后，日志板块出现对应 6 类记录，可按「供应商」类型筛选 |
| A3 | 前端标签补齐 | 操作类型下拉可正常选择项目管理全部新类型与供应商 6 类，标签渲染正常（无原始枚举兜底） |
| A4 | 访问收紧 | 非超级管理员（含 ADMIN）无法看到菜单、直调接口返回 403；ADMIN 的 `audit:view` 绑定已移除 |
| A5 | 回归保障 | 现有项目管理约 20 处手动埋点日志正常写入、无重复记录；AOP 与手动埋点共存无冲突 |

## 6. 术语表

| 术语 | 含义 |
|---|---|
| 用户操作日志 | 超级管理员审计板块，展示系统内用户操作留痕（`operation_log` 表） |
| 敏感操作 | 对核心业务数据（档案、行价、绑定关系）产生新增/修改/删除影响的写操作 |
| 手动埋点 | 业务代码中显式调用 `operationLogService.record(...)` 的记录方式（现状） |
| AOP 注解 | 通过 `@OperationLog` 注解 + 切面自动记录日志的方式（本次新增） |
| SpEL | Spring 表达式语言，用于从方法参数/返回值提取动态描述与目标 ID |
| SUPER_ADMIN | 内置超级管理员角色编码（`role.code='SUPER_ADMIN'`），代码内全权 |
