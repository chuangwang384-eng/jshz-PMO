# 项目配置板块图形化改造 需求文档

- 版本：v1.0
- 日期：2026-11-02
- 状态：评审通过，可实施
- 适用范围：<LOCAL_PATH> 前端 ProjectConfig.vue 及关联组件

## 1. 背景与问题

现状：项目配置板块为单个 `ProjectConfig.vue`，内含 4 个 tab（项目类型、类型流程、流程阶段、模板管理）；类型流程配置被压缩在类型编辑弹窗中，用「上移/下移按钮」表达阶段顺序；阶段模板绑定含全局兜底（type_id=0）与类型专属双层语义，仅以弱提示呈现。

痛点（基于代码事实核查确认）：

1. 类型 → 阶段 → 模板三层关联不可视，用户无法直观理解流程先后与跳过关系；
2. 全局兜底 vs 类型专属的「双层回退」语义易误解（「为何出现这些模板」「改全局是否影响类型专属」）；
3. 删除/修改的级联约束（拒删、级联清理）仅在提交时报错，事前无预览；
4. 排序与必填语义分散在 `project_phase`、`type_phase_rel`、`phase_template_rel` 三张表的 sort/required 字段，无全局总览；
5. 配置对执行侧的下游影响（新建项目默认阶段、阶段推进必填校验）不透明；
6. 整个板块入口深藏在「管理员设置」分组下，与项目执行侧（详情页已有 Stepper 图形）割裂。

## 2. 竞品参考

| 产品 | 配置设计要点 |
|---|---|
| Jira（Atlassian） | 官方承认项目配置「confusing or intimidating」并重构：配置页 tab 分组、可视化工作流编辑器、拖拽字段设计器、模板复用 |
| 禅道 | 可视化流程编辑器：拖拽+配置搭建流程，非开发人员可上手，审批流节点一目了然 |
| Monday.com / Asana | 色彩编码状态、卡片/看板视图、图形化自动化规则，显著降低学习成本 |

结论：本项目痛点与业界已验证方向一致，图形化改造必要且可行。

## 3. 目标（Go）

- G1 提供「项目类型流程总览图」，一屏可视化全部类型及流程；
- G2 提供三步向导（类型信息 → 流程绑定与排序 → 各阶段必填模板），新增/编辑类型统一走向导；
- G3 阶段顺序与阶段内模板排序支持拖拽，同时保留按钮/开关备选通道；
- G4 配置体系严格只做规则绑定，与模板内容创建、运行时内容提交解耦；
- G5 保留表格视图与旧入口，图形视图为默认，可自由切换。

## 4. 非目标（No-Go）

- N1 不新增数据模型，不改后端接口（复用 5 张表 + `/api/project/config/**`）；
- N2 本期不调整权限（仍 project:manage 可见）；
- N3 本期不实现影响面预览（v1.1 增强项）；
- N4 不在配置体系内承载模板内容编辑与运行时内容提交。

## 5. 用户故事

- US1 作为管理员，打开项目配置即看到全部类型的流程总览，快速判断某类型走哪些阶段；
- US2 作为管理员，新增类型时按向导三步完成配置，无需在不同弹窗/折叠面板间来回；
- US3 作为管理员，通过拖拽调整阶段顺序/模板排序，直观且即时反馈；
- US4 作为管理员，在图形界面中明确看到某阶段模板的来源（全局兜底 or 类型专属）与必填状态；
- US5 作为管理员，可随时切换回表格模式完成精细化编辑。

## 6. 功能需求

### FR1 项目类型流程总览图（P0）

- 主界面图形区展示全部项目类型及各自流程（横向阶段节点 + 连线）；
- 支持缩放/平移；点击类型或「配置」按钮进入该类型的向导编辑；
- 未配置流程的类型显示兜底提示（「未配置流程，默认使用全部启用阶段」）。

### FR2 三步向导（P0）

- 步骤1 类型信息：名称（唯一）、排序；保存沿用 project_type 接口；
- 步骤2 流程绑定与排序：从启用阶段中选择并排序，形成 type_phase_rel（sort）；
- 步骤3 各阶段必填模板：按阶段卡片展示模板，勾选必填、调整排序，保存 phase_template_rel（类型专属与全局兜底分离管理）；
- 新增与编辑统一复用向导；编辑时预填充现有配置。

### FR3 拖拽排序（P0）

- 阶段节点拖拽调整顺序（写回 type_phase_rel.sort）；
- 阶段内模板卡片拖拽调整顺序（写回 phase_template_rel.sort）；
- 同时保留上移/下移按钮、必填开关、移除按钮等备选通道。

### FR4 模板卡片与来源标记（P0）

- 阶段内模板以卡片呈现：名称、类型图标、必填开关；
- 区分标记「全局」（type_id=0 兜底）与「专属」（本类型绑定）；编辑全局绑定时给出影响提示。

### FR5 双模式切换（P0）

- 图形视图为默认；顶部提供「切换表格视图」按钮；
- 表格视图保留现有 4 tab 结构（项目类型、类型流程、流程阶段、模板管理）；
- 切换时对未保存状态给出提示。

### FR6 迷你流程缩略图（P0）

- 类型列表每行展示迷你流程缩略图（阶段圆点+连线），hover 放大查看；
- 与总览图共享组件与数据。

### FR7 兜底语义可见（P0）

- 未配置流程的类型、全局兜底绑定、被覆盖的专属绑定均以视觉标记呈现，降低误解。

### FR8 影响面预览（v1.1）

- 删除类型/阶段/模板、修改全局绑定时，事前列出受影响类型与项目数；
- 本期不做，设计预留接口与 UI 位。

## 7. 非功能需求

- NFR1 兼容现有数据：已有 5 表数据（含种子）无缝展示与编辑；
- NFR2 性能：总览图 ≤50 类型 / 300 节点流畅交互；列表页缩略图渲染不阻塞；
- NFR3 可维护：图形与表格共享同一数据源（Pinia store）与保存逻辑；
- NFR4 依赖：新增 vue-flow 相关包 ≤ 2 个，锁定版本；
- NFR5 无障碍：拖拽外保留按钮通道，键盘可操作排序。

## 8. 验收标准

- AC1 打开项目配置默认呈现流程总览图，所有类型流程正确渲染；
- AC2 通过向导新增类型：保存后类型列表、总览图、执行侧 ProjectEdit.vue 联动（新建默认阶段、阶段下拉范围）均正确；
- AC3 拖拽调整阶段顺序/模板排序后刷新页面顺序保持；
- AC4 全局/专属绑定来源标记清晰，必填校验（missingRequiredTemplates）行为与现状一致；
- AC5 表格/图形切换后数据一致；
- AC6 后端无任何代码/SQL 变更，现有接口回归通过。
