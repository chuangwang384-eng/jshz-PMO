| 项目 | 内容 |

## 1. 背景与目标

供应商管理模块已完整实做（v2.0：档案 + 图片/主图 + 酒店-打印店绑定）。本轮为增量改造，共三项：

1. **省份非必填、城市必填**：搜索/新增/编辑供应商时，省份不再必填，仅作为筛选字段；城市保持必填。
2. **图片可随时重命名 + 主图默认第一张**：供应商详情页图片名称可随时修改（不再局限于上传时命名）；主图在详情图库中默认置顶展示。
3. **酒店-打印店同城绑定**：酒店供应商与打印店的绑定必须发生在同一城市；存量跨城绑定提供清单供管理员确认后批量解绑。

目标：降低录入成本、提升图片管理体验、杜绝跨城绑定带来的业务风险。

---

## 2. 现状问题（探查结论）

### 2.1 省份/城市

- `supplier` 表只有 `city_id`，无省份字段；省份是前端分组展示与后端派生回填字段（`SupplierService.enrich()`）。
- 新增/编辑弹窗中省份、城市均为必填，且城市下拉在未选省份时禁用（`SupplierList.vue` L101-117、`SupplierDetail.vue` L171-187）。
- 后端仅校验城市（`cityId` 必须存在、`cityName` 精确匹配字典），不接收省份参数。
- 搜索区已按城市过滤，省份仅作城市下拉的筛选前置，符合"省份只作筛选"的目标。

**问题**：新增/编辑时强制先选省份才能选城市，录入效率低；且省份为派生展示字段，业务上无独立保存价值。

### 2.2 图片

- 图片上传时文件落盘为 `supplier_<uuid>.<ext>`（防路径穿越），显示名存 `supplier_image.name`（≤50 字符）。
- 上传框只支持为本次**第一个文件**命名，其余留空显示原文件名。
- 全代码**无重命名接口**，图片名上传后不可修改。
- 主图以 `is_main` 标识（每供应商至多一张，唯一索引 `uk_supplier_main` 保证）；首图自动为主图、可手动设主图、删除主图后自动提升 `sort_order` 最小者为新主图。
- 详情图库按 `sort_order`（上传顺序）排列，**主图不置顶**（仅格子打"默认封面"标签）；列表页封面已优先取 `mainImage`。

**问题**：图片名不可改、命名只作用于首文件；主图在详情页不置顶，与"封面图"心智不一致。

### 2.3 酒店-打印店绑定

- 绑定关系表 `supplier_hotel_print_rel`（`hotel_id` + `print_shop_id`，唯一约束）。
- 绑定接口 `SupplierService.bind()` 仅校验：id 合法、供应商存在、类型组合为 HOTEL+PRINT、不重复绑定；**无任何城市一致性校验**。
- 添加绑定弹窗的候选列表（`loadBindCandidates` → `listSuppliers({typeId, page, size})`）**不过滤城市**，下拉仅展示对端城市名（`o.cityName`）。

**问题**：能绑定到非本城市的打印店，业务上不合理（酒店需要本地打印服务），且无警示。

## 3. 范围

### 3.1 需求一：省份非必填、城市必填、省份仅作筛选

**目标规则**

1. 新增供应商弹窗：省份改为选填（仅用于联动筛选城市），城市必填且**始终可选**、支持搜索直选；选了省份后仍按省联动收窄城市列表。
2. 编辑供应商弹窗：与新增一致，省份选填、城市必填、城市可搜索直选。
3. 搜索区保持现状：省份仅作城市下拉筛选前置，查询按城市过滤。
4. 后端校验不变：城市必填、城市必须在固定只读字典中；省份参数仍不接收、不校验。

**涉及范围**：`SupplierList.vue` 新增弹窗、`SupplierDetail.vue` 编辑弹窗、`frontend/src/utils/supplier.js` 分组联动逻辑。后端零改动。

**验收标准**

- [ ] 不选省份时，新增/编辑弹窗城市下拉可用，输入关键字可搜到城市并选择；
- [ ] 选择省份后，城市下拉仅列出该省城市；切换省份自动清空已选城市；
- [ ] 未选省份、仅选城市可正常提交新增与编辑；
- [ ] 城市未选时提交，提示"请选择城市"，不产生请求；
- [ ] 提交 payload 不含省份；后端按 `cityId` 反查省份展示正常；
- [ ] 搜索区省份筛选、按城市查询行为与现状一致。

### 3.2 需求二：图片可随时重命名 + 主图默认第一张

**目标规则**

1. 详情图库每张图片提供"改名"操作，弹窗输入新显示名（≤50 字符），提交后立即生效；
2. 改名只修改显示名 `name`，物理文件名 `supplier_<uuid>.<ext>` 保持不变；
3. 允许重名（显示名无唯一性约束）；
4. 主图规则维持现状：首图自动为主图、可手动设主图、删除主图后自动提升一张；
5. 详情图库展示顺序：**主图排第一**，其余按 `sort_order` 升序（展示层排序，不动历史数据）；
6. 手动设主图后立即置顶。

**涉及范围**：后端新增改名接口 + 图片列表排序调整（`SupplierImageService`/`SupplierController`）；前端图库改名交互（`SupplierDetail.vue`）。

**验收标准**

- [ ] 图库每张图片有"改名"入口，输入 ≤50 字符名称保存后，图名立即更新；
- [ ] 重名图片可正常保存；
- [ ] 空名称保存后回退为显示原文件名（与现状上传逻辑一致）；
- [ ] 改名后刷新页面名称保持；
- [ ] 主图在详情图库排第一位，其余按上传顺序；
- [ ] 手动设置某图为新主图后，该图立即置顶；旧主图取消主图标记；
- [ ] 上传新图（首图自动为主图）后，新主图立即置顶；
- [ ] 删除主图后自动提升一张为新主图并置顶；
- [ ] 列表页封面展示与现状一致（优先主图）。

### 3.3 需求三：酒店-打印店同城绑定

**目标规则**

1. **同城判定**：`hotel.city_id == print_shop.city_id`（同一城市字典记录，如"广州市"对"广州市"）；同省不同市不算同城；
2. 绑定接口新增城市一致性校验：跨城绑定直接拒绝并返回明确错误；
3. 添加绑定弹窗候选列表**只列出同城**候选（带城市标签），跨城不可见；
4. 绑定关系列表：跨城存量关系显示"跨城"警示标签（基于对端 `cityId` 比对）；
5. 新增"跨城绑定清单"入口（供应商管理页）：列出全部存量跨城绑定（酒店、打印店、各自城市、绑定时间）；
6. 管理员在清单中勾选多条 → 批量解绑 → 弹窗二次确认后执行；
7. 操作权限沿用现有管理员体系，不新增权限码。

**涉及范围**：后端 `SupplierService.bind` 校验、候选列表接口（前端传 `cityId` 过滤）、新增跨城清单与批量解绑接口、`bindingsOf` 返回对端 `cityId`；前端绑定弹窗、绑定列表标签、跨城清单页/弹窗。

**验收标准**

- [ ] 同城市酒店与打印店可正常绑定；
- [ ] 跨城市绑定被拒绝，提示如"仅支持绑定同城市的打印店/酒店"；
- [ ] 添加绑定弹窗只出现同城候选，选项带城市标签；
- [ ] 绑定列表中跨城存量关系显示"跨城"标签；
- [ ] 跨城绑定清单正确列出全部存量跨城关系（分页正确）；
- [ ] 勾选多条批量解绑成功，解绑数量正确，二次确认拦截生效；
- [ ] 解绑后绑定关系列表与数据库一致；
- [ ] 非管理员无跨城清单入口与解绑操作权限（沿用现有权限码）。

## 4. 非功能要求

| 类别 | 要求 |
|---|---|
| 兼容性 | 三项改动均为增量，不改变现有数据表结构（无 DDL）；存量数据无需迁移 |
| 性能 | 城市下拉为本地过滤（城市数据已全量加载，349 条）；跨城清单分页查询 |
| 安全 | 改名接口校验图片归属当前供应商；批量解绑校验关系存在性；沿用现有鉴权 |
| 一致性 | 绑定批量解绑需事务保证 |
| 可回滚 | 前端改动可独立回滚；后端新增接口不影响旧逻辑；存量数据不动 |

---

## 5. 边界与不做

- 不做图片拖拽排序功能；
- 不做图片改名审计日志（如需可后续扩展）；
- 不做城市字典开放（维持固定只读）；
- 不自动解绑存量跨城关系（需管理员确认后批量解绑）；
- 不改列表页封面逻辑（现状已优先主图）。

## 6. 决策记录表

| # | 决策点 | 结论 | 理由 |
|---|---|---|---|
| Q1 | 不选省份时城市下拉形态 | 始终可用、支持搜索直选；选省份后仍按省联动过滤 | 城市 349 个需可搜索；保留联动收窄体验 |

| Q9 | 跨城清单与解绑流程 | 绑定列表"跨城"标签 + 清单页勾选批量解绑 + 二次确认；沿用管理员权限 | 兼顾可见性与可控性 |
