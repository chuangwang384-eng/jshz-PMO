## 1. 目标与已确认决策

管理员能在同一个配置向导内定义项目类型、增补阶段、配置员工应提交的内容，并在保存前理解效果。员工使用项目创建时的流程与材料规则，不受后续配置维护影响。

| 编号 | 用户已确认的规则 |
| --- | --- |
| D1 | 向导内就地新增阶段，纳入公共阶段库，其他类型可主动选用；不自动加入其他类型。 |
| D2 | 项目类型全局排序为连续且唯一的 1～N；新增默认末位，移动时其他类型自动顺移。 |
| D3 | 新项目使用新配置，已有项目保留创建时配置。 |
| D4 | 每个阶段明确选择“沿用通用要求 / 为此类型单独配置 / 无需提交材料”。 |

以下交互细节为本轮设计建议，评审后作为施工依据：草稿一次保存、员工预览、复制类型作为后续增强。本文不代表已实现或已上线。

## 2. 当前问题与边界

现有阶段维护在独立页签，类型向导只能选择已有阶段，必须离开当前操作补字典。未配置流程的类型默认使用全部启用阶段，新增公共阶段存在隐式影响。类型排序没有唯一校验，数字相同后靠 ID 排序。

“模板”在本系统指附件、专家、供应商、预算、富文本等资料要求，并不等于可下载的 Word 模板。配置定义规则，实际业务内容仍由员工在项目侧提交。本轮保留线性流程、现有材料类别和项目权限体系，不新增分支审批、自动通知、外部 AI、任意字段表单或单份附件对应多个独立材料项的精细校验。

当前代码按当前阶段的材料校验能否向后推进；附件和富文本按项目阶段统计，专家、供应商和预算按项目统计。引导须如实说明，不宣称每张同类别卡片都独立收集一份资料。

## 3. 页面与操作流程

### 3.1 第一步：类型信息

输入类型名称和展示位置。位置显示“第 3 位，共 8 个类型”，提供位置选择及移动前后的列表预览；新建默认最后。首页总览支持拖动，同时保留上移、下移供键盘和精确操作。

保存成功后显示服务器返回的最终顺序；多人操作发生冲突时提示“配置已被他人修改，请刷新后重试”，保留本人的未保存输入，不静默覆盖。

### 3.2 第二步：安排阶段

“添加已有阶段”支持名称搜索；无结果时出现“新建并加入当前流程”。轻量表单只需名称，提示保存后可供其他类型选用。空白、同名、停用同名和并发新增均给出可操作反馈：已有启用项直接选用；停用项跳转维护或取消，不偷偷恢复启用。

新增阶段在本次草稿中即时出现，完成整个向导才写入阶段库；取消向导不遗留公共阶段或半成品类型。移除阶段只改变当前草稿，不删除公共阶段。公共阶段维护入口保留，新增引用次数、停用说明和维护前影响提示。

流程必须至少一个阶段，不允许同一阶段重复；通过拖动或上下移动设定顺序。默认用紧凑列表明确显示完整流程，图形作为可切换预览；避免横向画布裁切成为唯一编辑入口。新类型不再隐式跟随全部启用阶段，可以主动选择“使用当前通用阶段作为起点”，形成独立的阶段列表。

### 3.3 第三步：设置各阶段提交要求

步骤标题改为“设置员工需提交的内容”。左侧阶段显示“待确认 / 已确认”、必填与选填数量；只有当前草稿确实确认过的阶段才标记完成，“无需提交材料”同样是明确完成状态。

| 模式 | 交互与规则 |
| --- | --- |
| 沿用通用要求 | 直接展示实际通用清单及来源；提示以后创建的项目使用届时通用要求，已创建项目保持不变。通用清单为空时明确显示“当前没有通用要求”，仍需确认。 |
| 为此类型单独配置 | 首次切换可复制当前通用清单作为起点，然后独立增减、选择必填/选填和排序。清空后提示改选“无需提交材料”，不自动回退。全部选填合法。 |
| 无需提交材料 | 不应用任何通用要求；显示“该阶段无材料拦截，员工仍可按现有权限添加资料”。 |

卡片展示资料名称、类别、必填/选填、填写说明与示例入口。示例使用虚构内容，不读取真实项目。说明明确：“必填表示离开当前阶段、向后推进前必须完成；不阻止保存项目或保存未完成的材料”。预算为 0 与未填写须区分，富文本是否完成沿用经回归确认的现有判定，不在本轮暗改标准。

提供常驻简短帮助：“选阶段 → 选要求模式 → 设置必填 → 预览”。可重看示例，不依赖一次性气泡教学。阶段切换、上一步操作保留草稿；加载失败明确提示重试，不把失败展示成空清单。保存失败保留草稿，重复点击不重复创建。

### 3.4 保存前检查与员工预览

第三步内提供“预览与确认”，不增加强制的第四个步骤。按阶段展示员工将看到的资料入口、必填标识、满足规则的口径，以及未满足时的推进提示。预览与实际运行采用同一套规则解析。

保存摘要列明新增公共阶段、阶段增删与顺序、各阶段要求模式、类型位置变化，并明确“本次不修改已有项目”。缺阶段、未确认模式、无效引用等错误定位回对应位置。整体提交成功后关闭向导，部分失败不得提示保存成功。

## 4. 复用与已有项目保护

项目创建时冻结：阶段成员与顺序、阶段名称、资料要求模式、解析后的资料清单与名称/类别/必填顺序。后续公共阶段改名、停用、通用要求修改、类型调整不改变该项目的显示和校验。类型列表展示位置属于管理界面排序，不是项目流程快照内容。

上线前对存量项目建立当时有效配置快照。历史上没有保存过的配置无法倒推：只能冻结迁移时的有效规则，不能声称还原项目最初创建时规则。当前阶段或历史材料引用不在有效流程内时列异常清单，人工确认后迁移，不能自动猜测插入顺序或移除业务资料。

已有项目类型调整在首期仅允许不改变类型的普通编辑；若请求改变类型则后端拦截并说明原因。既有业务确需换型时，后续另做显式迁移向导，避免普通保存悄悄替换规则。该兼容限制需施工前列入影响评审。

## 6. 验收条件

| 编号 | 场景与通过标准 |
| --- | --- |
| A1 | 向导内新增阶段后能排序、配要求；保存后进入公共库，仅当前类型包含该阶段。取消不落库。 |
| A2 | 新增公共阶段后，原来未显式配流程的其他类型及其已有项目不增加阶段。 |
| A3 | 类型新增、插队、拖动、删除后排序为 1～N；并发操作成功或明确冲突，数据库无重复位置。删除仍遵循原引用拦截。 |
| A4 | 三模式逐一验证；单独配置全部选填不继承通用必填；无需材料不被通用要求拦截。 |
| A5 | 第一次使用者能够看出材料在哪里填写、必填何时生效；在各阶段切换不丢草稿，所有阶段确认后才可提交。 |
| A6 | 修改类型/通用要求/公共阶段后，旧项目页面、推进、回退、材料校验保持其快照；新项目获得新规则。 |
| A7 | 前端预览、详情缺失提示和后端推进校验一致；乱序公共阶段不影响项目自身顺序。 |
| A8 | 断网、加载失败、重复保存、并发同名、非法输入均无半成品；无权限用户不能通过直接接口修改。 |
| A9 | 存量迁移可重复执行、无重复快照；异常项目有清单，材料、日志、负责人等原业务数据保持不变。 |

建议首次使用者任务验收：不用口头指导，完成一个含新阶段的类型，正确指出必填的生效时机，预览并保存；记录实际误操作点，不能以开发者自行点通代替易用性验收。
