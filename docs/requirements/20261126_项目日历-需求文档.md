## 1. 背景与目标

项目已有会议举办起止日（`project.meeting_start_date / meeting_end_date`），负责人、协助人、执行人也分别记录在 `project`、`project_assistant`、`project_executor`。但这些信息只能在项目列表和项目详情里逐个查看：员工看不到自己某一周的会议分布，部门负责人也无法判断某位员工哪天已被占满，容易出现撞期和排期失衡。

**目标**：提供按日期展示的项目日历，让个人看清自己的会议，让部门负责人看清本部门每个人的会议，且不扩大现有项目详情的查看范围。

## 2. 范围

**范围内**

- 项目管理页新增“日历”视图（与列表并列）。
- 工作台新增“我的近期会议”卡片；部门负责人另有“本部门会议概览”卡片。
- 立项时会议日期改为必填。
- 项目的 `team` 字段与组织架构树自动同步。

**范围外（本期不做）**

- 请假、出差、培训等非项目占用事项。
- 日历订阅（iCal）、企业微信日程同步、拖拽改期。
- 按项目阶段、客户、城市等维度的日历筛选。
- 跨部门（如总经理看全公司）的专门视图，见 8.1。

## 3. 已确认口径

| 编号 | 口径 | 说明 |
| --- | --- | --- |
| C1 | 负责人、协助人、执行人三类都算“有会议” | 日历上必须标出该人在此项目中的角色 |
| C2 | 部门以组织架构树为准 | 员工所属部门取自其在组织架构中的归属 |
| C3 | `team` 字段自动同步为组织架构树内容 | 不再由用户手选 |
| C4 | 会议举办日期立项必填 | 起止日期都要填，单日会议起止同日 |
| C5 | 已取消、已删除的项目不显示 | 只显示状态为正常的项目 |
| C6 | 部门负责人仅见日期、项目名、负责人 | 点进详情时按原有项目权限校验，日历不能绕过查看范围 |

## 4. 用户场景

- **S1 员工看自己的月历**：李明打开项目管理，切到日历，看到 12/01 同一天有两场会（一场负责、一场协助），当天格子标“撞期”，他提前找同事调整分工。
- **S2 工作台一眼看到近期会议**：李明登录后在工作台看到“明天有一场会（执行人）、下周一有一场会（负责人）”，点进去直接到项目详情。
- **S3 部门负责人看员工排期**：王芳切到“本部门”，看到项目一部每位员工在本月每天的会议占用，发现张婷 12/01 当天两场会，决定把其中一场的协助工作转给刘洋。
- **S4 负责人看到别部门项目但打不开详情**：王芳在排期里看到李明 12/08 有一场二部赵磊负责的会议，能看到日期、项目名、负责人；点“详情”时提示无权限，因为她不是该项目成员。
- **S5 立项必填会议日期**：新建项目时不填会议日期，系统提示必填，无法提交。
- **S6 部门调整后自动对齐**：员工调到项目二部后，其负责的未结项项目的团队标识自动更新，部门负责人看到的人员范围随之变化。

## 5. 功能需求

**FR-01 项目页日历视图**

- 项目管理页顶部提供“列表 / 日历”切换，切换状态与月份写入 URL，刷新和分享链接可还原。
- 个人月历：按月展示当月所有与自己相关的会议，多日会议在每个日期格子都显示。
- 会议以“角色标记 + 项目名”呈现，角色用文字（负/协/执）加颜色双重区分，不仅靠颜色。
- 当天有两场及以上会议时，格子标“撞期”。
- 点击会议进入项目详情，权限沿用现有校验。

**FR-02 部门员工排期**

- 仅部门负责人可见“本部门”切换。
- 以“员工 × 日期”的排期表展示本月，格子显示该员工当天的角色标记，多场会议标“!”。
- 点格子弹出当天会议列表，每条仅含日期、项目名、负责人、该员工的角色。
- 点“详情”时按原项目权限校验，无权限返回 403 并给出明确提示。

**FR-03 工作台卡片**

- “我的近期会议”：未来 14 天与我相关的会议，含日期、项目名、角色、距今天数。
- “本部门会议概览”（仅部门负责人）：未来 7 天涉及会议数、未来 14 天撞期处数与明细。
- 两张卡片纳入工作台现有可编辑布局，可显示、隐藏、拖动。

**FR-04 立项会议日期必填**

- 新建项目时会议起止日期必填，起日不得晚于止日。
- 编辑项目时不允许把会议日期清空。
- 存量项目缺失会议日期的，上线前须补齐，见 8.2。

**FR-05 team 自动同步**

- 项目的团队由负责人在组织架构中的部门自动得出，项目表单不再提供手选。
- 员工部门变更后，其名下未结项项目的团队标识自动更新。

**FR-06 过滤规则**

- 已取消、已删除项目在所有日历视图和工作台卡片中都不出现。

## 6. 非功能需求

- **权限**：日历接口只返回日期、项目名、负责人及角色，不返回预算、客户、专家、文件等字段；部门范围由服务端依据当前登录人的部门负责人身份计算，不接受前端传入部门。
- **性能**：一个月范围查询在约 35 个用户、数百个项目规模下应在 1 秒内返回。
- **一致性**：日期口径按 Asia/Shanghai 业务日期；撞期判定规则前后端只保留一处实现。
- **样式**：遵循 AGENTS.md 第 17 节的设计令牌，不硬编码颜色，暗色模式可用。
- **兼容**：迁移向后兼容，旧版本前端在新后端上仍能工作（README R-3）。

## 7. 验收条件

- [ ] 员工月历包含自己作为负责人、协助人、执行人的全部会议，角色标记正确，多日会议逐日显示。
- [ ] 同一人同一天两场及以上会议时，月历格子和部门排期均有撞期标识。
- [ ] 已取消、已删除项目在日历、排期、工作台卡片中均不出现；恢复后重新出现。
- [ ] 普通员工看不到“本部门”入口，直接调用部门范围接口返回 403。
- [ ] 部门负责人只能看到本部门成员的排期（范围按 8.1 的决定），看不到其他部门成员。
- [ ] 部门负责人在排期里点非本人参与的项目详情，返回 403 且提示清晰；点本人参与的项目可正常进入。
- [ ] 日历接口响应中不含预算、客户、专家、文件等字段（抽查响应体）。
- [ ] 新建项目不填会议日期被拒绝，错误提示指出字段；编辑时清空会议日期被拒绝。
- [ ] 员工调整部门后，其未结项项目的 team 在约定时间内更新，部门负责人范围同步变化。
- [ ] 工作台两张卡片可在布局编辑中显示、隐藏、拖动，刷新后保持。
- [ ] 日历 URL 带月份参数刷新后还原；暗色模式与窄屏（≤768px）可用。

## 8. 待决事项与待核实

1. **部门负责人是否可见下级部门**：组织架构是树形（项目部下含项目一部、项目二部、项目三部等）。建议负责人可见本部门及全部下级部门成员；总经理则可见全员。需负责人确认。
2. **存量项目补会议日期**：生产库中会议日期为空的项目数量未核实。建议上线分两步：先发日历（不强制），补齐存量后再发必填校验。
3. **team 与组织架构的对应**：现有 team 只有项目一部/二部/三部三个值，组织架构里还有“重点项目部”等部门。负责人不在这三个部门时，团队如何取值（留空、沿用原值，还是新增取值）需决定。
4. **部门调整的历史口径**：调岗后，历史会议在日历里按“当前部门”还是“会议时点部门”归属？建议本期按当前部门，不做历史追溯。
5. **协助人的列表可见性**：现有项目列表的行级过滤只含负责人和执行人，协助人能打开详情但在列表里看不到。日历会显示协助人的会议，两处口径不一致，需决定是否一并修正列表。
6. **停用员工**：已停用账号参与的未来会议，是否仍显示在部门排期里。建议显示并标注“已停用”，提醒负责人改派。
