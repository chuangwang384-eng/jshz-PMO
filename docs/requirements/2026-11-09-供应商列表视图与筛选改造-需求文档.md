# 供应商列表视图与筛选改造需求

日期 2026-11-09 · 状态：Owner 已给交互原型，按原型实施 · 版本 v1.0

适用于供应商管理列表页（`frontend/src/views/supplier/SupplierList.vue`，路由 `/supplier`，菜单「供应商管理」）。目标：把现有单一卡片网格改为「列表 / 卡片」双视图 + 完整的搜索筛选条 + 可按名称/更新时间排序，贴合 Owner 提供的交互原型。

## 1. 现状事实（2026-11-09 核实）

| 项 | 现状 | 位置 |
| --- | --- | --- |
| 页面结构 | 一行 toolbar（搜索框 200px + 类型 + 城市 + 搜索 + 重置 + 新增供应商 + 类型管理）+ 卡片网格 + 分页 | `SupplierList.vue`（464 行，改造前） |
| 视图 | **仅卡片视图**（封面图 140px + 名称 + 类型标签 + 省市 + 星级） | `.card-grid` / `.sup-card` |
| 搜索 | `keyword` 同时模糊匹配**名称 / 地址 / 联系人**，需点「搜索」或回车 | `SupplierService.pageSuppliers` |
| 筛选 | 类型（`typeId`）、城市（`cityId`）两项 | 同上 |
| 排序 | 固定 `update_time DESC, id DESC`，前端不可选 | 同上 |
| 分页 | `size` 默认 12，页容量 12/24/48 | `SupplierList.vue` |
| 状态字段 | **数据库无合作状态字段**（`supplier` 表仅有档案字段）；有评价才有 `avgStars`/`reviewCount` | `entity/Supplier.java`、`database/migration/20261026_add_supplier_module.sql` |
| 列表接口 | `GET /api/supplier/list?keyword=&typeId=&cityId=&page=&size=` | `SupplierController.list` |

## 2. 目标与非目标

**目标**
1. 列表 / 卡片视图可切换，选择本地记住（下次进入保持）。
2. 顶部两行筛选：名称/联系人搜索（输入即搜）、类型、城市、重置；第二行「仅看已评价」+ 视图切换。
3. 汇总行展示「共 N 家供应商」，右侧可切换排序（按名称 / 按更新时间）。
4. 列表视图每行展示：类型图标、供应商名称 + 类型标签、属地与联系人、评分与评价数、状态徽标、查看详情入口。

**非目标（本期不做）**
- 不改供应商详情页、新增弹窗、类型管理弹窗、图片/行价/评价/绑定任何逻辑。
- 不改权限模型（档案全员可维护，类型管理 `supplier:dict`，新增 `supplier:create`）。
- 不改数据库结构（不新增「合作状态」字段）。
- 不做批量操作、导出、卡片内联编辑。

## 3. 交互规格（对应原型）

| 原型元素 | 规格 |
| --- | --- |
| 搜索框 | 占位文案「搜索供应商名称、联系人」；清空即恢复全量；输入 400ms 防抖自动查询，回车立即查询 |
| 全部类型 / 全部城市 | 下拉可清空；`change` 即查询，页码回到第 1 页 |
| 重置 | 清空关键字/类型/城市/「仅看已评价」，排序恢复「按名称排序」 |
| 仅看已评价 | 勾选后只返回有评价的供应商（`onlyReviewed=1`） |
| 列表视图 / 卡片视图 | 二选一切换，样式为浅灰胶囊选中药；选择持久化在 localStorage（`supplier-view-mode`） |
| 共 N 家供应商 | 取接口 `total`，随筛选变化 |
| 按名称排序 | 下拉：按名称排序（默认）/ 按更新时间排序 |
| 列表行 | 左侧类型图标；标题行「名称 + 类型胶囊」；副行「省份 · 城市 · 联系人」；第三行「★ 4.8（12条评价）」，无评价显示「尚无评价」 |
| 行右侧 | 「查看详情」按钮；整行可点击进详情（**状态徽标「合作中/待评估」按 Owner 2026-11-09 二次要求已移除，见 §4**） |
| 分隔线 | 行间 1px 浅灰横线（`#eef1f5`），无纵向边框、无斑马纹 |

## 4. 状态徽标（已移除）

**结论（Owner 2026-11-09 二次确认）：列表行与卡片均不展示状态徽标。** 1.0.37.19 曾按下列推导口径上线，1.0.37.20 全部移除（含列表行右侧与卡片封面右上角），代码中的 `statusOf()` 与 `.status-pill` 样式一并删除。

保留推导记录备查：数据库没有合作状态字段，评价是系统内唯一「已实际合作并留痕」的事实，故原口径为「有评价（`reviewCount > 0`）= 合作中，无评价 = 待评估」。原型中「郑州大酒店 尚无评价 + 合作中」「北京首旅 4.6 分 + 待评估」为演示数据的随机组合，不是口径依据。

不做状态的原因：状态判断易引起歧义（有评价≠仍在合作），且信息价值低于「评分 + 评价数」，去掉后行右侧只有一个动作按钮，视觉更干净。

## 5. 验收标准

1. `/supplier` 打开默认列表视图；切到卡片视图后刷新页面仍为卡片视图。
2. 输入「北京」→ 列表只剩名称/地址/联系人匹配项，「共 N 家」同步变化。
3. 选类型「酒店」+ 城市「郑州市」→ 结果同时满足两个条件；点「重置」全部恢复。
4. 勾「仅看已评价」→ 返回的每一行都有评分（无「尚无评价」行）。
5. 排序切「按更新时间排序」→ 首行是最近更新的供应商。
6. 任一供应商点「查看详情」或行本身 → 进入 `/supplier/{id}` 详情页。
7. 无权限账号不见「新增供应商」「类型管理」入口（沿用 `supplier:create` / `supplier:dict`）。

## 6. 边界与已知限制

- 「按名称排序」为 MySQL 默认排序规则（`utf8mb4_general_ci`），中文按字面编码排序，**非拼音顺序**；如需拼音排序需引入排序字段，本期不做。
- 城市筛选为字典单选（一供应商一城市），不做多选；跨城筛选仍按单城市。
- 「仅看已评价」与排序均在服务端执行（保证分页后的 total 与排序正确），不做前端二次过滤。
