# 知识星球模板生成与微盘集成可行性评估

评估日期：2026-11-04。状态：分析已完成，方案待评审；未实施、未迁移、未发布。

## 1. 结论与负责人已确认方向

负责人确认：**上传规范文件生成草稿，人工确认后发布**。本轮评估不构成对数据库、权限或生产变更的批准。

目标可行，但应重构企业合规的模板生成与确认体验，复用现有 V4 模板版本、个人执行、执行快照、历史及提醒机制。不要将其整体替换成另一套清单系统，也不要把“文件提取成功”当成“合规要求识别完整”。

报告中的平台分类和共性阶段有参考价值；微盘文件数量、目录覆盖、各平台规则同质性及解析准确率尚未经本轮独立验证。目录名可以辅助推荐标签和附件，不能作为必办要求的权威来源。

## 2. 现状核查与报告修正

| 事项 | 代码证据及评估 |
| --- | --- |
| 上传自动生成新版模板 | KnowledgeDocumentService.upload 仅对 enterprise-compliance 调用旧 ComplianceService.parseAndCreateDrafts；产物是旧版事项，不是 V4 模板。需新建明确的解析草稿接入流程；不建议先写旧表再自动迁移。 |
| 文本解析基础 | KnowledgeDocTextExtractor 把全部空白压成空格，而 ComplianceParseService 按换行拆分、排除超过190字符的行。常规长文可能整段被排除。需独立结构化提取，不能直接复用搜索用的压平正文。 |
| Excel 支持 | 分发接受 xls/xlsx，但实现使用 XSSFWorkbook，不能据此认定支持旧 xls；仅首工作表、首行表头，公式/日期/合并表头等需补齐。结构化不等于业务识别高准确率。 |
| PPTX及扫描件 | 当前提取器没有 PPTX 分支；PPTX文字可补充提取，图片里的文字、扫描PDF和复杂表格需OCR与质量校验。未验证部署依赖和真实样本。 |
| 文件更新 | updateVersion 保存版本和正文、清预览缓存并通知收藏者，没有重新生成模板草稿。更新应产生新草稿及差异，不覆盖已发布模板和在途执行。 |
| 模板编辑复杂度 | ComplianceTemplateEditor 当前已是平铺节点卡片，不是必须手工建树；主要问题是字段密集、草稿/版本操作分散。可围绕生成结果改造为简洁表格及原文对照。 |
| 分类与权限 | ComplianceV4AccessService.requireDocument 明确只接受 enterprise-compliance。协会合规接入不能只改前端或触发条件；需评审后端资源边界、接口查询、发布及执行权限。菜单地址可以保留，权限影响不能称为零。 |
| V4是否已启用 | 仓库有V4生产发布记录，不能以配置默认false认定未上线。本轮未读取实时生产开关、数据库或进程，不声明当前运行状态。 |

现有 V4 同时包含来源文档、项目可读性、个人执行归属检查。其存在不等于已经实现微盘原始ACL同步；自动导入不可把原本受限微盘文件变成全员可读文档。

## 3. 建议需求范围

### 3.1 三个子菜单

保留会议执行标准、协会合规要求、企业合规要求三个入口。菜单是业务分类；平台/机构、适用场景和文件用途是独立标签，不应硬绑“一平台一模板”。先在企业合规打通生成闭环，再评估协会合规共用能力；会议执行标准可先保持资料库，只在确有可执行清单需求时接入。

文件用途至少区分：规范依据、空白表单/示例、执行证明材料。后两类不能默认解析成强制任务；身份证明、账户资料等默认排除自动采集。

### 3.2 主流程

1. 上传规范，选择业务分类、平台与场景；支持选择既有文档版本。首期单规范生成，多来源合并作为明确扩展，不强行把每个文件都变成模板。
2. 后台显示等待、提取中、待确认、失败等状态，上传成功与解析成功分开；可安全重试，不重复生成草稿。不能解析时保留原文件并说明原因。
3. 生成待确认草稿：分组/阶段、事项名称、完成标准、必需材料、适用条件、时间规则、原文引用。无法确定的字段留空并标注待核实，不补造要求。
4. 默认简洁表格编辑，支持删改、排序、补充及合并重复项；原文对照显示页码/段落/表格定位及摘录。长说明和条件分支收起为高级项，不强迫维护者逐条配置选择题。
5. 发布前检查来源、必要字段、未确认风险及条件冲突；高风险字段如强制性、金额、期限、例外条件必须明确确认。空草稿、提取不完整和无有效来源不得伪装为识别成功。
6. 维护者预览员工使用效果并发布版本。上传者可生成或编辑不等于有发布权，沿用并核验既有维护权限。
7. 员工复用已发布模板形成个人执行；个人日期、答案、备注、进度不回写公共模板。再次使用形成独立执行。
8. 规范更新生成新版本草稿，突出新增/变更/删除及来源变化；已开始执行保留原快照，是否迁移由单独规则决定，不自动替换。

共性清单可作为可选的“参考模板复制”，必须区别于从原文识别的事项，避免把通用建议误标为该平台强制规范。首期不需要先建设实时继承的“骨架+参数覆盖”引擎，否则新增冲突优先级和版本维护成本。

## 4. 技术方案与可行性边界

建议链路：原文件及版本 → 保留段落/页码/表格的结构化提取 → 候选事项及引用 → 去重/适用性检查 → 人工确认 → V4草稿 → 发布 → 原有执行链路。

- **高可行性**：简化确认界面、复用V4版本与执行、结构化Excel导入、文字型PDF/DOCX/PPTX提取。仍需真实样本测试，不能承诺任意排版均可识别。
- **有条件可行**：自然语言规范中准确抽取事项、否定/例外/条件和相对期限。仅关键词切行不足以实现。可先规则辅助；如采用模型，先确认本地部署能力、成本和数据边界，未经单独批准不得调用外部模型处理公司资料。
- **暂不能承诺**：扫描表格准确率、跨文件完整合并、自动发现所有缺失要求、全微盘自动同步并等价继承权限。

解析任务与业务模板分离；建议按来源文档版本、解析器版本和配置标识做幂等。解析失败或旧任务晚到不覆盖新结果；提供超时、重试、取消、错误提示和完整性标记。发布使用版本冲突校验；来源更新或撤权后必须重新校验。保留稳定节点标识，不能因排序或重生成无故改变事项身份。

当前代码可以复用但需要补齐：异步解析任务、草稿接入、结构化提取、解析结果原文对照、来源追溯和发布校验。多来源引用、平台元数据、解析任务记录可能需要数据库迁移，具体结构须在技术设计时核实实际数据库；本轮不预设新增表数量。

## 5. 微盘集成的处理方式

Agent能够检索微盘，不等于当前业务服务已获相同授权，更不等于每位员工可以读取Agent可见资料。腾讯云官方连接器资料证明存在微盘列表/文档信息集成能力，但资料有时效性，不能代替当前企业授权与API联调：
https://hiflow.tencent.com/docs/applications/qywechat-microdisk/

建议首期授权人员手动导入规范，先验证草稿质量。后续选定少量空间/目录开展只读同步试点，核验应用授权、实际列表和下载能力、在线文档导出支持、文件版本、API限制、网络与权限映射，再决定轮询或回调。不要为首期默认开放公网回调端口。

同步需稳定来源标识、源版本/内容摘要及本地版本映射；改名移动不能重复创建，删除/撤权不得继续通过本地副本或旧索引扩大访问。更新只创建新草稿，不能自动发布。明确原件存储保留、敏感文件排除、权限收回、审计与同步失败策略；不得把临时下载链接当永久原件。

报告中的22个平台和约69个候选文件是其Agent可见范围的调研结果，不是本轮核实的完整企业资产，也不是已评测的数据集。

## 6. 分期与验收建议

| 阶段 | 可交付成果 | 验收重点 |
| --- | --- | --- |
| 一：生成与确认闭环 | 企业合规上传→解析草稿→原文确认→发布→员工复用；简化编辑并保留原有执行 | 文件上传失败/解析失败/空文本分开；重复和并发不覆盖；无权不可读写发布；已有执行和提醒不受影响 |
| 二：识别质量及复用范围 | 补格式、复杂表格、条件/期限识别与可选参考模板；按批准范围扩展协会合规 | 不同排版及更新样本逐项人工标注；分别统计事项准确率、召回率及期限/金额/条件正确率，不能只统计能打开多少文件 |
| 三：微盘试点 | 白名单目录只读拉取、增量更新、来源追溯和撤权处理 | 真实授权测试；改名/移动/删除/失权/限流/重试；不得出现越权或自动发布 |

至少选三类有代表性的规范样本：结构化表格、叙述性PDF/DOCX、PPTX或扫描件，并包含规则变化前后版本。需要业务人员提供人工正确清单作为评测基准；不把目录结构当标准答案。发布后的正确性由人工确认承担，但系统应主动暴露低质量和缺失提取，不能将责任全部推给确认按钮。

“5分钟完成”“90%覆盖”等目前只能作为待验证目标。应记录完整生成耗时、人工改动比例、漏项情况和发布用时后再给工期与质量承诺；首次试点不设未经依据的精确估算。
