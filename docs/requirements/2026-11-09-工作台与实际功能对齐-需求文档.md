## 1. 审查范围与事实源

| 事实源 | 核实方式 | 结论 |
| --- | --- | --- |
| 实际菜单/路由 | `frontend/src/router/index.js` + `utils/menu.js`（菜单由路由表生成） | 一级：工作台、专家库、知识星球（4 个二级）、个人中心（6 个二级）、供应商管理、项目管理、管理员设置 |
| 实际项目流程 | 1.0.37.24～.27 交接/发布记录 + 库内 `project_phase` | 类型/执行人概念删除；旧 6 阶段停用，仅「日程上传」激活；配置接口 410；成员=负责人/创建人/协助人 |
| 工作台线上返回 | `GET /api/dashboard/overview`（测试账号，2026-11-09 16:25） | `phaseName="配置异常"`、`completionState=UNKNOWN`、`warning=UNKNOWN_COMPLETION`、`unknownCompletionCount=1`；逾期/今天/七天到期均 0 |
| 搜索线上返回 | `GET /api/search/global?keyword=测试` | 项目分组 `extra="配置异常"` |
| 库内数据 | `project` 1 行（CANCELED）；`project_executor` 0、`project_phase_history` 0、`project_phase` 仅日程上传启用 | 旧阶段/执行人/完成判定链路已无数据支撑 |

**结论**：出问题的不是布局或视觉，而是工作台的**项目数据口径**仍停留在 11-02 旧方案（配置快照 + 历史完成阶段 + 执行人），以及几处**入口/开关**与现行路由不一致。

## 3. 调整范围与边界

**改动**（仅工作台模块自身链路，无数据库迁移、无新接口、不改 API 契约）：

- 后端：`DashboardReadService`（projects/search）、`GlobalSearchModules`（project 分支）、`DashboardLayoutService`（卡片白名单与上限）
- 前端：`views/dashboard/DashboardView.vue`、`components/QuickAccessBar.vue`、`utils/dashboard.js`
- 测试基建：`database/testing/dashboard_baseline.sql`、`DashboardReadIntegrationTest`、`frontend/tests/dashboard.test.mjs`
- 文档：本文件、设计文档、发布记录、旧文档状态标注、架构/部署/交接摘要

**明确不动**（避免影响无关模块）：`ProjectService` / `ProjectList.vue` / `ProjectDetail.vue`、知识星球、审批、公告、通知、供应商等业务模块；不新增/删除数据库表与列；不修改权限码、认证与行级授权规则（工作台只读聚合沿用现有 `AuthUser` 上下文）。

> 已知遗留（不在本次范围）：`ProjectService.appendRowLevelCondition` 仍为 `owner + executor`，与 `isProjectMember` 口径不一致；工作台按业务定义的成员口径展示，项目列表页仍按旧口径过滤。建议后续由项目模块专项统一，本次不改项目模块代码。

**保留的既有能力**：12 列可编辑布局与按账号持久化（含并发 revision/409）、快捷访问个性化与撤权过滤、Ctrl K 全局搜索与六类分组、搜索深链定位、60s 轮询/失焦补刷/状态栏四态、待我审批/退回待修改/我的收藏/最新公告/未读消息/我的项目面板、权限与 capabilities 过滤、旧 hashed 资产兜底。
