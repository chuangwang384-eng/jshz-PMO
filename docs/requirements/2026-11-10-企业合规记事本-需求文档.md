# 企业合规记事本需求文档

2026-11-10 · 业务口径已确认，待实施

## 目标与角色

企业合规要求作为按规范文档组织的记事本。知识星球维护人上传文件、核对从文件解析的重要条目并发布。员工收藏文档后集中阅读条目，可把适用条目推送到自己参与执行的项目。项目成员在项目详情基本信息的「合规要求注意事项」中处理这些待办。

| 角色 | 能力 |
| --- | --- |
| 知识星球维护人 | 上传、解析、编辑和核对候选、发布、按文档撤下已发布事项 |
| 员工 | 按收藏文档筛选已发布条目、个人隐藏或恢复、推送选中条目 |
| 项目参与人 | 向本人参与的项目推送并在项目详情处理待办 |

## 业务规则

1. **文档与发布。** 按当前规范文档名称分组，内部以文档 ID 区分同名文件。上传解析后展示候选及来源，维护人核对后发布。员工仅看到其有权访问且已收藏文档的已发布事项。维护端可以按来源文档筛选。
2. **清空已发布事项。** 每份文档独立提供清空按钮。确认窗显示文档名与全部已发布条目的实际数量，数量覆盖该文档完整数据。确认后撤下这批事项并保留历史。原件、解析候选、收藏、模板和已推送项目待办独立保留。可重新核对发布。
3. **个人记事本。** 按文档名分组并可筛选具体收藏文档，提供隐藏、查看隐藏项和恢复显示。隐藏只影响当前员工的记事本。取消收藏立即移除该文档的全部条目，项目待办照常保留。
4. **推送项目。** 支持从记事本单选或多选同一文档事项。项目必须是本人作为负责人、创建人、协助人或有效历史执行人参与的项目。首次推送自动绑定该文档，之后只允许同一文档，本期无换绑入口。重复推送同一条目跳过并展示结果。
5. **项目待办。** 项目基本信息增加「合规要求注意事项」，显示绑定文档名、已推送事项、来源引用及处理状态。推送冻结条目标题、内容、来源引用；来源更新、撤下、取消收藏和个人隐藏均不改变项目快照及处理状态。来源原件仍按其自身访问权限打开。
6. **移除旧入口及数据。** 移除企业合规要求的「我的执行」。按负责人确认清理旧执行清单及其任务、提醒和事件。这批数据属于测试数据，无需备份。文档、收藏、已发布事项、模板和其他模块的数据保留。

## 验收条件

| 编号 | 验收 |
| --- | --- |
| AC01 | 真实文件上传后可核对解析结果并发布，员工收藏后按文档名看到对应条目，筛选另一文档时不混入。 |
| AC02 | 两个员工分别收藏同一文档，甲隐藏后乙仍可见；甲可恢复。取消收藏后甲的文档分组和条目自动移除。 |
| AC03 | 文档 A 的清空确认显示准确全量计数。撤下 A 后其项目快照不变，文档 B、A 的候选和模板仍可用。 |
| AC04 | 首次推送绑定来源，重复推送不重复生成待办。并发推送不同文档最多只有一份绑定成功。 |
| AC05 | 四类参与关系可操作，非参与者、仅有全量查看权的人员、已撤销关系的用户均被拒绝。来源权限也必须通过。 |
| AC06 | 项目待办可处理，来源条目更新或撤下后仍显示推送时的内容和当前处理状态。 |
| AC07 | 旧入口移除，旧执行四类记录按批准范围清零，旧提醒停止发送，其他数据核对一致。 |
