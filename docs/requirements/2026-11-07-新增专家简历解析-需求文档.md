# 新增专家·简历解析需求

日期 2026-11-07 · 状态：已评审（Owner 决策确认） · 版本 v1.1

在「新增专家（需审批）」弹窗中增加简历解析：用户上传简历文件后，系统自动解析并填充姓名、单位、头像（及顺带命中的科室/职称/联系方式）到对应表单位置，**人工确认后方可提交**。

## 1. 可行性结论（Owner 2026-11-07 修正后）

**四类格式全部支持**。解析管线复用企业合规/知识星球板块的既有能力：

| 简历类型 | 文本来源 | 头像候选来源 |
| --- | --- | --- |
| PDF | 文本层（PDFBox）；扫描件回退本机 Tesseract OCR | 文档内嵌图片抽取 |
| Word（doc/docx） | POI 文本抽取 | 文档内嵌图片抽取 |
| PPT（ppt/pptx） | POI 文本抽取 | 图片形状抽取 |
| 图片（jpg/png） | 本机 Tesseract OCR（chi_sim+eng，已有能力） | 整图即证件照候选 |

## 2. 现状事实（已核实，2026-11-07）

- 系统 OCR = **本机 Tesseract**（`KnowledgeDocTextExtractor.ocrPage`，`TESSERACT_CMD`/`TESSDATA_DIR` 可配，chi_sim+eng，45s 超时，支持 TSV 坐标模式），已用于知识文档扫描页与企业合规表格识别；图片独立文件此前未入解析链路。
- PDF/Word/PPT/XLS 文本抽取能力齐备（PDFBox/POI）；PDFRenderer 可栅格化扫描页。
- 新增专家弹窗：三类照片上传 + 表单字段，走审批流（员工）/管理员直建。
- **项目内无 LLM 集成**（无 dashscope/openai/ollama 等任何模型服务接入）。

## 3. 需求范围

### P0 简历上传与解析入口

1. 新增专家弹窗顶部增加「上传简历自动解析」区域：支持 pdf/doc/docx/ppt/pptx/jpg/png，单文件 ≤20MB。
2. 上传后展示解析中状态；完成后空字段自动填充候选值，**不覆盖用户已输入内容**。
3. 解析失败（无文本/识别质量差/超时）明确提示原因，可「重新解析」，不阻塞手动填写。
4. 简历原文不落盘不留存，解析完即弃；审计只记动作与命中数，不记内容。

### P0 字段抽取（顺带命中即填）

姓名、单位、科室、职称、联系方式、头像，解析策略见设计文档 §2。Owner 明确：**不同简历格式差异大，需要语义理解**——本期采用多策略本地解析（标签行 + 上下文模式 + 词表），并预留语义理解增强接口（见决策点）；所有结果均为候选，人工确认。

### P0 头像候选（Owner 已确认策略）

抽取/识别出的图片按启发式（尺寸/比例/位置）产出**候选缩略图**（最多 3 张），图片简历则整图作为候选；用户点击「使用此照片」确认后才进入证件照上传位，走既有临时照片→审批归档链路。

### P1 解析反馈

1. 成功：提示"已解析 N 个字段，请核对后提交"。
2. 失败：明示原因（无有效文本/OCR 失败/超时/格式不支持），可重新解析。

## 4. 交互规则

| 场景 | 预期 |
| --- | --- |
| 上传不支持的格式 / 超限 | 即时拒绝并提示 |
| 解析中 | 显示解析中状态（OCR 场景可能 10~45s），表单可继续手动填写 |
| 解析完成 | 空字段填充候选值；头像候选区展示缩略图 |
| 解析结果质量差 | 字段缺失即留空，不猜测；用户手动补填 |
| 提交 | 走既有审批流，以用户确认后的表单为准 |

## 5. 已决策事项记录（2026-11-07 Owner 确认）

1. **OCR 能力**：项目已有本机 Tesseract（企业合规/知识星球链路），图片简历纳入本期支持。
2. **头像策略**：候选 + 用户确认。
3. **解析范围**：姓名/单位/头像 + 科室/职称/联系方式顺带命中即填。
4. **语义理解**：Owner 要求解析具备语义理解能力。现状项目无 LLM 集成——本期交付**多策略本地解析**（标签行 + 机构/科室/职称词表 + 上下文模式推断），并预留解析策略接口；**真语义理解（LLM 抽取）需 Owner 就以下二选一拍板后另立需求**：A 本地部署 LLM（如 Ollama+Qwen，数据不出内网，需 GPU/资源与部署窗口）；B 外部 LLM API（个人信息外发，需符合数据安全审批，不建议默认）。
