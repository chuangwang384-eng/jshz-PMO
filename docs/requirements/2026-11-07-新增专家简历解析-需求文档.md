# 新增专家·简历解析需求

日期 2026-11-07 · 状态：待评审

在「新增专家（需审批）」弹窗中增加简历解析：用户上传简历文件后，系统自动解析并填充姓名、单位、头像（及可扩展的科室/职称等字段）到对应表单位置，**人工确认后方可提交**。

## 1. 可行性结论（先回答"能做到吗"）

**能做到，但按文件类型分档**（依据 2026-11-07 对现有解析基础设施的核实）：

| 简历类型 | 可行性 | 依据 |
| --- | --- | --- |
| PDF | ✅ 完整支持 | PDFBox 已在依赖中，可抽文本层 + 抽取内嵌图片（头像候选） |
| Word（doc/docx） | ✅ 完整支持 | POI 已在依赖中，可抽文本 + 内嵌图片 |
| PPT | ✅ 支持 | POI XSLF 已在依赖中，可抽文本 + 图片形状 |
| 图片（jpg/png 扫描件/照片） | ⚠️ **本期不支持**，需 Owner 决策 | 系统**无在线 OCR 服务**（合规模块 OCR 模型路径此前记录"待就绪"）；引入 OCR 涉及个人信息处理方式，见 §5 决策点 |

- 字段抽取**不调用外部 AI 服务**，采用本地启发式解析（标签行匹配 + 正则），数据不出内网，符合 AGENTS.md 第 6 节。
- 解析结果一律作为**候选值**填入表单，用户核对/修改后走既有审批流提交；解析失败不阻塞手动填写。

## 2. 现状事实（已核实，2026-11-07）

- 新增专家弹窗（员工视角需审批）已有：三类照片上传（证件照/身份证正反面）+ 姓名/单位/科室/职称/联系方式等表单字段。
- `KnowledgeDocTextExtractor`：PDF/Word/PPT/XLS 文本抽取能力齐备；图片返回 null（无 OCR）。
- 照片存储走 `PhotoStorageService`（临时照片 → 审批通过归档）。
- 专家新增走审批流（`createExpertApprovalRequest`），照片为附件上传链路。

## 3. 需求范围

### P0 简历上传与解析入口

1. 新增专家弹窗顶部增加「上传简历解析」区域：支持 pdf/doc/docx/ppt/pptx，单文件 ≤20MB。
2. 上传后前端展示解析中状态（解析在后端异步/短超时同步均可，设计文档定）；完成后表单自动填充候选值，**已填字段被解析覆盖前需提示确认**（解析只填空字段，不覆盖用户已输入内容）。
3. 解析结果展示来源标记（如字段旁"来自简历"角标可选），用户可自由修改。
4. 支持不上传简历直接手动填写（现状保持）。

### P0 字段抽取

1. **姓名**：标签行匹配（姓名/Name）或首行人名启发式；2-20 汉字校验沿用现有规则。
2. **单位**：标签行匹配（单位/工作单位/任职单位/所在单位）。
3. **科室**：标签行匹配（科室/所在科室）。
4. **职称**：标签行匹配（职称/专业技术职务/职级）。
5. **联系方式**：手机号/邮箱正则提取（1 个候选，多个时取第一个）。
6. **头像**：抽取文档内嵌图片，按"位于文档前部 + 尺寸在头像常见范围（80~1500px）+ 非横幅/logo 特征"启发式选取**候选**，展示为"解析出的证件照候选"缩略图，用户点击确认后才进入证件照上传位（等同手动上传的临时照片链路）。

### P1 解析反馈与失败处理

1. 解析成功：提示"已解析 N 个字段，请核对后提交"。
2. 解析失败（无文本层/格式异常/超时）：明确提示原因，表单可继续手动填写；提供"重新解析"。
3. 每次解析记录审计日志（操作人、文件名、解析字段命中数），不留存简历原文（解析完成即弃，不落盘存储；仅内存/临时文件处理后删除）。

### P2 图片简历 OCR（暂缓，见决策点）

图片简历接入 OCR 解析。涉及内网 OCR 服务部署或外部 API 选型，需 Owner 决策后另立需求。

## 4. 交互规则

| 场景 | 预期 |
| --- | --- |
| 上传不支持的格式 | 即时拒绝并提示支持格式 |
| 上传超限文件 | 即时拒绝（≤20MB） |
| 解析中 | 上传区显示解析中状态，表单可继续手动填写 |
| 解析完成 | 空字段自动填充候选值；字段旁标注"来自简历" |
| 解析命中头像候选 | 展示候选缩略图 + 「使用此照片」按钮，确认后等同手动上传证件照 |
| 解析失败 | 红色提示原因 + 「重新解析」；不阻塞手动填写 |
| 用户先填后传 | 解析只填空字段，不覆盖已输入内容 |
| 提交 | 走既有审批流，提交内容以用户确认后的表单为准 |

## 5. 需要 Owner 决策的事项

1. **图片简历 OCR**：本期不支持图片简历（无 OCR 服务）。选项 A：暂缓（建议）；B：部署内网 OCR（如 PaddleOCR，需服务器资源与部署窗口）；C：调用外部 API（涉及专家个人信息外发，**不符合** AGENTS.md 数据不出内网要求，不建议）。
2. **头像候选策略**：启发式抽取文档图片可能命中非头像图（工作照/科室合影）；建议保留"候选 + 用户确认"交互（建议 A），还是严格要求仅抽取证件照样式照片（准确率会显著下降）？
3. **解析范围**：本期只填 姓名/单位/头像（Owner 原始诉求）+ 科室/职称/联系方式（顺带命中即填）？还是严格只填三项？
