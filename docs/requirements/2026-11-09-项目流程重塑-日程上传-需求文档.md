# 项目流程重塑：删除类型/执行人 + 第一步「日程上传」 需求文档

| 项 | 内容 |
|----|------|
| 需求人 | Owner（2026-11-09 对话提出，附示例日程 `10.23-日程.pptx`） |
| 需求概述 | 重塑项目逻辑：删除「项目类型」「执行人」概念并解绑流程；新建项目不可选阶段；总负责人推进项目进程；第一个阶段固定为「日程上传」，上传日程文件后系统解析参会专家姓名与会议角色 |
| 参考 | 专家库简历解析链路（Ollama 语义抽取 + 人工确认）；GitHub 参考项目在设计文档 §2 列出 |

## 1. 范围决策（Owner 已确认）

1. **阶段流程**：先只定第一步「日程上传」，后续阶段等 Owner 逐个提需求再加。
2. **解析结果入库**：人工确认页 + 自动匹配专家库（匹配到关联档案，匹配不到标记库外专家）。
3. **权限**：阶段推进 = 总负责人 + 创建人；预算/费用明文可见 = 总负责人 + 创建人 + 协助人（普通成员看脱敏）。
4. **旧表处理**：类型/阶段/执行人相关表**停用不删**（代码入口下线、页面移除、`type_id` 置 NULL 不删列），观察后下版删除。

## 2. 概念删除清单

| 删除概念 | 现状 | 新口径 |
|---------|------|--------|
| 项目类型 | `project.type_id` + `project_type`/`project_type_phase_rel` 配置，类型决定阶段流程 | 概念删除：新建/编辑/列表/详情/导出不再出现类型；`type_id` 列保留停用（全部置 NULL）；类型→阶段配置接口与前端配置页下线 |
| 执行人 | `project_executor` 子表，阶段推进授权=负责人+执行人，预算明文可见=负责人+执行人 | 概念删除：表单移除执行人多选；推进授权改为负责人+创建人；预算明文可见=负责人+创建人+协助人；`project_executor` 表停用保留 |
| 新建选阶段 | 表单「当前阶段」可选 | 移除该字段；新建项目自动落在第一阶段「日程上传」 |

「会议类型（线上/线下）`category`」**不是**项目类型，保留不变。

## 3. 第一阶段：日程上传

### 3.1 上传

- 新建项目保存后，详情页第一阶段卡片提示上传日程文件；任何格式（初版支持与简历解析相同的格式集：pdf/doc/docx/ppt/pptx/jpg/jpeg/png，20MB）。
- 文件存项目资料库（复用 `ProjectStorageService` 随机名策略），一个项目当前生效一份日程，重复上传覆盖并保留历史记录。
- 项目没有日程文件时，第一阶段标记「待上传」。

### 3.2 解析识别（AI 输出=候选，必须人工确认）

- 系统解析日程文件，提取**参会专家**的：姓名、会议角色。支持提取时间段/议题作为辅助信息展示。
- 会议角色四类：**大会主席 / 大会主持 / 大会讲者 / 讨论嘉宾**。
- 讨论嘉宾判定规则（Owner 口径）：**同一段落/议题下有多人发言的，全部判为讨论嘉宾**（如示例「大咖论道」5 人）；单人段按列头/文案判讲者、主持；「大会主席」「主席致辞」判大会主席。
- 同一人出现多个角色时按 主席 > 主持 > 讲者 > 讨论嘉宾 取最高一个（同页脚大会主席=致辞人只算主席）。
- 解析链路参考专家库简历解析：文本提取（PDFBox/POI，扫描件回退 OCR）→ Ollama 语义抽取 → 前端候选确认页。
- **解析失败/低置信**：允许人工对照原文手动录入/修正参会专家（姓名+角色），不允许静默丢弃。

### 3.3 确认页与专家库匹配

- 详情页日程卡内展示候选专家表：姓名 / 角色 / 时间段 / 议题 / 匹配到的专家档案（可搜索改绑）。
- 姓名与专家库**精确匹配**自动关联 `expert.id`；匹配不到标记「库外专家」，可一键按解析信息跳转新建专家档案（预填，沿用简历解析预填交互），或保持库外仅作项目内记录。
- 用户逐条确认（可改姓名/角色/绑定）后保存为项目**参会专家**正式记录；保存后如日程后续阶段需要可回溯原始解析 JSON。

## 4. 交互变化

- **新建项目表单**：移除「类型」「当前阶段」「执行人」三项；其余字段（1.0.37.23 已上线的字段集）不变。
- **列表**：移除类型列/类型筛选/执行人筛选；「当前阶段」列改为显示新阶段口径（第一阶段=日程上传，含解析状态：待上传/解析中/待确认/已完成）。
- **详情**：移除类型、执行人展示与阶段配置入口；新增「日程与参会专家」卡片（阶段一内容）。
- **阶段推进**：按钮权限改为负责人+创建人；本期只有一步，推进按钮隐藏（无下一步），权限改造先行落地为后续阶段做准备。

## 5. 接口变化概要

- 创建/编辑 body 不再接受 `typeId`/`executorIds`（传入忽略）；列表/详情/导出返回中移除类型与执行人字段。
- 下线（停用）：`/api/project/config/types`、`/config/types/{id}/phases`、`/config/phases` 等类型→阶段配置接口；执行人写入口。
- 新增：日程上传 / 解析 / 候选查询 / 确认保存 / 参会专家维护接口（详见设计文档 §5）。

## 6. 不在本次范围

- 后续阶段（第二阶段及以后）的定义与推进流程。
- 类型/阶段/执行人旧表的物理删除（下版）。
- 日程解析中的时间地点结构化入日程表、专家档期冲突检测、自动发邀约。

## 7. 验收要点

1. 新建项目表单无类型/阶段/执行人；保存后详情页第一阶段为「日程上传·待上传」。
2. 用示例日程（`10.23-日程.pptx`）实测解析：成慧君=大会主席、马媛=大会主持、谭波/肖艳=大会讲者、于晓/侯艺芳/杨柳/罗辉/崔庆丽=讨论嘉宾，人工确认页可修改后保存。
3. 确认保存后参会专家落地项目；姓名匹配专家库自动关联档案，库外专家可跳转建档预填。
4. 阶段推进权限：负责人/创建人可推进（本期无下一步则隐藏），协助人与普通成员不可；预算明文对协助人可见、普通成员脱敏。
5. 列表/详情/导出无类型与执行人残留；旧配置接口返回 404/410 或前端不可达；无孤儿报错。

## 9. 追加需求（Owner 2026-11-09 第二轮）

1. **阶段化界面（只看当前阶段该看的）**：项目处于「日程上传」阶段时，详情页仅展示 项目生命周期 / 阶段任务·日程上传 / 阶段资料·日程上传 / 参会专家（右栏仅保留「当前待办」）；预算指标、基本信息卡、备注、专家名单、供应商、合同、时间线、项目成员、相关附件、项目动态**全部隐藏**，待项目推进到对应阶段后再展示。
2. **上传即入资料 + 自动解析**：在阶段资料区上传日程后，系统自动把文件挂载到当前阶段资料（同一份文件不重复落盘），并**自动触发解析**；解析失败不阻断上传，仅标记失败供重新上传或手动补录（原来需再点「开始解析」）。
