# 企业合规模板可视化维护需求文档 V1.0

日期：2026-11-05；任务：COMPLIANCE-VISUAL-20261105。状态：需求已确认，文档待审阅；未施工、未迁移、未发布。

## 1. 目标与确认决策
维护人无需理解草稿、修订和版本编号，选中文档即可整理可供员工使用的执行清单。

| 规则 | 已确认行为 |
| --- | --- |
| 模板对应关系 | 一份企业合规规范文档对应一个当前模板 |
| 编辑形态 | 阶段分组＋事项卡片，拖动排序，点击编辑 |
| 编辑保存 | 未点击生效时自动保留编辑内容，跨会话可继续 |
| 对员工生效 | 仅点击“保存并生效”后统一生效 |
| 已有执行 | 模板更新只影响新建清单，已有清单保持原内容与个人进度 |
| 存量多个模板 | 维护人首次进入选择保留哪个，其余归入历史，不删除 |

范围仅企业合规要求的模板维护及员工新建清单入口适配。原有执行、提醒、个人权限及原文访问边界沿用。不扩展协会分类、微盘同步、流程连线、自动决策或自动发布。

## 2. 页面与主流程
保持现有企业合规入口和模板维护页签。移除新建草稿、继续编辑草稿、已发布版本、复制为新修订、输入版本编号等操作。后台保留必要历史记录，业务页面不要求维护人操作这些概念。

页面顶部为文档选择、模板名称、保存状态、“从原文提取”“预览清单”“保存并生效”。左侧显示阶段目录和事项数量；中间为可拖动的阶段及事项卡片；右侧按需展开事项属性或原文对照。窄屏使用抽屉，不能挤压成不可操作的多栏。

1. 选择文档，直接打开其已保留的编辑内容；没有模板时显示“添加事项”与“从原文提取”。
2. 添加阶段或事项，拖动调整顺序；选中事项显示可编辑详情。
3. 系统自动保存，显示“保存中／已保存，尚未生效／保存失败，重试”；员工仍使用上次生效内容。
4. 预览与员工实际看到的结构一致；确认完整后点击“保存并生效”。
5. 保存成功提示“已生效，仅用于之后新建的清单”；同时显示生效时间与维护人。

首次尚未生效时明确“员工暂不可使用”。无变化时生效按钮禁用；生效过程禁用重复点击。保存失败不可显示已保存或已生效。

## 3. 阶段与事项编辑
阶段支持新增、改名、折叠、移动；事项支持新增、复制、删除、同阶段排序及跨阶段移动。删除含事项的阶段必须明确选择移动事项或一并删除；提供当前编辑会话的撤销入口。所有拖动提供上移、下移、移动到阶段的按钮替代。

事项卡片默认显示标题、要求摘要、填写方式及原文引用状态。默认编辑字段为事项名称和操作要求；更多设置展开所需材料、完成标准、规范时限、填写方式、完成前必填。填写方式沿用确认事项、文本、单选、多选；选择类型才显示选项配置。个人到期日、优先级、进度、个人备注不属于模板字段。

原文引用以页码/章节和摘录展示，可点击定位原件；维护人不编辑JSON。人工新增事项可不关联原文；自动提取事项显示“待核对”，核对后标记“已核对”，修改提取文字或替换引用后重新待核对。不能把OCR成功当作内容完整。

## 4. 文件提取与原文核对
提取仅写入编辑内容，不直接生效。不覆盖维护人已经整理的内容：展示候选列表，可逐项选择加入、忽略或合并替换指定事项，替换前展示差异。没有现有内容时可批量加入；加入后保留稳定来源锚点和原文摘录。

扫描页、OCR失败、部分成功和候选截断必须显示具体页码/范围及补充处理建议。重新提取不得自动恢复已删除事项或重复加入相同来源候选。提取中可查看页面，避免重复提交；失败保留既有编辑内容。

保存并生效前检查：模板名称、至少一个有效事项、事项标题、选择项完整性、必填规则和结构合法性。自动提取事项尚未核对时阻止生效并定位；存在无法提取页时须维护人明确确认已人工核对并补齐，保留确认记录。人工新增内容不需要伪造来源。

## 5. 自动保存、多人编辑及生效
自动保存仅保存维护内容，不改变员工当前可用模板。成功保存的数据跨设备/重新登录可继续；网络断开时本次未保存内容留在当前页面，离开前提示风险。快速输入合并保存；切换文档先处理未保存内容，不允许旧请求覆盖新文档。

多人共用同一份编辑内容。后端乐观锁拒绝覆盖他人的新修改；冲突时保留本机未保存内容，提示刷新对比，不静默覆盖、不把冲突当成功。自动保存与生效必须按同一内容序号确认，不能让未保存的最后一次输入遗漏。生效失败时旧可用内容继续有效。

## 6. 员工入口与历史保护
员工选择规范文档后使用唯一当前生效模板，不再选择多个修订或版本。无可用模板时说明原因。员工新建执行时固定模板内容、来源依据和结构，之后模板改名、删项、排序或再次生效都不得修改该执行的内容、答案、计划日期、进度或提醒。

历史保护不豁免权限：来源被撤权、移出分类或永久删除时仍执行现有授权规则，不能通过旧快照扩大访问。来源下架后能否继续读取既有清单沿用原业务规则。

存量收口由维护人首次进入完成：展示全部候选及状态、事项数、维护人、更新时间和预览，选择一个作为保留内容。其余放入只读历史，员工已有引用不变。多个候选时不自动选择最近者；尚未选择期间员工当前可用模板入口保持既有行为，并提示待维护人整理。选择已生效候选时保留其可用内容；选择未生效内容时不可自动对员工生效，须点击保存并生效。选择应可审计，重复提交不能重复归档。

## 7. 权限和验收
沿用文档上传者或knowledge:maintain编辑、knowledge:maintain生效；没有生效权限的上传者显示“编辑已保存，需维护人生效”。存量收口仅维护人执行。前端显隐不替代后端授权；原文预览与引用查询检查来源权限。

| 验收场景 | 通过标准 |
| --- | --- |
| 简单维护 | 选文档即可编辑，页面无草稿/修订/版本编号操作 |
| 排序 | 拖动及按钮操作结果一致，保存重开顺序不变 |
| 自动保留 | 编辑后重登可继续，员工仍见原生效内容 |
| 一次生效 | 最后输入已保存并整体生效，失败不改变旧内容 |
| 历史执行 | 更新/删项后原清单内容和个人状态完全不变 |
| 多人冲突 | 后保存者收到冲突，本地输入保留，无静默覆盖 |
| 提取核对 | 引用可定位、扫描漏页可见、未核对不能生效 |
| 存量收口 | 人工选择、其余只读保留、已有引用不变、重复提交幂等 |
| 权限 | 无权编辑、生效、查看来源均在后端拒绝 |
