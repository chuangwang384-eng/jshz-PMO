# 个人工作台信息密度优化需求

日期 2026-11-07 · 状态：待评审

适用于 [个人工作台产品需求](2026-11-02-个人工作台-需求文档.md) 与 [可编辑布局专项](2026-11-06-个人工作台可编辑布局-需求文档.md) 的信息密度与视觉专项。本期只调整工作台的**展示层**，不改变现有的布局编辑逻辑、卡片目录、权限过滤和持久化结构。

## 1. 背景与问题

1.0.34.1 上线后按负责人反馈，工作台具备模块化结构与信息分区，但以"高效、克制、高信息密度"的标准衡量存在以下问题（均已对照 2026-11-07 线上截图与代码核实）：

| # | 问题 | 现状事实 | 来源 |
| --- | --- | --- | --- |
| 1 | 空面板占据大量纯白空白 | 「待我审批」「退回待修改」等面板数据为 0 时仍按已保存宽高占满网格，仅显示一行"暂无…"；有内容的「我的项目」被挤在右侧 | 线上截图 2026-11-07 |
| 2 | 头部垂直空间过大 | "问候语+副标题+日期+刷新按钮+搜索+快捷入口"纵向堆叠，首屏露出核心卡片过少 | 线上截图 |
| 3 | KPI 数字卡片视觉噪音 | 四张统计卡占整行，非零状态背景色（浅红/浅黄）饱和度偏高；数字为 0 时与有内容卡片视觉权重相同 | 线上截图 |
| 4 | 列表信息未结构化 | 「我的项目」每行为连续一行文字（阶段 · 负责人 · 结束日期 · 最近推进），无法竖向对齐快速扫读 | DashboardView.vue 模板 |
| 5 | 原始 ISO 时间戳直接展示 | 「最近推进」渲染后端原文 `2026-11-02T15:51:07`，未经格式化 | DashboardView.vue 渲染 `lastPhaseChange.time` 原文 |
| 6 | 缺少内联操作 | 列表行只有「详情 →」，无快捷操作 | 线上截图 |
| 7 | 视觉层级 | 问候语字号最大，抢了业务数据的焦点 | 线上截图 |

## 2. 目标与非目标

**目标**：把空间让给有数据的模块，降低空状态与装饰元素的视觉噪音，让列表可扫读、时间可读、重要风险一眼可见。

**非目标（本期明确不做）**：
- 不改变布局编辑与展示逻辑：12 列网格、编辑模式（拖动/缩放/保存/取消/恢复默认）、`CARD_CATALOG`、每用户持久化（`user_dashboard_layout`）、权限与能力过滤全部保持现状。
- 不改任何后端接口契约与数据结构；所有格式化在前端完成。
- 不改造左侧边栏（系统级导航已在侧边栏，需求建议 5A 现状已满足）。
- 不新增或删除任何卡片类型，不改变默认权限规则。

## 3. 需求范围（按优先级）

### P0 首屏效率

1. **空状态自动折叠**：浏览模式下，列表类面板（待我审批/退回待修改/我的收藏/最新公告/未读消息）数据为空时，卡片收缩为一条细状态条（如"暂无待审批事项"），不再保留大面积空白；有数据后自动恢复完整面板。空状态条上保留「刷新」与「查看全部」入口。
2. **时间格式化**：所有列表中的时间戳统一格式化为友好格式（日期类 `M月D日`；时刻类 `M月D日 HH:mm`；起止日期保留 `YYYY-MM-DD`）。不允许出现原始 ISO 字符串。
3. **头部压缩**：问候区高度压缩（字号下调、与副标题平齐），日期与「刷新工作台」收至问候区右侧同一行；全局搜索与快捷入口保持现有位置与行为。
4. **KPI 卡降噪**：统计卡改为"标题 + 数字"单行紧凑形态，删除与标题重复的副标题；数值为 0 时使用极淡样式，仅非 0 且异常（如已逾期 > 0）保留高亮色。

### P1 可读性与视觉

5. **我的项目列表结构化**：行内改为对齐网格——项目名（含风险标签）为主列，阶段/负责人/结束日期/最近推进为对齐的属性列，不再用"·"串联长句。
6. **风险视觉强化**：风险标签沿用现有 `warning` 字段映射（逾期=danger、临期=warning），逾期行可附加行级强调（如 2px 顶边线），不新增颜色语义。
7. **颜色降噪**：卡片浅红/浅黄背景改为更淡的底色或仅顶部彩色边线区分状态；页面内统一通过 CSS 变量管理。

### P2 操作效率（需负责人逐项决策后才可纳入本期）

8. **内联审批操作**：在「待我审批」行内提供同意/驳回快捷操作。**前置依赖**：[审批人快速审批需求](2026-11-02-审批人快速审批-需求文档.md) 的后端接口与审计；内联操作必须复用同一接口与权限校验，前端不得自行拼装。未确认前本期不做。
9. **全局搜索升级为命令面板（Ctrl+K）**：在现有搜索基础上增加键盘唤起与"跳转到模块"候选。不移动搜索框位置、不影响布局编辑。未确认前本期不做。

## 4. 交互规则

| 场景 | 预期 |
| --- | --- |
| 空面板浏览 | 显示细状态条（图标/文案/刷新/查看全部），卡片占位收缩；布局数据不变化 |
| 空面板出现数据 | 自动恢复完整面板与列表行 |
| 编辑模式 | 全部卡片按已保存宽高完整显示（含空面板），拖动/缩放/保存行为与现状一致 |
| 窄屏（<900px） | 沿用现状单列；折叠条与列表行自适应 |
| 时间展示 | 列表时刻 `M月D日 HH:mm`；项目结束日期 `YYYY-MM-DD`；超过当年显示年份 |
| 权限 | 折叠条、按钮、入口均沿用卡片现有 `perm`/`cap` 规则，无新增权限 |

## 5. 验收条件

1. 空数据账号登录工作台：待办类面板为细状态条，首屏可见「我的项目」「最新公告」等有内容模块；无渲染崩溃、无横向滚动。
2. 同一账号保存过自定义布局后升级：布局数据完好，编辑模式与升级前行为一致；空面板在编辑模式仍完整显示。
3. 页面中所有时间均为格式化文本，grep 模板无裸 `T` 分隔 ISO 输出（`2026-10-28 02T15:51:07` 类问题不复现）。
4. KPI 卡：0 值无重色；逾期 > 0 时保持高亮；卡片不含重复副标题。
5. 「我的项目」行内属性竖向对齐；逾期/临期标签颜色正确；无权限卡片不出现在任何形态（含折叠条）。
6. 真实 Edge + 构建产物验证：登录首屏、返回工作台、刷新、拖拽编辑保存闭环回归通过。

## 6. 需要负责人决策的事项

1. P2-8 内联审批操作是否纳入本期（涉及后端接口复用与审计要求）。
2. P2-9 Ctrl+K 命令面板是否纳入本期。
3. 空面板折叠是否需要"恢复完整卡片"的手动开关（建议：不需要，有数据自动展开）。
