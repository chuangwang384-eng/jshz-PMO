## 一、缺陷修复（Bug Fixes）

### P1 知识星球分类子页列表不过滤（子页仍显示全部分类文档）

- **现象**：进入分类子页（如 `/knowledge-planet/meeting-execution`）时，列表仍显示全部分类文档，未按当前分类过滤。
- **根因**：`views/KnowledgePlanetHome.vue`（知识星球父路由组件）模板内无 `<router-view />`，导致四个分类子路由（`MeetingExecution / AssociationCompliance / EnterpriseCompliance / CustomerPreferences`）在父页内部无法渲染，页面实际停留在父页"上传中心 + 全分类总览"，因此看起来"子页仍显示全部分类"。前端 `KnowledgeDocList.vue` 的 `category` 过滤参数与后端 `GET /api/knowledge/docs` 的 `category` 可选过滤逻辑本身均正常。
- **修复**：`KnowledgePlanetHome.vue` 增加 `<router-view />` 用于渲染子路由；通过 `route.name === 'knowledge-planet'` 的 `isRootPage` 判断，仅父路由显示"上传中心 + 全分类总览"，分类子路由只渲染本分类列表。双账号（超管 / 员工）均可正常使用：后端按 `category` 过滤 + 按权限过滤 `status`（超管见上架+下架，员工仅见上架）逻辑不变。
- **影响范围**：仅前端 `views/KnowledgePlanetHome.vue`；后端接口、路由定义、子页组件均未改动。

### P2 角色调整通知点击不跳转（role_changed 通知点击后 URL 不变）

- **现象**：`role_changed` 类型通知点击后 URL 不变，未跳转到对应页面。
- **根因**：后端 `UserService.assignRoles` 埋点 `role_changed` 通知时 `jump_path` 传入 `null`；前端 `NotificationBell.vue` 点击逻辑仅在 `jumpPath` 存在时才 `router.push`，故点击无跳转。
- **修复**：`UserService.assignRoles` 的 `role_changed` 通知 `jump_path` 由 `null` 改为 `/profile`（个人中心），与设计文档/交接文档约定一致。
- **其他类型跳转检查**：`approval_result → /profile/my-approvals?status=1|2`、`approval_todo → /approval/manage?status=0`、`password_reset → /profile/change-password`、`doc_off_shelf / doc_deleted → /knowledge-planet` 埋点均带有正确 `jump_path`，前端 `NotificationBell.vue` 通用 `router.push(jump_path)` 逻辑正常，不受影响。
- **影响范围**：仅后端 `service/UserService.java`（第 5 参由 `null` 改为 `"/profile"`）；前端通知跳转逻辑无需改动。
