# 发布与回滚记录：1.0.108 串场照片池化与专家资料全局化（photo-pool）

- 发布时间：2026-11-21 12:17–12:22（`release-full.ps1` 编排一次成功，state=SUCCESS/verified）
- ReleaseId：`1.0.108-photo-pool`

## 背景（用户反馈四问题）

1. 「串场文件过大，请压缩图片」：同一位专家出现在多个环节时，其照片 dataURL 在每个出场页/简历页/讨论墙**重复嵌入**（重复 5-6 次 × 200-400KB），deck 超 10MB 上限（`MAX_DECK_SIZE`）被拒。
2. 专家信息重复编辑：同一专家在多个环节是独立资料对象，改一处其他环节不联动。
3. 裁剪圆框默认过小，部分专家只能圈到脸、肩膀露不出。
4. 图片过大的影响：超限即保存/预览/归档被拒；未超限时大稿加载/翻页变慢。

## 内容

- **照片池化**：`Deck` 新增 `photos` 照片池；向导构建时同一张照片全稿只存一份，页面内以 `ph:{序号}` 引用；后端 `resolvePhotos` 渲染时解析为实际 dataURL。deck/HTML 中照片体积从「重复 ×N」降为「唯一 ×1」。旧草稿（image 直接存 dataURL、无 photos）完全兼容。
- **专家资料全局化**：向导引入专家资料池——同一专家（按专家库 ID，无 ID 按姓名）共享同一份资料对象（姓名/单位/职称/头像/简介），**任一环节编辑全局联动**；「大会角色」按环节独立（`roleBySegment`，同一专家在 A 环节是主席、B 环节可以是主讲）。
- **裁剪圆框调大**：默认框 46%→62%；人脸识别圆框直径系数 0.62→0.95（≈脸框长边 1.9 倍，覆盖发型与肩颈），识别圆心略下移露肩。
- **裁剪输出 WebP**：400×400 圆形透明图优先 WebP（同质量体积约 PNG 的 1/5，透明保留），不支持 WebP 的环境回退 PNG；后端 IMAGE 白名单本就含 WebP。

## 效果

以 12 位专家、11 个讨论墙的会议为例：照片总量从约 6MB（重复嵌入）降至约 1-1.5MB（池化 + WebP），远低于 10MB 上限；deck JSON 存库体积同步下降（`project_stage_form.form_data` 为 MySQL JSON 列，非瓶颈）。
