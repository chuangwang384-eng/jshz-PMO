# 工作台二维布局部署与验收

状态为本地施工，生产未发布。

## 接口和数据

GET /api/dashboard/layout/v2 返回 {revision,items}。items 为 null 表示采用默认布局，空数组表示用户主动清空。PUT 同一路径提交 {revision,items}。坐标 x/y 从 0 开始，按 12 列、200 行校验，宽高为正整数。最小宽度 3 列，普通卡最小高 2 行，面板最小高 4 行，最大高 24 行。重复卡片、重叠和越界拒绝。认证账号决定查询与写入范围，卡片权限使用现有模块和审批权限规则。响应沿用系统 API 包装，版本冲突使用业务码 409。

user_dashboard_layout 新增可空 layout_v2 JSON。内容包含 schemaVersion、writeId、legacyHash 和 items。旧 layout 列继续供已有 API 读写。新保存锁定账号行，比较当前 revision，在同一事务写入二维布局和旧格式投影。旧写入若改变投影，下一次读取采用旧格式并生成新的 revision。已有布局只在用户保存后写入新列。

## 执行和回退

1. 核对目标数据库元数据及备份。先有 20261105_user_dashboard_layout.sql，再执行可重复的 20261106_dashboard_layout_v2.sql。迁移不改已有行内容。验证 layout_v2 为可空 JSON。
2. 在隔离目录构建后端和前端。构建时设置 VITE_DASHBOARD_LAYOUT_V2=true 打开新编辑器。未设置时使用原布局 API 和静态浏览。GridStack 14.1.0 只在首次点编辑时加载。该开关在构建时固化，灰度和回退通过切换已验证的前端制品进行。
3. 在获批后部署支持新接口的后端，再切换前端。确认登录、工作台和项目入口，检查几何、保存结果和应用错误。需回退时切回无工作台崩溃记录的已验证前端制品，保留两个布局列，原布局投影继续可读。回退版只能展示顺序和列宽。
4. 复跑脚本为 pwsh -NoProfile -File scripts/run-compliance-v4-e2e.ps1 -DashboardLayout。使用隔离 MySQL 13316、Spring 18086 和 Edge 访问本地 Vite Preview 5173。脚本创建临时账号和凭据，使用独立输出目录打包，退出后清理进程。生产服务和制品目录禁止用于构建或测试。
