## 实现与权限矩阵

- 前端 `/dashboard` 为登录默认入口，合法内站redirect优先；保留原业务路由、强制改密及后端认证规则。非法外站/反斜杠/控制字符目标被拒绝。
- 首屏是待我审批、退回待修改及项目风险；本人申请进度独立，消息不与业务重复加总；项目后接收藏、公告、消息。
- 本人项目负责人OR执行人去重，管理员默认仍是本人项目；排除取消/删除/权威已完成，UNKNOWN单列。北京时间今天不逾期，第7天包含、第8天不预警。
- 聚合查询使用最小DTO；全局搜索和完整结果列表共用 `ModuleSearcher.QuerySpec` 注册规格。复用PermissionService接口规则，显式保留各模块资源过滤；原模块权限变化必须同步查询规格及测试。

| 数据 | 后端范围 |
| --- | --- |
| 本人申请 | applicant_id/申请人本人，退回项与等待他人审批分开 |
| 待我审批 | approval:audit + 原待审列表快照可见性 + 当前指派/或签可操作性交集 |

| 专家/客户/供应商 | 当前模块查看范围，客户排除软删；搜索仅必要标题/辅助字段，不传身份证等 |

## API 契约

均使用现有ApiResponse包装，业务错误code与HTTP状态沿用统一异常处理；未登录由既有安全链拒绝。用户身份从认证上下文取得，不接受客户端指定身份扩大范围。

| 接口 | 参数 / 返回 |
| --- | --- |
| GET /api/dashboard/overview | sections可选无重复枚举；返回generatedAt/businessDate/capabilities/sections。每卡片success/empty/error、updatedAt、data；项目与风险同批数据投影 |
| GET /api/search/global | keyword为trim后1–100 Unicode字符；modules可选六类子集；固定顺序分组、每组≤5、total/hasMore/items/allTarget |
| GET /api/search/global/module/{module} | 相同keyword、过滤与排序，page默认1/上限100000，size默认20/上限100 |
| GET /api/dashboard/focus/{kind}/{id} | application/approval/notification/knowledge/announcement；授权单条定位，不受当前分页影响；非法400、无权/失效403或404 |
| GET /api/dashboard/my-projects | page默认1、上限100000，每页20；与本人卡片相同筛选与排序 |
| GET /api/dashboard/my-approvals | 同上分页；与待我审批卡片相同可操作性规则 |
| POST /api/approval/requests/{id}/resubmit | 新增可选body `{changes:{文本字段:新值},reason?:string}`；无body旧调用兼容 |

搜索排序：标题精确→前缀→包含→其他字段，更新时间/ID倒序。SQL参数化、LIKE使用 `!` 转义，使%、_、反斜杠为普通文本。项目当前模型没有独立编号列，以项目数字ID参与编号搜索；客户辅助信息为工作单位；知识文件不可提取正文时仅元数据，不引入OCR。

搜索失败分组的total/hasMore为null，绝非0；无权分组不返回。卡片错误data为null，有独立重试；多个卡片重试按卡片版本号合并，不互相取消。全量刷新与离页取消旧请求。搜索输入法组合期间不请求，300ms防抖，序号兜底忽略旧响应；键盘和清空均覆盖自动化测试。

重新提交：仍仅申请人本人且status=4，文本白名单、创建必填、敏感格式复用原校验；单字段≤5000、原因≤1000。照片保留原申请；合同仅可补身份证/银行卡。敏感字段空输入保留原值，不用脱敏旧值重建申请。变更、4→0条件更新、清理旧审批指派/意见、审批快照、RESUBMIT记录及通知同事务，重复或竞争请求拒绝。专家权威档案仅审批通过时修改。

## 资源、超时与部署影响

- 有界执行器8线程、128排队位；原32位在隔离20并发100请求时产生11个MODULE_BUSY卡片错误，因此调为128。仍保留饱和拒绝、取消和关闭回收。
- overview模块预算1200ms、请求上限1500ms；search模块预算1500ms、请求上限2000ms；JDBC每条查询1秒超时。前端分别3秒/4秒。数据库超时可能返回MODULE_UNAVAILABLE，Future预算超时为MODULE_TIMEOUT，饱和为MODULE_BUSY；均展示重试，不暴露SQL或异常内容。
- 日志只记录模块、错误类别、耗时，不记搜索词、正文或凭证。首期无业务缓存、外部统计SDK、外部模型。
- 没有新生产环境变量、端口、依赖、权限码或业务数据库迁移。未改变CORS配置；隔离前端使用现有允许来源 `http://localhost:5173`，测试后端127.0.0.1:18085、MySQL127.0.0.1:13319，均非生产端口。
- 发布前必须核实目标库是否已有有效项目配置快照及对应版本，不得将测试schema当作迁移，也不得自动执行项目配置历史迁移。正式发布仍须单独批准，按仓库蓝绿/原子前端流程执行。
- 回滚需匹配的原前后端制品并恢复旧默认入口；本功能无新增业务表，可回退代码；已重新提交的申请及审计记录不得因回滚删除。当前本地撤销仅针对本轮文件，不reset他人改动。

- 反斜杠用例最初因测试fixture的SQL字面转义导致1项失败，改为参数化插入后通过，未弱化断言。

- 首次普通前端build在transform阶段终止，改用隔离outDir；生产dist/index.html核对仍为2026-11-04 14:09:44。
- 隔离JAR运行时曾因Windows文件锁打包失败；仅停止本次隔离进程后重打包通过，未停止生产。
- 隔离端口15185的浏览器登录被现有CORS拒绝；改用已允许的localhost:5173，不放宽CORS。
