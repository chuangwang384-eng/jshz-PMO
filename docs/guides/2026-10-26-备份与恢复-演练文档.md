## 一、备份产物说明

每次备份生成 `<LOCAL_PATH>`，包含：

| 产物 | 内容 | 说明 |
| --- | --- | --- |
| `expert_system_*.sql` | 数据库全量导出（mysqldump，--single-transaction --routines --triggers --hex-blob，utf8mb4） | 不带 CREATE DATABASE/USE，导入时指定目标库 |
| `照片库.zip` | `<LOCAL_PATH>` 全目录（含 `原图备份` 等子目录） | 压缩归档 |
| `照片库_tmp.zip` | `<LOCAL_PATH>`（审批中临时照片） | 目录缺失/为空时跳过（非致命） |
| `知识文档库.zip` | `<LOCAL_PATH>` 全目录（含 `_preview`） | 压缩归档 |
| `*.sha256` | 每产物一份 SHA256 校验（sha256sum 同格式） | 恢复/演练前必须校验 |
| `manifest.txt` | 产物清单（文件名/大小/SHA256/耗时） | 汇总索引 |

保留策略：默认保留最近 **5** 份，超出的最旧 `backup_*` 目录**移入回收站**（`-Keep` 可调；仅清理时间戳备份目录，不碰其他路径）。运行日志：`logs\backup.log`。

凭据：优先取环境变量 `MYSQL_PASSWORD`；未设置时从本地 `start-backend.bat`（gitignored）运行时解析，脚本与日志均不落盘明文。

## 二、日常操作

```powershell
# 一键备份（默认模式）
powershell -NoProfile -ExecutionPolicy Bypass -File <LOCAL_PATH>

# 校验最新备份（SHA256 + zip 全量读取；-From 可指定目录）
powershell -NoProfile -ExecutionPolicy Bypass -File <LOCAL_PATH> -Mode Verify

# 自动恢复演练（建测试库→导入→对比表/行数→结论追加到本文档）
powershell -NoProfile -ExecutionPolicy Bypass -File <LOCAL_PATH> -Mode Drill
```

计划任务 `jshzPMOBackupWeekly`：每周日 02:00 以当前用户静默执行 Backup 模式（`schtasks /Query /TN jshzPMOBackupWeekly /V` 查看状态与最近结果）。

## 三、手动恢复步骤（生产灾难恢复，须负责人批准）

> 前置：确认恢复范围与时间点（选哪份 backup_*）；恢复会覆盖目标库当前数据，属高风险操作（AGENTS.md §14）。

1. **选定并校验备份**：
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File <LOCAL_PATH> -Mode Verify -From "<LOCAL_PATH>"
   ```
   校验不通过**禁止使用**该备份。
2. **停写入口**：停止后端服务 `ExpertSystemBackend`（需管理员），避免恢复期间产生新写入。
3. **恢复数据库**（示例恢复到生产库 expert_system；如需先演练见第四节）：
   ```powershell
   # 建议先重命名当前库留底（由 DBA 决定），再导入：
   & "<LOCAL_PATH> Files\MySQL\MySQL Server 26.7\bin\mysql.exe" -h 127.0.0.1 -P 3306 -u root --default-character-set=utf8mb4 expert_system `
     -e "source <LOCAL_PATH>"
   ```
4. **恢复文件库**：解压 `照片库.zip`、`知识文档库.zip`（及需要的 `照片库_tmp.zip`）到 `<LOCAL_PATH>` 对应目录（先移走现存目录留底）：
   ```powershell
   Expand-Archive -Path "<LOCAL_PATH>" -DestinationPath "<LOCAL_PATH>" -Force
   Expand-Archive -Path "<LOCAL_PATH>" -DestinationPath "<LOCAL_PATH>" -Force
   ```
5. **重启并验证**：启动 `ExpertSystemBackend` → `/health` 探针 → 登录、专家列表行数、知识星球列表、审批单抽查与备份时点一致。
6. **留档**：在本文件记录恢复事件（时间、备份版本、执行人、验证结果）。
