## 2. 推送前置安全检查清单

在推送任何分支前，必须完成以下安全检查，防止敏感信息泄露到远程仓库。

### 2.1 凭据必须走环境变量

`application.yml` 中的数据库口令与 JWT 密钥必须通过环境变量注入，配置中只保留 `${...}` 占位符：

```yaml
spring:
  datasource:
    password: ${MYSQL_PASSWORD}
jwt:
  secret: ${JWT_SECRET}
```

> 环境变量名：`MYSQL_PASSWORD`、`JWT_SECRET`。禁止在 `application.yml` 中提交真实明文凭据。

### 2.2 启动脚本只跟踪占位模板

- `start-backend.bat`（含真实凭据）**不得**加入 Git 跟踪；
- 仅跟踪 `start-backend.example.bat` 占位模板。

### 2.3 推送前敏感文件扫描

每次推送前执行以下命令，检查是否有敏感文件被跟踪：

```bash
git ls-files | findstr /i "password secret key token .env application.yml start-backend"
```

或逐项查看完整跟踪清单：

```bash
git ls-files
```

- 若发现 `application.yml`、`start-backend.bat`、`.env`、密钥文件等出现在列表中，**立即停止推送**，按第 3 节解除跟踪后再推送。

## 3. .gitignore 处理

### 3.1 需要忽略的目录

以下目录/文件必须加入 `.gitignore`：

```gitignore
frontend/releases/
.zcode/
供应商图库/
```

### 3.2 保留占位文件

`frontend/releases/.gitkeep` 必须保留跟踪（用于在仓库中维持该目录结构）。

### 3.3 解除已跟踪构建产物

若构建产物已被跟踪（例如 `frontend/releases` 下的文件曾提交过），按以下步骤解除跟踪并重新纳入占位文件：

```bash
# 1. 解除 frontend/releases 目录的跟踪（文件仍保留在本地磁盘）
git rm -r --cached frontend/releases

# 2. 强制重新添加占位文件
git add -f frontend/releases/.gitkeep

# 3. 提交本次变更
git commit -m "chore: untrack frontend releases and keep .gitkeep placeholder"
```

> 说明：`git rm -r --cached` 只解除版本跟踪，不会删除本地文件。

## 4. 分支同步方法

清理提交（如 .gitignore 变更、解除跟踪等）需要同步到全部 6 个分支时，按以下方法逐分支应用。

### 4.1 方法一：cherry-pick（推荐，注意空变更）

```bash
git cherry-pick <commit-hash>
```

> ⚠️ 踩坑提醒：若某分支已包含相同变更，`cherry-pick` 可能因"空变更"（empty commit）挂起。此时先执行 `git cherry-pick --abort` 放弃，再改用 4.2 的手动应用方式。

### 4.2 方法二：checkout 文件 + commit（空变更时使用）

当 `cherry-pick` 因空变更失败时，改为手动应用指定提交对特定文件的变更：

```bash
# 1. 切换到目标分支
git checkout <目标分支>

# 2. 从源提交中取出目标文件到工作区
git checkout <commit-hash> -- .gitignore

# 3. 提交变更
git commit -m "chore: sync .gitignore updates from <commit-hash>"

# 4. 推送该分支（见第 5 节）
git push origin <目标分支>
```

> 对全部 6 个分支（main、feature/knowledge-maintainer、feature/my-applications、feature/rbac-upgrade、feature/supplier、refactor/code-cleanup）逐一执行上述操作。

### 4.3 PowerShell 下 git 输出噪音处理

- PowerShell 中 `Write-Host` 输出可能被 CLIXML 噪音干扰，导致 git 报错信息难以阅读；
- 建议将 git 报错重定向到文件后读取：

```powershell
cmd /c "git push origin <分支> 2> push_error.txt"
Get-Content push_error.txt
```

## 5. 认证与推送命令

### 5.1 认证方式：URL 内嵌 PAT

Git 推送认证使用 **URL 内嵌 PAT** 方式：

```bash
git push https://<PAT>@github.com/chuangwang384-eng/jshz-PMO.git <分支名>
```

> ⚠️ 踩坑提醒：
> - `http.extraHeader` 中配置的 `Bearer` / `token` 头对 **git 推送不生效**，必须用 URL 内嵌 PAT 方式；
> - PAT 属于敏感凭据，请妥善保管，勿提交到仓库或写入文档。

### 5.2 覆盖 GitHub 自动生成的 Initial commit

若远程仓库仅含 GitHub 自动生成的 `Initial commit`（内容只有 README.md），本地完整分支可直接强制推送覆盖：

```bash
git push -f https://<PAT>@github.com/chuangwang384-eng/jshz-PMO.git <分支名>
```

## 6. 后续更新分支的常规流程

### 6.1 本地提交并推送

```bash
# 1. 本地提交
git add .
git commit -m "本次变更说明"

# 2. 推送到指定分支（未设置 upstream 时显式指定）
git push origin <分支名>
```

> 说明：`upstream` 设置可以后续再补，不阻塞首次推送：
> ```bash
> git push -u origin <分支名>
> ```

### 6.2 网页端操作（GitHub）

- **新增协作者**：仓库 Settings → Collaborators → Add people，输入对方 GitHub 账号；
- **main 分支保护**：仓库 Settings → Branches → Add branch protection rule，选择 `main`，勾选所需保护项（如禁止直接推送、要求 PR 审查等）。
