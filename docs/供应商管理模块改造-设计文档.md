## 1. 设计原则

- **增量最小化**：不改数据表结构（无 DDL）、不动存量数据；后端以新增接口/校验为主，前端以表单与交互调整为主。
- **展示层排序**：主图置顶通过查询/渲染顺序实现，不做物理重排。
- **校验前置**：绑定同城校验放后端（权威），前端候选过滤放前端（体验）。
- **破坏性操作留人工**：存量跨城解绑由管理员在清单中确认后批量执行。

## 4. 需求二设计：图片改名 + 主图置顶

### 4.1 数据库

无变更。`supplier_image.name`、`sort_order`、`is_main` 均已存在。

### 4.2 后端

#### 4.2.1 新增改名接口

```
PUT /api/supplier/{supplierId}/images/{imageId}/name
Content-Type: application/json
Body: { "name": "新显示名" }
```

- 校验：
  - 供应商存在、图片存在且属于该供应商（`imageId` + `supplierId` 匹配，防越权）；
  - `name` 为空 → 置 NULL（显示时回退原文件名，与上传逻辑一致）；非空 → 长度 ≤50，超长报错；
  - 允许重名，不做唯一校验。
- 实现：`SupplierImageService.updateName(supplierId, imageId, name)`：`UPDATE supplier_image SET name = ? WHERE id = ? AND supplier_id = ?`，返回更新后的图片对象。
- 错误码：`IMAGE_NOT_FOUND`（图片不存在/不属于该供应商，HTTP 404）、`NAME_TOO_LONG`（HTTP 400）。

#### 4.2.2 图库排序调整（`SupplierImageService.list`）

- 查询返回后排序：`is_main = 1` 的图片排第一，其余按 `sort_order ASC, id ASC` 稳定排序。
- 前端渲染顺序不变（直接按返回数组渲染），列表页封面逻辑不变（已优先 `mainImage`）。

### 4.3 前端（`SupplierDetail.vue`）

- 图库每张图片的操作区增加"改名"按钮（主图格子上保留"默认封面"标签与设主图按钮并存）。
- 点击改名 → 小弹窗，输入框预填当前显示名（`img.name || img.fileName`），限制 50 字符，确认后调改名接口 → 成功后刷新图库列表。
- 空输入提交：视为清空显示名，保存后显示原文件名。

## 5. 需求三设计：酒店-打印店同城绑定

### 5.1 同城判定

```text
同城 = hotel.city_id == print_shop.city_id
```

两端 `city_id` 均为 `supplier_city.id`（NOT NULL），无需空值处理。

### 5.2 后端

#### 5.2.1 绑定校验增强（`SupplierService.bind`）

在现有校验链（id 合法 → 供应商存在 → HOTEL+PRINT 组合 → 不重复）中增加：

- 读取两端 `city_id`，若 `hotel.getCityId() != printShop.getCityId()` → 拒绝，返回错误码 `BIND_CITY_MISMATCH`，提示"仅支持绑定同城市的打印店/酒店"（HTTP 400）。

#### 5.2.2 绑定候选接口

- 复用 `GET /api/supplier/list`（已支持 `cityId` 过滤），前端调用时传入当前供应商 `cityId`。后端无需新增接口。

#### 5.2.3 绑定列表返回对端 `cityId`（`bindingsOf`）

- 返回结构在 `id/name/cityName/typeName` 基础上增加 `peerCityId`，供前端比对标记"跨城"。

#### 5.2.4 新增跨城清单接口

```
GET /api/supplier/bindings/cross-city?page=1&size=20&keyword=
```

- 查询全部 `supplier_hotel_print_rel` 关联两端供应商，过滤 `hotel.city_id != print_shop.city_id`；
- 返回分页列表，每项：`relId`、`hotelId`、`hotelName`、`hotelCity`、`printShopId`、`printShopName`、`printShopCity`、`createBy`、`createTime`；
- 支持按关键字（酒店/打印店名称）模糊过滤。

#### 5.2.5 新增批量解绑接口

```
POST /api/supplier/bindings/unbind-batch
Body: { "relIds": [1, 2, 3] }
```

- 校验：`relIds` 非空、每项存在；事务内逐条删除；
- 返回：`{ "unboundCount": n }`；存在不存在的 id 时整体失败回滚（保证一致性），或跳过并返回明细——**推荐整体校验后统一删除**（简单可控）；
- 错误码：`BINDING_NOT_FOUND`（HTTP 404）、`PARAM_INVALID`（HTTP 400）。

### 5.3 前端

#### 5.3.1 绑定弹窗候选过滤（`SupplierDetail.vue` `loadBindCandidates`）

- `listSuppliers({ typeId, cityId: currentSupplier.cityId, page: 1, size: 200 })`，只显示同城候选；
- 选项 label 保留 `${o.name}（${o.cityName || '-'}）` 城市标签。

#### 5.3.2 绑定列表跨城标签

- 绑定关系列表项：`peerCityId !== currentSupplier.cityId` 时显示"跨城"警示标签。

#### 5.3.3 跨城绑定清单与批量解绑

- 入口：供应商管理列表页顶部新增"跨城绑定"按钮（带数量角标，可选）或详情页绑定卡片内入口；
- 弹窗/独立页展示清单表格（酒店 / 打印店 / 各自城市 / 绑定时间 / 操作人），支持关键字搜索与分页；
- 表格前列复选框 → 勾选多条 → "批量解绑" → 二次确认弹窗（显示将解绑 n 条）→ 调批量解绑接口 → 刷新清单与绑定列表。

## 11. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 放开省份必填后城市搜索体验不佳 | 城市下拉 filterable 本地过滤，数据仅 349 条，性能无忧 |
| 主图置顶影响既有排序预期 | 仅展示层排序，回滚只改一行查询；存量数据不动 |
| 同城校验误伤合理业务（如异地集团采购） | 先上线后观察；如确有跨城合理场景，可加配置开关（本期不做） |
| 批量解绑误操作 | 二次确认 + 仅解绑关系（可重新绑定，可逆） |

回滚策略：阶段独立上线，任一阶段可单独回滚前端或后端；无数据迁移，回滚无残留。
