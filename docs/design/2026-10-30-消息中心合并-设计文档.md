## 一、范围与约束

### 1.1 范围

1. 右上角两个铃铛（`AnnouncementBell.vue` + `NotificationBell.vue`）合并为单一入口 `MessageDrawerBell.vue`，点击打开右侧 `el-drawer` 消息抽屉。
2. 抽屉内三个 Tab：**全部 / 系统消息 / 公告**。
3. 后端新增 2 个公告接口：`GET /api/announcement/unread-count`、`POST /api/announcement/read-all`。
4. 公告分页接口补充"生效中优先"筛选参数（低风险，见 §4.3）。
5. 未读角标 30 秒轮询合成（系统消息 + 公告）。

### 1.2 明确不做（与需求文档一致）

- 不重构公告 / 系统消息两套后端存储；
- 不新增后端统一聚合接口（「全部」Tab 前端合并）；
- 不做抽屉内详情承载（点击跳独立页面）；
- 不新增"新公告轻提示"（系统消息 ElNotification 轻提示保留）；
- 不改动现有路由与菜单；新增抽屉不产生新路由。

## 三、后端接口设计

### 3.1 `GET /api/announcement/unread-count`（新增）

**语义**：当前用户对"生效中公告"（ONLINE 且生效期内）的未读数。登录即可。

**请求**：`GET /api/announcement/unread-count`（无参数，AuthUser 取当前用户）

**响应**（`ApiResponse<Long>`）：
```json
{ "code": 0, "message": "ok", "data": 3 }
```

**Service 实现**（`AnnouncementService` 新增，参考 `NotificationService.unreadCount` 的返回形态）：
```java
/**
 * 当前用户生效中公告未读数（与 effectiveList 同一生效口径）。
 */
public long unreadCount(Long userId) {
    LocalDateTime now = LocalDateTime.now();
    List<Announcement> effective = this.list(new LambdaQueryWrapper<Announcement>()
            .eq(Announcement::getStatus, STATUS_ONLINE)
            .le(Announcement::getEffectiveTime, now)
            .and(w -> w.isNull(Announcement::getExpireTime)
                    .or().gt(Announcement::getExpireTime, now))
            .select(Announcement::getId));
    if (effective.isEmpty()) {
        return 0;
    }
    List<Long> ids = effective.stream().map(Announcement::getId).toList();
    Long read = announcementReadMapper.selectCount(new LambdaQueryWrapper<AnnouncementRead>()
            .eq(AnnouncementRead::getUserId, userId)
            .in(AnnouncementRead::getAnnouncementId, ids));
    return ids.size() - (read == null ? 0 : read);
}
```

**等价 SQL（语义参照）**：
```sql
SELECT COUNT(*)
FROM announcement a
WHERE a.status = 'ONLINE'
  AND a.effective_time <= NOW()
  AND (a.expire_time IS NULL OR a.expire_time > NOW())
  AND NOT EXISTS (
      SELECT 1 FROM announcement_read r
      WHERE r.announcement_id = a.id AND r.user_id = #{userId}
  );
```

**Controller 新增**（参考 `NotificationController.unreadCount`）：
```java
/** 当前用户生效中公告未读数 */
@GetMapping("/unread-count")
public ApiResponse<Long> unreadCount(@AuthenticationPrincipal AuthUser user) {
    if (user == null || user.getUserId() == null) {
        return ApiResponse.ok(0L);
    }
    return ApiResponse.ok(announcementService.unreadCount(user.getUserId()));
}
```

> 权限说明：员工视角即可；无 `announcement:manage` 的管理员/超管同样按本人口径计数（不特殊处理，保证角标一致）。

### 3.2 `POST /api/announcement/read-all`（新增）

**语义**：当前用户把全部"生效中公告"标记已读（幂等，重复调用不报错、不重复插入）。登录即可。

**请求**：`POST /api/announcement/read-all`（无 body）

**响应**（`ApiResponse<Void>`）：
```json
{ "code": 0, "message": "ok", "data": null }
```

**Service 实现**（`AnnouncementService` 新增，复用 `markRead` 的"先查后插"幂等思路）：
```java
/**
 * 当前用户把全部生效中公告标记已读（幂等：差集插入 announcement_read）。
 */
public int markAllEffectiveRead(Long userId) {
    LocalDateTime now = LocalDateTime.now();
    List<Announcement> effective = this.list(new LambdaQueryWrapper<Announcement>()
            .eq(Announcement::getStatus, STATUS_ONLINE)
            .le(Announcement::getEffectiveTime, now)
            .and(w -> w.isNull(Announcement::getExpireTime)
                    .or().gt(Announcement::getExpireTime, now))
            .select(Announcement::getId));
    if (effective.isEmpty()) {
        return 0;
    }
    List<Long> ids = effective.stream().map(Announcement::getId).toList();
    List<AnnouncementRead> already = announcementReadMapper.selectList(
            new LambdaQueryWrapper<AnnouncementRead>()
                    .eq(AnnouncementRead::getUserId, userId)
                    .in(AnnouncementRead::getAnnouncementId, ids));
    Set<Long> readIds = already.stream()
            .map(AnnouncementRead::getAnnouncementId).collect(Collectors.toSet());
    int count = 0;
    LocalDateTime t = LocalDateTime.now();
    for (Long id : ids) {
        if (readIds.contains(id)) {
            continue;
        }
        AnnouncementRead ar = new AnnouncementRead();
        ar.setAnnouncementId(id);
        ar.setUserId(userId);
        ar.setReadTime(t);
        announcementReadMapper.insert(ar);
        count++;
    }
    return count;
}
```

**等价 SQL（语义参照）**：
```sql
INSERT INTO announcement_read (announcement_id, user_id, read_time)
SELECT a.id, #{userId}, NOW()
FROM announcement a
WHERE a.status = 'ONLINE'
  AND a.effective_time <= NOW()
  AND (a.expire_time IS NULL OR a.expire_time > NOW())
  AND NOT EXISTS (
      SELECT 1 FROM announcement_read r
      WHERE r.announcement_id = a.id AND r.user_id = #{userId}
  );
```

**Controller 新增**（参考 `NotificationController.readAll`）：
```java
/** 当前用户把全部生效中公告标记已读（幂等） */
@PostMapping("/read-all")
public ApiResponse<Void> readAll(@AuthenticationPrincipal AuthUser user) {
    if (user != null && user.getUserId() != null) {
        announcementService.markAllEffectiveRead(user.getUserId());
    }
    return ApiResponse.ok();
}
```

> 注意：read-all 只覆盖"生效中公告"（与 unread-count 同一口径），已下架/已过期公告不在范围——与 S6「把生效公告全标已读」一致。

### 3.3 后端补充改动：`GET /api/announcement` 增加生效中筛选（低风险）

**核对结论**：现有 `pageQuery` 排序为 `isTop DESC + createTime DESC`，员工视角仅过滤 `status=ONLINE`，**未过滤生效时间**，不满足需求文档 S3「公告 Tab 生效中优先 + 发布时间倒序」。需求文档提示"若现有分页接口不满足排序，需在后端补排序参数（低风险）"，故做如下**兼容性新增参数**（不改默认行为，旧调用不受影响）：

**方案**：`GET /api/announcement?scope=effective&page=1&size=20&keyword=&status=`

- 仅当 `scope=effective` 时，员工视角在 `status=ONLINE` 基础上追加生效时间过滤：
  - `effective_time <= now AND (expire_time IS NULL OR expire_time > now)`
- 排序保持 `isTop DESC + createTime DESC`（即"生效中优先 + 置顶优先 + 发布时间倒序"）。
- `scope` 缺省 / 非 effective 时行为与现状完全一致（公告列表页 `/profile/announcements` 不传，零回归）。
- 管理视角不受影响（管理页走 `scope` 缺省 + 显式 status）。

**Controller 改动**：`pageQuery` 增加 `@RequestParam(required = false) String scope`，透传 Service。

**Service 改动**：`pageQuery` 增加 scope 参数，员工分支追加：
```java
if ("effective".equalsIgnoreCase(scope)) {
    LocalDateTime now = LocalDateTime.now();
    wrapper.le(Announcement::getEffectiveTime, now)
           .and(w -> w.isNull(Announcement::getExpireTime)
                   .or().gt(Announcement::getExpireTime, now));
}
```

**排序参数说明**：不新增"按生效时间排序"的排序关键字；"生效中优先"通过 `scope=effective` 过滤实现（只保留生效中，天然排掉未生效/已过期），置顶与时间倒序沿用现有 `orderByDesc(isTop).orderByDesc(createTime)`。

### 3.4 与 NotificationController 写法对照（新接口照此风格）

| 环节 | 参照写法 | 本任务做法 |
|---|---|---|
| Controller | `NotificationController.unreadCount/readAll`，`@AuthenticationPrincipal AuthUser`，`ApiResponse.ok(...)` | 同风格，见 §3.1/§3.2 |
| Service | `NotificationService.unreadCount/markAllRead`，MyBatis-Plus `LambdaQueryWrapper` | 同风格，公告口径用 announcement/announcement_read |
| 幂等 | `markAllRead` 用 update 条件 `isRead=0`；公告侧联合键 + 先查后插 | read-all 差集插入；unread-count 纯计数 |
| 返回值 | unread-count 返回 `Long`；read-all 返回 `Void` | 一致 |

### 4.2 三个 Tab 的数据流与状态管理

| Tab | 数据来源 | 加载函数 | 分页 | 已读管理 |
|---|---|---|---|---|
| 系统消息 | `fetchNotifications({ page, pageSize: 20 })` | `loadNotif(page)` | `notifPage`，每页 20 | 单条 `markNotificationRead` / 全部 `markAllNotificationsRead`（store 已有） |
| 公告 | `listAnnouncements({ scope: 'effective', page, size: 20 })` | `loadAnn(page)` | `annPage`，每页 20 | 单条 `markAnnouncementRead(id)` / 全部 `markAllAnnouncementsRead()`（API 新增） |
| 全部 | 并发 `loadNotif` + `loadAnn` 后 `mergeAll()` | `loadMore()` | 两路各自翻页 | 单条按来源调各自接口；全部已读 = 两个 read-all 都调 |

**数据流规则**：
1. **打开抽屉**：`refreshCurrentTab()` → 按当前 Tab 强制刷新（`activeTab==='all'` 时两路各拉第 1 页合并；`notif` 拉系统消息第 1 页；`ann` 拉公告第 1 页），页码重置为 1。
2. **切换 Tab**（`@tab-change`）：切换到该 Tab 时若列表为空则加载第 1 页；已有数据不重复加载（保持滚动位置，S2）。
3. **滚动到底**：`el-infinite-scroll` 触发 `loadMore()`（见 §4.3）。
4. **已读操作**：单条点击 / 全部已读后，同步更新本地 `isRead` 与未读计数，不整页重拉（公告 `read===false`、系统消息 `isRead===0` 语义各自保留）。

### 4.3 `el-infinite-scroll` 用法（抽屉内）

```html
<div
  class="msg-scroll"
  v-infinite-scroll="loadMore"
  :infinite-scroll-disabled="scrollDisabled"
  :infinite-scroll-distance="80"
>
  <MessageItem v-for="item in currentList" :key="item.key" ... />
  <div v-if="currentLoading" class="scroll-loading">加载中...</div>
  <div v-if="currentDone" class="scroll-done">没有更多了</div>
</div>
```

- 滚动容器必须是**可滚动元素**（`overflow-y: auto; max-height: calc(100vh - 180px)` 之类，避免绑定到 window）。
- `infinite-scroll-disabled`：`currentLoading || currentDone` 时禁用（防重复请求）。
- `loadMore` 内按 Tab 分派：
```js
function loadMore() {
  if (activeTab.value === 'all') {
    // 两路分别判断是否可继续翻页，再各拉下一页并 mergeAll()
    if (!notifLoading.value && !notifDone.value) loadNotif(notifPage.value + 1)
    if (!annLoading.value && !annDone.value) loadAnn(annPage.value + 1)
  } else if (activeTab.value === 'notif') {
    if (!notifLoading.value && !notifDone.value) loadNotif(notifPage.value + 1)
  } else {
    if (!annLoading.value && !annDone.value) loadAnn(annPage.value + 1)
  }
}
```
- 每页返回后依据 `items.length < pageSize`（或 `items.length >= total`）置 `done=true`。

### 4.4 「全部」Tab 合并去重算法

**前提**：公告 id 与系统消息 id 分属两表，数值可能冲突；两条消息类型标签不同，必须按**来源类型 + id** 区分。key 规则：`${source}-${id}`，source ∈ { `ann`, `notif` }。

**合并函数（每次任一来源加载完成页后调用）**：
```js
function mergeAll() {
  const map = new Map()
  for (const n of notifItems.value) map.set(`notif-${n.id}`, { ...n, source: 'notif', key: `notif-${n.id}` })
  for (const a of annItems.value) map.set(`ann-${a.id}`, { ...a, source: 'ann', key: `ann-${a.id}` })
  mergedItems.value = [...map.values()].sort((x, y) => {
    const tx = (x.createTime || '').replace('T', ' ')
    const ty = (y.createTime || '').replace('T', ' ')
    return ty.localeCompare(tx)   // 时间字符串倒序（yyyy-MM-dd HH:mm:ss 字典序即时间序）
  })
}
```

**要点**：
1. 置顶只在公告 Tab 生效（`activeTab==='ann'` 时后端已按 isTop 排序）；「全部」纯按时间排，前端不再做置顶逻辑（S3）。
2. 去重以已加载集合为准：后加载页中若出现已存在 key，Map set 覆盖同 key（同一条公告在后续页重复出现时保留先出现的旧数据即可，实际后端分页不会重复返回同一 id；覆盖不产生副作用）。
3. 未读状态各自独立：公告看 `read`，系统消息看 `isRead`（两字段名不同，item 渲染按 `source` 分支）。
4. 分页进度：`notifPage` / `annPage` 分别推进；`all` Tab 下 "全部已读" 同时调两个 read-all 并同步本地状态与角标。

## 五、轮询合成方案

### 5.1 方案选择（推荐：扩展 notification store，单定时器）

不新建独立定时器；在现有 `notification.js` store 中**扩展公告未读维度**，保持"一套定时器"：

```js
// state 新增
announcementUnread: 0,

// actions 新增
async loadAnnouncementUnread() {
  try {
    this.announcementUnread = await getAnnouncementUnreadCount()
  } catch (e) { /* 静默，下轮重试 */ }
},

// init / poll / refresh 中追加调用（三处都加，保证初始化与刷新同步）
// 例：poll() 开头
async poll() {
  const before = new Set(this.baselineIds)
  await Promise.all([this.loadUnread(), this.loadAnnouncementUnread()])
  await this.loadList({ page: 1, pageSize: 20 })
  // ... 原轻提示逻辑不变
}
```

**合成**：`MessageDrawerBell.vue` 中 `totalUnread = notification.unread + notification.announcementUnread`（computed）。

**轻提示保留**：系统消息新增时的 `ElNotification` 行为完全不变（仍由 `poll()` 的 baselineIds 逻辑触发）；公告不弹轻提示（S4）。

### 5.2 启动与停止

- 挂载 `MessageDrawerBell` 时（`onMounted`）：`if (auth.isLoggedIn) { notification.init(); notification.startPolling() }`（与现有 NotificationBell 相同）。
- `onBeforeUnmount`：`notification.stopPolling()`。
- 抽屉打开时：`refreshCurrentTab()` 强制刷新当前 Tab；同时 `notification.loadUnread()` + `notification.loadAnnouncementUnread()` 同步角标（S9）。

### 5.3 时序与并发

- 轮询每 30s：`Promise.all([unread, announcementUnread])` 并发；列表刷新跟随现有逻辑。
- 抽屉打开瞬间与轮询同时触发：无冲突（列表状态以页面/抽屉内 ref 为准，轮询只负责角标与轻提示；store.items 不再作为抽屉列表唯一来源）。
- 删除旧铃铛后 `notification.init()` 的启动责任转移给 `MessageDrawerBell`，**必须保证全局只启动一次**（`startPolling` 已有 `if (this.pollTimer) return` 幂等保护）。
