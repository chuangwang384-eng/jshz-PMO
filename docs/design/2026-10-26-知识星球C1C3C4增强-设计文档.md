# 知识星球增强 C1/C3/C4 — 设计文档（2026-10-26）

> C1 文档内容检索（期望型）/ C3 文档收藏与更新通知（期望型）/ C4 下载次数统计（兴奋型）。
> 迁移脚本：`database/migration/20261026_add_knowledge_c1c3c4.sql`（幂等）。

## C1 内容检索

- `knowledge_document` 加列 `content MEDIUMTEXT NULL`：上传/更新时抽取正文（pdf → PDFBox 2.0.31；doc → POI scratchpad HWPF；docx → XWPF；图片类为 null），空白归一化后截断 200,000 字符入列；抽取失败置 null 不阻断上传（该文档仅不支持内容检索）。
- `listKnowledgeDocs` keyword 检索范围扩展为 title / file_name / content 三列 OR LIKE（内网文档量级小，LIKE 足够，暂不引入全文索引）。
- 前端两处搜索框 placeholder 改「按标题 / 内容关键字检索」，传参与交互（回车/清空）不变；空关键字行为不变。

## C3 收藏与更新通知

- 新表 `knowledge_favorite`（id / doc_id / user_id / create_time，UNIQUE(doc_id,user_id)，KEY(user_id)）。
- 接口（均登录即可，**userId 一律取当前登录用户，不接收客户端传入，天然杜绝越权操作他人收藏**）：
  - `POST /api/knowledge/favorites/{docId}` 收藏（幂等，唯一约束兜底并发）
  - `DELETE /api/knowledge/favorites/{docId}` 取消收藏（幂等）
  - `GET /api/knowledge/favorites` 我的收藏列表（{doc, favoriteTime}，收藏时间倒序，已删除文档自动过滤）
  - `GET /api/knowledge/favorites/{docId}` 单文档收藏状态
  - 路径设计说明：刻意避开 `DELETE /api/knowledge/docs/**`（permission 表绑定 knowledge:manage 的通配规则），否则普通员工取消收藏会被 403。
- 更新通知：`PUT /api/knowledge/docs/{id}` 版本更新成功后，向该文档全部收藏者写 `doc_updated` 通知（「您收藏的文档《xx》已更新至 vN」，jump=/knowledge-planet），排除操作人本人；通知失败不影响主流程。取消收藏后自然不再收到通知（通知按收藏关系实时查询写入）。
- 前端：文档列表与全部文档总览操作列新增「收藏/取消收藏」（row.isFavorite 本地即时切换，收藏视图取消后从列表移除）；知识星球父页卡片头新增「全部文档 / 我的收藏」切换；收藏视图客户端按标题/文件名筛选、不分页；更新提醒由既有 NotificationBell 30s 轮询展示。

## C4 下载次数统计

- `download_log` 加列 `doc_id BIGINT NULL` + `idx_doc_id`；下载端点 `GET /api/knowledge/docs/files/{fileName}?download=1`（附件下载）时写一条 `download_type='knowledge_doc'`、`doc_id`、`expert_name`=文档标题 的记录；**inline 预览不计入**；按存储文件名反查文档，失败不阻断下载。
- 列表接口返回 `downloadCount`：`SELECT doc_id, COUNT(*) ... GROUP BY doc_id` 单次聚合（全列表一次查询，无 N+1），未下载显示 0。
- 前端列表新增「下载次数」列：管理员（knowledge:manage）与文档上传人本人可见数值，其他用户显示 —（不暴露他人文档热度）。

## 兼容与影响

- 既有接口签名不变；空关键字/标题检索行为不变；分页逻辑不变。
- 历史文档 content 为 NULL：仅不支持内容检索，标题/文件名检索不受影响（不做存量回补，如需可后续离线补抽）。
- 事实基线更新：表 14→15（+knowledge_favorite），Mapper/Entity 14→15，Controller 数不变（收藏接口并入 KnowledgeController）。
