# jshz-PMO 项目管理权限变更设计文档

- 日期：2026-10-28
- 范围：项目管理模块（全员可新建 + 行级数据权限）
- 状态：已确认，待实施

## 一、变更目标

1. **全员可新建项目**：所有登录用户（EMPLOYEE 等普通角色）均可创建项目。
2. **行级数据权限**：普通员工只能看到自己负责（owner）或执行（project_executor 含本人）的项目；ADMIN 与超级管理员可见全部。

## 二、已确认设计决策

| 决策点 | 结论 |
|---|---|
| 数据权限适用范围 | 普通员工按"负责人或执行人"过滤；ADMIN / 超级管理员豁免 |
| 新建入口粒度 | 新增全员权限码 `project:create`，绑定所有非 SUPER_ADMIN 角色；前后端改绑 |
| 数据出口覆盖 | 列表 + 详情 + 导出 + 关联子接口（专家/供应商/文档/合同/预算）统一过滤 |
| 验收方式 | 测试账号 `must_change_password` 置 0，用 `测试/111111` 直接验收 |

## 三、数据库变更（新增迁移脚本 20261028_project_permissions.sql，幂等）

1. `permission` 表：将原 id=81 规则（method=POST, path=/api/project, code=project:manage）改造为 `project:create`（若已存在 project:create 规则则删除 id=81 行）。**必须处理原规则**，否则 DbPermissionFilter 先命中 project:manage 时普通员工无该码被 403。
2. `role_permission` 表：将 `project:create` 绑定到所有非 SUPER_ADMIN 角色（EMPLOYEE / PROJECT_OWNER / ADMIN / KNOWLEDGE_MAINTAINER 等，以 role 表实际角色为准），INSERT ... SELECT ... WHERE NOT EXISTS 幂等。
3. `permission` 表：新增标记权限码 `project:view-all`（不绑定 method/path 接口规则，仅用于代码内豁免判断；type 按 permission 表既有约定选非接口规则类型）。
4. `role_permission` 表：将 `project:view-all` 仅绑定 ADMIN 角色；超级管理员由代码内强制全权自动豁免（PermissionService 中 SUPER_ADMIN 恒返回全部权限码）。
5. 验收辅助（单独执行，不入业务迁移）：`UPDATE users SET must_change_password=0 WHERE username='测试'`（先查询现值，仅清标记，不动密码）。

## 四、后端变更（ProjectService.java / ProjectController.java）

1. `ProjectService.create()`：权限校验由 `requireManage(user)`（project:manage）改为 `requireCreate(user)`（校验 project:create）。
2. 新增公共行级过滤方法：
   - 豁免判断：`user.hasPermission("project:view-all")` 为 true 则不过滤（SUPER_ADMIN 恒全权自动豁免；ADMIN 因绑定 view-all 豁免；PROJECT_OWNER 不绑 view-all，即使持有 project:manage 也受行级过滤）。
   - 非豁免条件：`owner_id = 当前用户 OR id IN (SELECT project_id FROM project_executor WHERE user_id = 当前用户)`。
3. `pageProjects()`：非豁免用户无条件追加行级条件（不依赖前端主动传参）。
4. 读出口（GET）逐一校验项目可读，越权抛 403/BusinessException：
   - `detail()`（GET /api/project/{id}）
   - `experts` / `suppliers` / `docs` / `contracts` / `budget`（按 projectId 读取的关联子接口）
   - `export()`（导出）
5. 写类接口保持 `project:manage` 不变：`phase`（阶段推进）、`cancel`、`config`，以及关联子表增删改。

## 五、前端变更（ProjectList.vue）

1. 第 49 行"新建项目"按钮：`v-permission="'project:manage'"` → `v-permission="'project:create'"`。
2. 配置 / 编辑 / 取消 / 删除按钮保持 `project:manage` 不变。
3. 列表无前端逻辑改动（行级过滤由后端强制）。

## 六、可直接发给施工 Agent 的一段话

> 在 <LOCAL_PATH> 中实现"全员可新建项目 + 行级数据权限"：新建迁移脚本 `database/migration/20261028_project_permissions.sql`（幂等，含 project:create 规则改造与全员绑定、project:view-all 权限码新增及 ADMIN 绑定）；后端 ProjectService.create 校验由 project:manage 改为 project:create；新增行级过滤公共方法（豁免=hasPermission(project:view-all)，非豁免追加 owner 或执行人条件），应用于 pageProjects 及 detail/experts/suppliers/docs/contracts/budget/export 全部 GET 读出口，越权返回 403；前端 ProjectList.vue 新建按钮改绑 project:create；最后执行 npm run build 与 mvn package 确保构建通过。不触碰其他模块。

## 七、验收标准（10 项）

| # | 验收项 | 预期 |
|---|---|---|
| 1 | 测试账号（EMPLOYEE）登录 | 测试/111111 可直接登录，无需改密 |
| 2 | 新建项目按钮可见性 | 测试账号可见"新建项目"按钮 |
| 3 | 新建表单打开 | 正常打开、必填校验生效 |
| 4 | 合法创建落库 | 创建成功，project 表新增，operation_log 有 CREATE_PROJECT |
| 5 | 列表展示本人项目 | 创建人自动成为执行人，列表可见自己创建的项目 |
| 6 | 刷新 / 重登持久 | 重新登录后项目仍在 |
| 7 | 详情页数据 | 详情、专家、文档等数据正确展示 |
| 8 | 行级过滤-不可见他人项目 | 测试账号看不到"他人负责/执行"的项目 |
| 9 | 越权访问拦截 | 测试账号直接调 GET /api/project/{他人项目id} 返回 403 |
| 10 | 管理员豁免与回归 | ADMIN 仍可见全部项目；专家库/供应商等其他模块不受影响 |

## 八、风险与边界

- 不绕过权限控制：新建放开走权限码、行级过滤在后端强制，前端按钮仅展示层控制。
- 现有数据仅 1 条项目：验收前需先用 ADMIN 造一个"他人项目"，验证测试账号不可见。
- 迁移脚本幂等，可重复执行；只动项目管理模块，不触碰其他模块。
