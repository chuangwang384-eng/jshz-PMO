# 工作台导航与快捷访问整合设计

日期 2026-11-07 · 状态：已评审（Owner 决策确认） · 版本 v1.1 · 关联需求：[2026-11-07-工作台导航与快捷访问整合-需求文档](../requirements/2026-11-07-工作台导航与快捷访问整合-需求文档.md)

**Owner 决策（2026-11-07）**：顶部导航右侧改造（App.vue 页头头像下拉）本期不做；快捷访问个性化后端变更纳入；图标沿用 `@element-plus/icons-vue`；Ctrl K 仅工作台页；「更多」与编辑态样式按概念图执行。

| 组件 | 改动 | 影响范围 |
| --- | --- | --- |
| `frontend/src/components/GlobalSearchBar.vue` | Ctrl K 支持（`defineExpose({focus})`）、提示徽标、去独立搜索按钮、去标题 | 工作台页 |

## 2. 搜索 + 快捷访问整合卡片（P0）

### 2.1 结构

`DashboardView.vue` 中删除 `<GlobalSearchBar />` 与 `<nav class="quick-links">` 两个独立区块，替换为一张 `.nav-card`：

```
┌─ .nav-card ──────────────────────────────────────────┐
│ 🔍 搜索专家、项目、客户、供应商或知识文档…    [Ctrl K] │  ← GlobalSearchBar（改造后，无标题）
│ ────────────────────────────────────────────────────  │
│ 快捷访问 [条目][条目][条目][条目][条目][条目] [更多▾][编辑] │  ← QuickAccessBar
└──────────────────────────────────────────────────────┘
```

- `GlobalSearchBar` 保留全部搜索逻辑（防抖/分组/键盘导航/清空），仅：删 label 标题、输入框样式改为 `#F1F5F9` 底 + 无独立搜索按钮（回车触发）、右侧加 `.kbd-hint`（`Ctrl K`）。
- Ctrl K：`DashboardView.vue` `onMounted` 注册 `document.addEventListener('keydown')`，`event.ctrlKey/metaKey && event.key==='k'` 时 `preventDefault()` 并调用 GlobalSearchBar 暴露的 `focus()`；检查 `event.isComposing` 避免输入法冲突；组件卸载时移除监听。当前项目无其他全局快捷键（已核实），无冲突。**仅工作台页生效**。

### 2.2 QuickAccessBar 组件

```js
// 数据模型（对齐 user_dashboard_layout 的"配置即数据"思路）
QuickAccess = { id: 'page.project', order: 0 }   // 只存卡片标识与顺序，不存标题/图标/路径
```

- **候选集** = `CARD_CATALOG` 中 `page.*` 项（复用现有 `perm`/`cap` 过滤函数 `canShow`），新增入口零代码（改目录即可）。
- 默认顺序 = 现有 `entries` 顺序过滤后取前 6，其余进「更多」。
- 图标：每项固定映射一个 `@element-plus/icons-vue` 图标（映射表集中在组件内，后续换 Lucide 仅改映射表）。
- 「更多 ▾」：`el-dropdown` 列出第 7 项起条目；样式按概念图（胶囊条目、轻边框）。
- 编辑态：按概念图执行——行内「编辑」按钮进入，候选列表（含未启用项）+ 已启用列表，点击增删、`HTML5 drag&drop` 排序（复用可编辑布局的原生拖拽模式，不引第三方库）；「保存/取消/恢复默认」；有改动离开页面提示（`onBeforeRouteLeave` 已有同类拦截，模式一致）。

## 3. 快捷访问个性化持久化（P1，后端）

### 3.1 数据库（1 张新表，幂等迁移）

```sql
-- database/migration/20261107_add_user_quick_access.sql（重复执行保护：CREATE TABLE IF NOT EXISTS）
CREATE TABLE IF NOT EXISTS user_quick_access (
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id     BIGINT NOT NULL,
  item_key    VARCHAR(64) NOT NULL,      -- 对应 CARD_CATALOG 的 page.* 标识
  sort_order  INT NOT NULL DEFAULT 0,
  updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_user_item (user_id, item_key),
  KEY idx_user (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='工作台快捷访问个性化配置';
```

迁移脚本标注适用库（expert_system）与幂等保护，先在隔离测试库执行并验证重复执行，再随发布流程上生产。

### 3.2 接口（对齐 layout 接口模式）

- `GET /api/dashboard/quick-access` → `{ items: ['page.project', ...] }`；未配置返回空（前端用默认）。
- `PUT /api/dashboard/quick-access`，body `{ items: [...] }`：服务端逐项校验 `item_key ∈ page.* 白名单` 且当前用户有权（capability 校验与 `/api/dashboard/overview` 同源），非法项拒绝整单（400）；全量覆盖写入（事务内删旧插新）。
- 登录校验沿用现有过滤器；无新权限点。
- 与 `user_dashboard_layout` 一致：**服务端不存标题/图标/路径**，展示信息始终来自前端目录，撤权后过期配置自动失效。

| 类型 | 内容 |
| --- | --- |
| 构建 | `VITE_DASHBOARD_LAYOUT_V2=true npm run build -- --outDir temp/...`（**必须带开关，见 2026-11-07 editfix 事故**） |
| 后端 | 新接口单测：未登录 401、非法 item_key 400、全量覆盖幂等、撤权项被拒；迁移脚本隔离库执行 + 重复执行 |

| 回归 | 布局编辑闭环；搜索分组结果；**App.vue 页头零改动确认**（截图对比铃铛/用户名/退出登录） |

异常路径：quick-access 接口失败时回退默认入口（不阻塞页面）；`PUT` 保存失败保留编辑内容可重试；接口超时不影响布局编辑。

## 6. 风险与兼容

- 新表迁移为加表操作，无不可逆变更；回滚 = 还原 jar + 前端 conf 指针，表保留（无害）。
- 后端发布与前端发布分两步：先迁表+发后端（旧前端不受影响，接口无人调用），再发前端——天然兼容窗口。
- 概念图中的表情符号、黄色圆形图标为示意素材，实现用现有图标库等价替换，不引入图片资源。
