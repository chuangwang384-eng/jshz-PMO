## 2. 后端：工作台项目数据口径

### 2.1 `DashboardReadService.projects()`

一次查询取全部相关项目，无逐卡查询；移除 `project_config_snapshot`、`project_phase_history`、`ProjectConfigurationService.phase()`、`DashboardRules.completion()` 的依赖。

```sql
SELECT p.id, p.name, p.category, p.team, p.status,
       p.start_date, p.end_date, p.meeting_start_date, p.meeting_end_date,
       p.owner_id, p.creator_id, u.username ownerName,
       ph.name phaseName, sc.name cityName,
       EXISTS(project_executor …) isExecutor,
       EXISTS(project_assistant …) isAssistant
FROM project p
LEFT JOIN sys_user u ON u.id = p.owner_id
LEFT JOIN project_phase ph ON ph.id = p.phase_id
LEFT JOIN supplier_city sc ON sc.id = p.city_id
WHERE p.status NOT IN ('DELETED','CANCELED')
  AND (p.owner_id = ? OR p.creator_id = ?
       OR EXISTS(project_assistant …) OR EXISTS(project_executor …))
```

- **成员范围**：与 `ProjectService.isProjectMember` 对齐（负责人/创建人/协助人 + 历史执行人兼容）。工作台是只读聚合，不扩大任何写权限。
- **阶段名**：`project_phase.name`（当前字典仅「日程上传」激活）；缺失时返回「未设置阶段」，不再返回「配置异常」。
- **风险**：`DashboardRules.warning("INCOMPLETE", endDate, today)`，复用既有日期边界（含第 7 天、今天单独计数、空日期不告警）。新流程不设完成阶段，因此**不再判定 COMPLETED/UNKNOWN**。
- **`projectRisk` 字段保持不变**：`overdueCount / dueTodayCount / dueSoonCount / unknownCompletionCount`，后者恒 0（兼容前端旧字段，前端已移除对应横幅）。
- **输出字段**（保留旧 key 以兼容已保存布局与前端）：`id/name/status/endDate/ownerName/phaseName/myRelations/warning/target/completionState`，新增 `category/team/teamLabel/startDate/meetingStartDate/meetingEndDate/cityName`；不再输出 `lastPhaseChange`。
- `teamLabel` 映射 DEPT1/2/3 → 项目一部/二部/三部（与 `ProjectService.teamLabelOf` 一致）。

### 2.2 全局搜索 project 分组

```sql
FROM project t LEFT JOIN project_phase ph ON ph.id = t.phase_id
WHERE t.status <> 'DELETED'
  AND (t.owner_id=? OR t.creator_id=? OR EXISTS(assistant) OR EXISTS(executor))  -- 无 project:view-all 时
extra = COALESCE(ph.name, '未设置阶段')
```

`DashboardReadService.search()` 删除 `metadata`/配置解码分支，直接透传 SQL `extra`；`assertFalse(...contains("effective_config"))` 仍然成立。搜索分组、排序、脱敏、超时降级逻辑不变。

### 2.3 卡片白名单（后端）

`PUBLIC_CARDS` 增 `page.profileHome`；`MODULE_CARDS` 增 `page.complianceAssociation` / `page.complianceEnterprise` → `knowledge`；`validate` 上限 20→24（目录 23 张）。`QuickAccessService` 复用同一 `allowed()`，无需单独改动。

## 3. 前端：结构、入口与交互

### 3.1 卡片目录与白名单一致性矩阵

新增 3 个入口均落在四处白名单中（`safeTarget` 为深链跳转必需，否则点击无反应）：

| 卡片 id | 标题 | 路径 | 权限/能力 | CARD_CATALOG | QUICK_ACCESS_ORDER | ICONS | LayoutService | safeTarget |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `page.complianceAssociation` | 协会合规要求 | `/knowledge-planet/association-compliance` | `cap: knowledge` | ✓ | ✓ | `Document` | MODULE→knowledge | ✓（已有） |
| `page.complianceEnterprise` | 企业合规要求 | `/knowledge-planet/enterprise-compliance` | `cap: knowledge` | ✓ | ✓ | `Files` | MODULE→knowledge | ✓（已有） |

新增项排在 `QUICK_ACCESS_ORDER` 末尾 → 默认展示前 6 个入口不变；已保存配置账号经 `enabled` 补回后出现在「更多」下拉，不破坏既有顺序。`DEFAULT_LAYOUT`（4 统计卡 + 6 面板）不变。

### 3.2 布局编辑固定启用

删除 `import.meta.env.VITE_DASHBOARD_LAYOUT_V2` 判断与 `getLegacyDashboardLayout()` 前端回退分支。后端 `/api/dashboard/layout/v2` 的 `snapshot()` 已实现 legacy→v2 的 `legacyHash` 校验回退，前端无需再读旧接口。构建不再需要任何环境变量开关。

### 3.3 「我的项目」面板

- 头部按钮：`项目列表`（`/project`）+ `刷新`；删除重复的「全部可见项目」与失效的 `mine=1` 深链。
- 行内容：`会议名称 + 风险标签` / `团队 · 会议类型 · 会议城市 · 阶段 · 负责人 · 会议举办时间（单日或区间）· 结束日期` / `我的角色`；移除「最近推进/回退」与 `phaseName || '筹备'` 兜底。
- 会议时间用 `meetingRange()` 归一化：无值不显示，单日显示一天，多日显示 `起 ~ 止`。

### 3.4 快捷访问交互修正

```js
// 与后端 QuickAccessService.MAX_ITEMS = 10 对齐（1.0.37.28.1 补丁）
const MAX_ITEMS = 10
const defaultEnabled = computed(() => props.candidates.slice(0, MAX_ITEMS))
const enabled = computed(() => {
  if (!config.value) return defaultEnabled.value
  const known = new Map(props.candidates.map(c => [c.id, c]))
  const ordered = config.value.filter(id => known.has(id)).slice(0, MAX_ITEMS).map(id => known.get(id))
  const used = new Set(ordered.map(c => c.id))
  const extra = props.candidates.filter(c => !used.has(c.id)).slice(0, MAX_ITEMS - ordered.length)
  return [...ordered, ...extra]
})
```

**发布后补丁 1.0.37.28.1**：候选扩到 13 项后，原先「补回全部新增项」会让 `saveDraft()` 提交 12–13 项，触发后端 `400 快捷访问最多 10 个`，并因下述整单中止连带布局保存失败。现按 10 上限截断 `defaultEnabled` / `enabled` / `addable`，`saveDraft()` 增加超限防御，编辑区满额时提示「最多 10 个，请先移除再添加」。卡片目录 23 项、布局上限 24 不受影响；未启用的新入口仍可从布局编辑与侧边栏进入。

`saveLayout()` 接收 `saveDraft()` 返回值：`=== false`（空草稿）时整单中止，不调用布局保存、不弹「已保存」，`finally` 恢复编辑态可用，`cancelEdit()` 不执行 → 用户修改完整保留。

### 3.5 移除项

- 「项目状态待核实」横幅（`unknownCompletionCount` 已恒 0，口径不再存在）与 `InfoFilled` 引用；`WarningFilled` 由状态栏继续使用。
- `utils/dashboard.js` query 白名单中的 `mine`（项目列表不再读取）。
