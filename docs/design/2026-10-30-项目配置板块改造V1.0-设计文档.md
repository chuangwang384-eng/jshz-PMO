> 版本：v1.0

> 设计原则：沿用现有技术栈与既有模式（DbPermissionFilter 数据驱动权限、migration 脚本变更、全量替换保存语义），最小侵入、兼容存量数据、可回滚。

## 1. 总体架构

```
项目类型(project_type) ──1:N──> 类型阶段序列(project_type_phase_rel) ──> 全局阶段字典(project_phase)
        │
        └──(类型维度)──> 阶段模板绑定(project_phase_template_rel.type_id) ──> 模板(project_template)
```

- 类型阶段序列：新表 `project_type_phase_rel`，表达"某类型选用哪些阶段、按什么顺序"；
- 阶段模板绑定：现有表 `project_phase_template_rel` 加类型维度 `type_id`，`type_id=0` 表示全局兜底，非 0 表示类型专属；
- 读取语义：优先类型专属，无专属回退全局兜底。

## 2. 数据模型设计

### 2.1 新建表 project_type_phase_rel（类型 → 阶段序列）

```sql
CREATE TABLE project_type_phase_rel (
  id          BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
  type_id     BIGINT NOT NULL COMMENT '项目类型ID（FK project_type.id）',
  phase_id    BIGINT NOT NULL COMMENT '流程阶段ID（FK project_phase.id）',
  sort        INT NOT NULL DEFAULT 0 COMMENT '阶段顺序（小在前）',
  create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (id),
  UNIQUE KEY uk_type_phase (type_id, phase_id),
  KEY idx_type_id (type_id),
  KEY idx_phase_id (phase_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='项目类型-流程阶段关联（类型自定义阶段序列）';
```

说明：
- `uk_type_phase` 保证同一类型内阶段不可重复；
- `idx_phase_id` 用于阶段删除时的引用校验与级联清理。

### 2.2 改造 project_phase_template_rel（阶段模板绑定加类型维度）

```sql
ALTER TABLE project_phase_template_rel
  ADD COLUMN type_id BIGINT NOT NULL DEFAULT 0 COMMENT '项目类型ID，0=全局兜底绑定' AFTER template_id;

-- 调整唯一键：由 (phase_id, template_id) 改为 (type_id, phase_id, template_id)
ALTER TABLE project_phase_template_rel
  DROP INDEX uk_phase_template,
  ADD UNIQUE KEY uk_type_phase_template (type_id, phase_id, template_id);
```

说明：
- 存量绑定行 `type_id` 自动落为 0（全局兜底），无需搬数，兼容现有种子数据；
- 用 `0` 而非 `NULL` 表达"全局"，避开 MySQL 唯一索引中 NULL 不参与唯一性约束的问题；
- 全量替换保存语义沿用现有 `savePhaseTemplates`：先删目标 (type_id, phase_id) 全部行，再按传入 binds 重建。

### 2.3 读取语义

查某类型 T 某阶段 P 的模板绑定：
1. 取 `type_id = T AND phase_id = P` 的专属绑定；存在则返回；
2. 无专属绑定时，取 `type_id = 0 AND phase_id = P` 的全局兜底绑定；
3. 仍无则返回空列表（前端按模板字典勾选界面展示）。

## 3. 后端接口设计

### 3.1 新增/扩展接口

| 接口 | 方法 | 说明 | 权限 |
|---|---|---|---|
| `/api/project/config/types/{typeId}/phases` | GET | 查类型阶段序列（按 sort 升序，含阶段完整信息） | 登录即可 |
| `/api/project/config/types/{typeId}/phases` | PUT | 全量保存类型阶段序列（先删后插，入参为排序后的 phaseId 数组） | project:manage |
| `/api/project/config/types/{typeId}/phases/{phaseId}/templates` | GET | 查该类型该阶段模板绑定（无专属时回退全局兜底） | 登录即可 |
| `/api/project/config/types/{typeId}/phases/{phaseId}/templates` | PUT | 全量保存该类型该阶段模板绑定（type_id=typeId） | project:manage |
| `/api/project/config/templates/{id}` | PUT | 修改模板（名称/模板类型；名称唯一校验、类型枚举校验） | project:manage |
| `/api/project/config/templates/{id}` | DELETE | 删除模板（有绑定引用时拦截提示"请先解除绑定"） | project:manage |

### 3.2 保留接口

| 接口 | 说明 |
|---|---|
| `GET/PUT /api/project/config/phases/{phaseId}/templates` | 现有全局绑定接口保留（等价 typeId=0 场景），作为未配置流程类型的兜底维护入口 |
| types / phases / templates 现有 CRUD | 保留，templates 增加 PUT/DELETE |

### 3.3 删除联动

**deleteType（改造）**：
1. 校验 `project.type_id = id AND status != DELETED` 有引用 → 抛"该类型下仍有 N 个项目，不能删除"（沿用现有）；
2. 无引用时：删除 `project_type_phase_rel` 中 type_id=id 全部行；删除 `project_phase_template_rel` 中 type_id=id 全部行（类型专属绑定）；再删类型本身；写 operation_log。

**deletePhase（改造）**：
1. 校验项目引用（现有）；
2. 校验 `project_type_phase_rel` 中存在 phase_id → 抛"该阶段已被类型流程引用，不能删除"；
3. 无引用时：删除 `project_phase_template_rel` 中 phase_id 全部行（含 type_id=0 与各类型专属行）；再删阶段；写 operation_log。

**deleteTemplate（新增）**：
1. 校验 `project_phase_template_rel` 中存在 template_id（不限 type_id）→ 抛"该模板已被绑定引用，请先解除绑定"；
2. 无引用时删除模板；写 operation_log（ACTION_DELETE_TEMPLATE）。

### 3.4 新增 Service 方法建议

- `listTypePhases(Long typeId)`：查类型阶段序列，join project_phase 取完整信息；
- `saveTypePhases(Long typeId, List<Long> phaseIds)`：校验 type 存在、phase 存在且 is_active=1，先删后插、按入参顺序赋 sort=0..n-1，事务保护；
- `listTypePhaseTemplates(Long typeId, Long phaseId)`：优先专属、回退全局的读取逻辑；
- `saveTypePhaseTemplates(Long typeId, Long phaseId, List<BindItem>)`：typeId=0 时走原 savePhaseTemplates 逻辑，typeId>0 时写类型专属行；
- `updateTemplate(Long id, UpdateTemplateReq)`、`deleteTemplate(Long id)`。

## 4. 权限规则设计（migration 脚本 20261030_project_config_v2.sql）

```sql

  (method = 'PUT' AND path = '/api/project/config/templates/*') OR
```

## 5. 项目联动逻辑

### 5.1 新建项目

- 所选类型已配置流程（project_type_phase_rel 有行）：阶段下拉只显示该类型流程内阶段，`phase_id` 默认取排序第一个阶段；
- 所选类型未配置流程：沿用现有全局阶段逻辑（显示全部启用阶段，默认取最小 sort 阶段）。

### 5.2 编辑项目

- 切换类型时校验当前阶段是否属于新类型流程；不属于则提示并要求重新选择；
- 阶段下拉按类型流程过滤（未配置流程时显示全部启用阶段）；
- 后端在保存项目时按同规则二次校验（防绕过），非法阶段返回 400 并提示。

## 6. 前端交互设计

### 6.1 类型编辑弹窗扩展（核心）

现有编辑弹窗（400px 仅 name）扩展为三块：
- **基础信息**：类型名称、排序（沿用现有字段语义，新增排序输入）；
- **流程配置（阶段序列）**：已选阶段列表按顺序展示，支持"添加阶段"（从启用阶段字典挑未选中的）、上移/下移调整顺序、移除；
- **阶段模板绑定**：每个已选阶段可展开配置区，勾选模板、设置必填与排序（复用现有"阶段模板绑定"交互模式：勾选表格 + 必填 select + 排序 input）。

保存策略：弹窗内一个"保存"按钮统提——先保存基础信息（`PUT types/{id}`），再保存阶段序列（`PUT types/{typeId}/phases`），最后逐个保存有变更的阶段模板绑定（`PUT types/{typeId}/phases/{phaseId}/templates`）；任一步失败，弹窗停留并提示具体失败环节，不静默、不丢已填数据。

### 6.2 阶段模板绑定 Tab 改造

- 现有"选阶段 → 配模板"改为"选配置范围 → 选阶段 → 配模板"；
- 配置范围两类：
  - **具体类型**：阶段下拉自动带出该类型流程内阶段；保存走类型专属接口（type_id=类型）；
  - **全局兜底**：type_id=0，维护未配置流程类型的默认绑定；保存走现有全局接口；
- 绑定表格展示与勾选交互沿用现有风格（是否绑定/必填选填/排序）。

### 6.3 模板管理 Tab 补全

- 表格增加操作列：编辑（弹窗改模板名称/模板类型）、删除（二次确认，后端校验绑定引用并拦截提示"请先解除绑定"）；
- 新建模板表单维持现有样式。

### 6.4 新建/编辑项目联动（前端）

- 新建项目：选择类型后阶段下拉自动刷新为该类型流程内阶段（未配置流程则显示全部启用阶段），默认选中第一个；
- 编辑项目：切换类型时校验当前阶段，非法则提示重新选择。

### 6.5 加载容错

- 4 个 Tab 数据分开加载（fetchAll 拆为 4 个独立请求函数），各自失败各自弹错误提示（el-message），互不影响；
- 失败时提供重试入口（Tab 内"重试"按钮或局部刷新）。

### 6.6 权限兜底

- 页面级：路由守卫 `project:manage` 保留；
- 按钮级：写操作按钮统一校验权限码（前端权限码来源同现有），无权限不渲染（与后端接口校验双保险）。
