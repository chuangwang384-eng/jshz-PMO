## 3. R2 编辑执行人设计

### 3.1 根因链回顾

详情接口不返回 executorIds → 编辑弹窗 watch 拿不到 → 编辑保存 delete 掉 executorIds。

### 3.2 后端改动（ProjectService.java）

- `toBriefMap()`（L115-127）与 `detail()`（L192-207）增加返回 `executorIds`：
  ```java
  m.put("executorIds", executorIdsOf(project.getId())); // List<Long>，参考现有 executorNamesOf 实现
  ```
- `update()`（L249-283）**无需改动**：现有逻辑已支持 executorIds 非空时删旧插新。

### 3.3 前端改动（ProjectEdit.vue）

1. **watch 回显**（L105-110）：详情接口补返回后 `p?.executorIds` 自然生效，无需改逻辑；确认 `form.executorIds = [...p.executorIds]` 分支可达；
2. **save() 去掉删除**（L119-121）：编辑场景不再 `delete data.executorIds`，直接提交：
   ```js
   if (form.id) {
     await updateProject(form.id, data) // data 含 executorIds
   } else {
     await createProject(data) // 新建保持原样
   }
   ```
3. **标签展示**：`el-select multiple` 的 `el-option` 保持 `:label="u.username"`，选中项即显示姓名标签；无需引入工号字段（ADR-003）。

### 3.4 边界

- 执行人下拉数据源 `GET /api/project/executors` 不变（仅 id/username）；
- 后端 update 传空数组时：现有逻辑 `executors.isEmpty()` 不替换（保持原执行人），与"未修改直接保存"语义一致；

## 4. R3 阶段按钮改造设计

### 4.1 操作区新结构（ProjectDetail.vue L10-19 改造）

```html
<!-- 推进 / 回退：canAdvance 才显示 -->
<el-button v-if="detail.canAdvance && canAdvanceToNext" type="primary" @click="confirmAdvance">
  推进下一阶段
</el-button>
<el-button v-if="detail.canAdvance && canRollbackToPrev" @click="confirmRollback">
  回退阶段
</el-button>
<!-- 保留原按钮 -->
<el-button v-if="detail.canManage" @click="openEdit">编辑项目</el-button>
<el-button v-if="detail.canAdvance" type="warning" @click="openCancel">取消项目</el-button>
```

### 4.2 边界与显隐

- `canAdvanceToNext`：`detail.phase.sort < maxSort`（如非已完成阶段）且当前阶段必填模板已提交（D10）；
- `canRollbackToPrev`：`detail.phase.sort > minSort`（如非立项阶段）；
- 已完成阶段隐藏推进按钮；立项阶段隐藏回退按钮；无权限（非 canAdvance）两者均不显示。

### 4.3 确认弹窗

- 推进：`确认将项目推进到「下一阶段名」阶段？`
- 回退：`确认将项目回退到「上一阶段名」阶段？已提交的材料会保留，推进回来后可继续编辑。`
- 使用 `ElMessageBox.confirm`，确认后调用阶段变更接口。

### 4.4 后端 changePhase 改造（ProjectService.java L358-390）

新增两类校验，失败返回明确错误（建议直接抛业务异常，前端 ElMessage 提示）：

1. **相邻阶段校验**（严格逐级，D4/D10）：
   ```java
   // 从 project_phase 表取当前阶段 sort 与目标阶段 sort
   // 推进：target.sort == current.sort + 1
   // 回退：target.sort == current.sort - 1
   // 否则拒绝：throw "仅支持相邻阶段推进或回退"
   ```
   注意：`changePhase` 目前被"取消项目恢复 ACTIVE"复用（L381-383），恢复场景不改变阶段，不受影响；
2. **当前阶段必填模板已提交校验**（D10，仅推进方向）：
   ```java
   // 查询当前阶段绑定的 required=1 模板类型（project_phase_template_rel）
   // 检查项目在每种必填类型下是否已有提交记录（口径见需求文档 §9）
   // 未提交 → throw "当前阶段必填材料未提交：xxx"
   ```
   回退方向不做材料校验。

### 4.5 接口与日志

- 仍调用 `PUT /api/project/{id}/phase`，body 传 `targetPhaseId`（前端根据当前阶段 ±1 计算）；
- `OperationLogService` 记录不变（ACTION_CHANGE_PHASE，"阶段变更：旧 → 新"），详情页时间线零改动。

### 4.6 前端按钮置灰与提示

- 推进按钮在必填材料未提交时置灰（`:disabled="!requiredTemplatesSubmitted"`），并可在按钮旁/下方给出提示文案（"立项材料未提交，无法推进"）；
- 计算 `requiredTemplatesSubmitted` 的数据：详情接口如已有模板提交状态则直接使用；否则新增一个轻量只读字段（如 `missingRequiredTemplates`）随 detail 返回（参考现有 changePhase 的 missingRequiredTemplates 校验逻辑，可复用）。

## 6. 风险与回滚

| 风险 | 等级 | 缓解 |
|---|---|---|
| 压缩宽度后小屏仍溢出 | 低 | 保留 flex-wrap 兜底，按钮组右对齐 |
| 相邻校验影响既有自由跳步使用习惯 | 中 | 业务明确接受严格逐级；接口拒绝提示清晰 |
| 必填材料提交口径不确定 | 中 | 需求文档 §9 标注，开发前核对模板提交表 |
| 前端/后端不同步回滚 | 低 | 后端校验与前端按钮配套发布，回滚时一并回退 |
