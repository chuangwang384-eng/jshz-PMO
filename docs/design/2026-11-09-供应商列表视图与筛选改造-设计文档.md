# 供应商列表视图与筛选改造设计文档

日期 2026-11-09 · 版本 v1.0 · 对应需求：[2026-11-09-供应商列表视图与筛选改造-需求文档](../requirements/2026-11-09-供应商列表视图与筛选改造-需求文档.md)

## 1. 设计原则

1. **最小改动**：只动列表页 `SupplierList.vue` 与 `GET /api/supplier/list` 的入参，不动表结构、不动详情页、不动权限规则。
2. **单一数据源**：视图切换、排序、筛选全部落在 URL 无关的组件状态；筛选条件与接口参数一一对应，不做前端二次过滤。
3. **向后兼容**：列表接口新增参数均为可选且有默认值，其他调用点（详情页「同城对端」候选、新增弹窗初始绑定候选）不传新参数时行为不变。

## 2. 后端设计

### 2.1 接口入参扩展（`SupplierController.list`）

```
GET /api/supplier/list?keyword=&typeId=&cityId=&onlyReviewed=&sort=&page=&size=
```

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `onlyReviewed` | boolean | `false` | `true` 时只返回存在评价记录的供应商 |
| `sort` | string | `name` | `name` = 名称升序；`updated` = 更新时间倒序（旧行为） |

### 2.2 查询实现（`SupplierService.pageSuppliers`）

```java
if (onlyReviewed) {
    // 子查询而非 join：与 MyBatis-Plus 分页的 count 语句天然兼容，不会因 join 放大行数
    wrapper.inSql(Supplier::getId, "SELECT supplier_id FROM supplier_review");
}
if ("updated".equalsIgnoreCase(sort)) {
    wrapper.orderByDesc(Supplier::getUpdateTime).orderByDesc(Supplier::getId);
} else {
    wrapper.orderByAsc(Supplier::getName).orderByAsc(Supplier::getId);
}
```

- 排序均追加 `id` 兜底，避免同名/同更新时间在翻页时抖动。
- `onlyReviewed` 用 `IN (子查询)` 而不是 `JOIN`：`page()` 的 count 语句由 MyBatis-Plus 生成，`inSql` 会被原样带进条件，`JOIN` 则需要手写 XML，收益为零。
- 默认排序由 `update_time DESC` 改为 `name ASC`（贴合原型「按名称排序」）。影响面已核实：`SupplierDetail.vue` 两处候选清单（同城对端、初始绑定）不传 `sort`，改为按名称排序对选择体验更友好，无逻辑依赖原顺序。

### 2.3 状态字段（1.0.37.20 起不再展示）

**不加库字段，也不展示徽标。** `reviewCount` 仍由 `enrich()` 在列表阶段批量算出（评分行需要），但前端不再据此推导状态：1.0.37.19 曾展示「合作中 / 待评估」，1.0.37.20 按 Owner 要求移除，`statusOf()`、`.status-pill`、`.card-status` 全部删除。列表行右侧只保留「查看详情」按钮。

## 3. 前端设计（`SupplierList.vue`）

### 3.1 结构

```
el-card（唯一白底面板）
├─ .filter-row      搜索框(300) + 类型(150) + 城市(150) + 重置 + [右侧] 新增供应商 / 类型管理
├─ .view-row        仅看已评价（左） + 列表视图/卡片视图 胶囊切换（右）
├─ el-divider
├─ .summary-row     共 N 家供应商（左） + 排序下拉（右，无边框）
├─ 列表视图 .sup-list → .sup-row × N   （或）
├─ 卡片视图 .card-grid → .sup-card × N
└─ 分页 total/sizes/prev/pager/next/jumper
```

### 3.2 状态与交互

| 项 | 实现 |
| --- | --- |
| 筛选对象 | `filters = { keyword, typeId, cityId, onlyReviewed, sort }` |
| 输入即搜 | `onKeywordInput` 400ms 防抖，回车立即 `handleSearch`；组件卸载时清理定时器 |
| 视图切换 | `viewMode` + `localStorage['supplier-view-mode']`，取值仅 `list`/`card`，非法值忽略 |
| 排序 | `el-select`（`sort-select`）无边框样式，选项「按名称排序 / 按更新时间排序」 |
| 行点击 | 整行 `@click` 进详情；「查看详情」按钮 `@click.stop` 同样进详情（防止冒泡重复跳转） |
| 类型图标 | 按 `typeBizKey` 映射：HOTEL→OfficeBuilding、PRINT→Printer、MEDIA→VideoCamera、IMAGING→Camera、FLEET→Van、TICKET→Ticket，自定义类型回退 Files |
| 属地行 | `[province, cityName, contact]` 去空后 ` · ` 连接；全空显示「未填写属地与联系人」 |
| 评分行 | 有评价：★ + `avgStars` + `（N条评价）`；无评价：「尚无评价」 |
| 状态徽标 | **1.0.37.20 起不展示**（原型有，Owner 二次确认去掉）；行右侧仅「查看详情」 |

### 3.3 视觉规范（对齐 1.0.37.17 客户列表改造口径）

- 行间只留 1px 横向分隔线 `#eef1f5`，无纵向边框、无斑马纹。
- hover 背景 `#f7f9fc`；最后一行去掉分隔线。
- 视图切换选中态：浅灰胶囊 `#f1f2f5` + 深色文字加粗；未选中为灰字，hover 转深。
- 「查看详情」为朴素按钮（白底、`#dcdfe6` 边框、圆角 8px），不做主色实心，避免抢注意力；行右侧只有这一个元素，纵向贴行首对齐。
- 卡片视图沿用原卡片（封面 140px + 名称/类型 + 属地 + 星级），封面右上角不再叠加状态徽标。

### 3.4 分页

`size` 默认 12 → 10，页容量 10/20/50（列表视图一屏信息密度更高；卡片视图 10 个/页仍可接受）。

## 4. 兼容性与风险

| 风险 | 处理 |
| --- | --- |
| 默认排序变化影响详情页候选清单顺序 | 已核实无顺序依赖；按名称排序更易查找 |
| `onlyReviewed` 子查询命中评价表 | `supplier_review` 有 `idx_review_supplier(supplier_id)` 索引，`IN` 子查询走索引 |
| 自定义类型无 `bizKey` | 图标回退 `Files`，不报错 |
| 老浏览器 localStorage 不可用 | `try/catch` 包裹，失败时按默认列表视图运行 |
| 前端已发布但后端未发布 | 新参数会被旧后端忽略 → 筛选/排序静默失效。**因此本次前后端必须同版本发布（1.0.37.19）** |
