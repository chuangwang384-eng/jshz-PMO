# 企业合规模板可视化维护技术设计 V1.0

日期：2026-11-05；任务：COMPLIANCE-VISUAL-20261105；状态：设计待审阅，未实施。
依据：[需求文档](../requirements/2026-11-05-企业合规模板可视化维护-需求文档.md)。

## 1. 基线与设计原则
代码核查基线为codex/personal-dashboard-v11 / 3e8bb1c及现有未提交改动；生产状态不由本设计推断。现有ComplianceTemplateEditor暴露草稿、修订及编号；ComplianceV4Service使用不可变发布模板和执行快照，模板节点包含stage、source_anchor，模板有row_version与source_document_version_id。

取消用户操作概念，不删除底层不可变历史。共享编辑内容与当前生效内容分开保存；编辑、提取和收口不改写员工执行快照。不改公共登录和既有个人执行权限。

## 2. 前端结构
将ComplianceTemplateEditor拆为文档工作区容器、阶段目录/卡片画布、事项属性面板、来源对照面板、候选导入对话框、员工预览与存量选择对话框。仅维护一个工作区状态，不在多个组件复制整树。

模型使用稳定UUID作为阶段/事项/选项标识；顺序显式保存。默认字段和更多设置分层；原文JSON不暴露为输入框。SortableJS作为拖动候选，实施时核实Vue适配包维护状态、许可证和锁文件；避免仅因Star高引入整个业务平台。拖动和按钮共用同一排序函数。

工作区状态包括documentId、editRevision、savedRevision、生效标识、groups、nodes、选中项、dirty、saving、conflict及提取状态。输入防抖自动保存，同一文档只允许一个保存请求在途，后续合并排队；响应仅在文档ID及请求序号匹配时应用。生效先等待保存队列完成，再以最新savedRevision提交；失败保留编辑内容。离开前存在未保存输入时提示，不承诺离线跨设备恢复。

## 3. 拟议数据增量（尚未迁移）

| 对象 | 建议字段与约束 |
| --- | --- |
| compliance_template_workspace | document_id主键，content JSON、row_version、content_schema_version、updated_by/at、selection_resolved |
| compliance_template_binding | document_id主键，active_template_version_id可空、row_version；唯一生效指针 |
| compliance_template_selection_log | 文档、被选模板、其他历史ID、操作人/时间、请求ID唯一；收口审计 |
| 来源复核数据 | 工作区节点source结构含documentVersionId、anchor、excerpt、kind、reviewStatus；漏页确认绑定来源版本和提取结果摘要 |

名称为设计候选，实施前读取实际目标元数据、数据量及索引再定稿。阶段采用workspace JSON显式groups，避免复用现有VARCHAR(32)阶段枚举容纳自由名称。生效模板节点仍需保存稳定分组信息，可采用新增group_code/group_name/order字段或模板结构快照；必须在迁移脚本/实体/快照读取中统一，禁止只改前端。source_anchor现有VARCHAR(500)可能不足以容纳长摘录；实施须核对真实结构并提供兼容扩容/结构化方案，不静默截断JSON。

工作区整体上限、事项/选项/摘录长度沿用现有可接受约束并由后端统一验证；拖动排序不允许重复ID、悬空阶段或条件引用越界。未来扩展条件逻辑不在本轮开放。

## 4. 拟议API契约
下列为设计接口，尚未实现。统一放在/api/compliance/v4/documents/{id}/template-workspace下。

| 方法/后缀 | 语义 |
| --- | --- |
| GET / | 返回共享编辑结构、rowVersion、生效摘要、权限能力、是否需存量选择 |
| PUT / | body含expectedRowVersion、content及requestId；自动保存，不生效 |
| POST /activate | expectedRowVersion＋requestId；原子生成不可变模板并切换唯一生效指针 |
| POST /extract | 生成候选，返回来源版本、提取摘要、漏页与候选；不覆盖工作区 |
| POST /merge-candidates | 选择的候选及添加/合并目标，带expectedRowVersion；幂等合并 |
| GET /legacy-candidates | 维护人获取存量模板摘要与授权预览 |
| POST /select-existing | 选中ID＋expectedRowVersion＋requestId；首次收口，保留其他历史 |

员工新建入口增加唯一active-template查询；既有version接口保留兼容读取，但新建清单服务必须在事务中校验请求仍为该文档当前生效指针，若已经切换则返回409并让员工重新确认。原执行读取继续按已固定模板/快照，不改为动态指针。其他历史新建调用要统一限制，不能绕过唯一模板。

HTTP和业务码遵循现有ApiResponse；409表示编辑冲突或模板已变化，403/404保持资源策略。错误不回传原件路径、敏感摘录或凭据。

## 5. 事务与并发
自动保存采用document_id＋row_version条件更新，冲突不覆盖。生效在同一事务锁用户、来源文档、工作区及绑定行（沿用现有锁顺序，实施前核对其他写链），检查最新来源权限/状态、待核对项和漏页确认，创建不可变模板及节点、更新唯一指针和审计后一次提交。任一步失败整体回滚，旧指针仍可用。请求ID带内容摘要去重，重复请求返回既有结果，内容不一致返回冲突；相同内容生效可无操作返回，避免无意义历史膨胀。

OCR/文件解析放在生效事务外；提取前捕获来源版本和授权，落候选时再检查来源版本及权限。文件更新或撤权导致旧结果不能合入，明确提示重新核对。提取候选以来源版本＋锚点＋规范化摘录摘要去重；稳定ID不能用列表位置重排后再生成。所有来源引用与复核状态必须由后端校验关联，禁止信任客户端任意文件路径。

## 6. 来源确认与文件更新
右侧使用现有授权预览能力，按PDF页/Word段落或表格行定位，无法精确定位时展示授权原件及可读锚点，明确降级。引用绑定实际知识文档版本，不能只链接当前文件。原版本缺失时展示不可定位提示，不假装定位成功。

扫描页/失败页提示与复核记录持久化，重新生成或更换来源使相关确认失效。候选复核后的文本或引用改变需重新核对。上传新文件不自动替换已生效模板或已有清单；工作区提示来源更新、提供提取差异入口，生效前明确核实来源依据。

## 7. 存量迁移与发布
先只读盘点每文档全部模板、状态、执行引用、来源版本、孤儿节点及重复编码。无候选创建空工作区；唯一候选可初始化编辑内容并保留原生效关系；多个候选标记需人工选择，不能按更新时间擅自丢弃。仅发布模板可初始化active指针；未生效候选只初始化工作区。选择时归入历史的是管理可见性标记，不删除原表记录、不破坏既有execution.template_version_id。未完成选择期间保持兼容入口，选择提交后员工仅见唯一生效模板。

采用增量表/字段→兼容后端→工作区初始化/人工选择→新前端→收口旧新建入口的分阶段发布。迁移需版本化脚本、重复执行护栏、备份、目标库元数据核实和独立审批；本设计不授权自动迁移生产。

回滚优先切回前端入口并保留新增数据；旧前端的多模板入口不能恢复绕过新生效指针的新建行为。必须使用兼容后端，保留旧执行和历史，不DROP表或批量恢复旧快照。具体开关与回滚制品在施工发布方案中确定。

## 8. 验证与文档交付
验证包含自动保存失败/重试、快速切文档旧响应、两账号并发冲突、生效末次输入、重复/并发生效、来源更新/撤权、部分OCR漏页确认、候选去重、跨阶段排序、存量选择幂等及原清单逐字段不变。数据库测试在独立实例运行；真实Edge无API拦截覆盖选择文档→编辑→自动保存重登→预览→生效→员工新建，另一既有执行不变。

性能测试用现有允许最大事项规模验证输入流畅、排序、保存及预览；阈值在施工前依据现有约束确定，不能编造达标数据。架构、部署、API、数据字典、权限矩阵和交接需随实施同步。本轮只文档，测试/构建/迁移/部署均未执行。
