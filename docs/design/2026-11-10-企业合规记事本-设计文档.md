# 企业合规记事本设计文档

2026-11-10 · 待实施

## 现状与边界

前端入口为 EnterpriseCompliance.vue，规范文档由 KnowledgeDocList.vue 展示，MaintenanceBoard.vue 负责候选和已发布事项。现有分组缺文档标题时回退到数字占位。收藏沿用 knowledge_favorite。旧单条删除会物理删除事项及责任人，因此批量撤下需要独立业务入口。现有模板工作区和其清空功能独立。项目基本信息位于 ProjectDetail.vue，旧 compliance_item.project_id 和旧执行清单的 project_id 无法直接表达一份文档绑定及独立项目待办。

## 页面与数据流

- 企业合规要求默认打开「合规记事本」，保留规范文档库及维护入口。记事本包含文档筛选、已隐藏切换、事项卡片、来源引用和批量推送。收藏变更事件立即刷新记事本和筛选项。
- 维护端按文档返回真实标题。对历史缺失文档显示可辨识的来源状态和记录 ID。按文档撤下按钮使用服务端全量数量，确认前展示目标文档和数量。
- 项目选择器只显示真实参与且文档绑定兼容的项目。项目详情在基本信息内展示文档名及待办列表，即使现有基本信息分组随阶段折叠也提供可访问入口。
- 事项内容按纯文本渲染。引用跳转通过知识文档现有授权与版本校验，已失效来源显示状态。

## 拟议数据模型

| 结构 | 键与用途 |
| --- | --- |
| 已发布事项 | 在 compliance_item 的既有状态模型中扩展撤下状态及撤下人、时间，具体枚举和列名以实施时核实为准。历史记录追加撤下操作，候选原文保留。 |
| 个人隐藏 | 新增关系，以用户 ID 与稳定事项 ID 唯一约束。查询只读当前员工的隐藏状态。重新收藏时仍沿用个人隐藏偏好。 |
| 项目文档绑定 | 新增绑定表，以项目 ID 为主键，保存来源文档 ID、绑定时名称、操作人和时间。项目首次推送事务内写入。 |
| 项目合规待办 | 新增待办表，以项目 ID 与稳定来源事项 ID 唯一约束。存来源文档/版本引用、标题和内容快照、处理状态、操作者、创建及更新时间、乐观锁序号。 |

本期采用待处理、已完成两种项目状态，复用项目现有访问边界及操作记录能力。项目待办保存必要快照和来源锚点，原件由知识库管理。

## 拟议接口与事务

| 能力 | 契约 |
| --- | --- |
| 记事本查询 | 以会话用户为准，通过文档访问、收藏与已发布状态过滤；支持文档 ID、隐藏视图与分页。 |
| 隐藏与恢复 | 对事项 ID 幂等更新当前用户的隐藏关系。 |
| 清空预览与提交 | 维护人权限和文档权限双校验。预览返回标题、全量条数及集合版本。提交校验版本，集合变化时返回冲突并重新确认。事务内批量撤下、写审计和返回实际数量。 |
| 可推送项目 | 按真实成员关系过滤并返回绑定兼容性。项目全量查看豁免仅用于读取。 |
| 推送事项 | 输入项目 ID、同一文档下的事项 ID 列表。服务端重新检查项目真实参与关系、文档权限及事项发布状态。锁定项目行，校验或建立绑定，写快照并依唯一约束去重，返回新增与跳过数量。来源并发撤下与推送采用一致的锁顺序，批次失败整批回滚。 |
| 项目待办读写 | 按项目权限读取，按参与关系处理，变更带编辑序号。打开原文件时另校验来源权限。 |

项目权限实现复用负责人、创建人、协助人和历史执行人关系，提取真实成员判定供项目选择器和推送接口共用。现有 ProjectService.isProjectMember 有管理员快捷放行，直接复用会扩大推送范围。项目读取权限与来源文档权限均通过后才返回快照正文与引用，来源权限撤销时保留快照但对该用户隐藏内容。原件读取再次独立校验。

## 迁移、发布与验证

1. 新增状态和关系表采用增量迁移，先验证旧数据兼容、重复运行、唯一约束、索引及失败回滚。数据库元数据、API 与权限文档在实施时同步。
2. 旧执行数据清理单独实施。先禁用旧执行新增入口、写接口和提醒投递，确认在途处理排空及旧版实例退出。只读核对目标库、行数与引用关系。在同一事务内按依赖顺序清理 compliance_execution_reminder、compliance_execution_event、compliance_execution_task 和 compliance_execution。执行前独立确认具体生产范围及影响，按已确认口径无需备份。已提交的旧测试数据删除不可恢复。保留旧模板、工作区、收藏、解析及已发布事项。
3. 使用隔离 MySQL 与真实浏览器验证需求 AC01–AC07。补充双账号隐藏隔离、项目关系撤销、重复推送、跨文档并发首次绑定、预览后发布集合变化、旧提醒关闭以及清理范围的回归。生产上线后验证健康、路由、权限拒绝与只读结果。
4. 应用回退使用上一版制品，保留新表与状态以支持恢复发布。先验证旧版对撤下状态的过滤与对新数据的兼容。旧入口和提醒必须持续关闭，避免回退后重新产生旧执行数据。
