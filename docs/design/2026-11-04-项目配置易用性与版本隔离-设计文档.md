## 1. 实际基线与设计约束

代码基线 `8c49755`。前端入口 `frontend/src/views/project/ProjectConfig.vue`，向导 `components/StepWizard.vue`、`TemplateBindStep.vue`，共享状态 `frontend/src/stores/projectConfig.js`。服务端入口 `backend/src/main/java/com/jshz/expert/controller/ProjectController.java` 与 `service/ProjectService.java`。

已核实：`createType/updateType` 直接保存 sort；`createPhase` 创建即启用；类型阶段关联可清空；材料读取支持类型专属和 type_id=0 通用回退；`validatePhaseForType` 在未配流程时放行；`missingRequiredTemplates` 在筛选 required 后才回退；推进代码比较公共阶段 sort，而非类型阶段关联顺序。上述行为与新规则有差异。数据库实际类型、约束、所有运行端调用尚需施工前核验，本文不把 Java 实体当作生产元数据。

保留 Vue、现有组件、Java 服务和 MySQL 技术栈。新增一个配置聚合服务与规则解析器，逐步抽离相关逻辑，避免全面重构 ProjectService。保留图形/表格入口，但共享同一个草稿和提交接口。

## 2. 领域决策与旧 ADR 的关系

本轮细化既有“类型—阶段—材料要求”，不把“材料要求模板”和“项目内业务内容”混用。

- 类型流程为显式有序列表；空列表只允许未发布草稿，不能作为“全部阶段”的运行信号。
- 阶段要求模式：`INHERIT` 沿用通用、`CUSTOM` 类型独立、`NONE` 无要求。先解析模式和完整清单，再筛必填。
- 项目快照是项目运行规则的权威来源；公共阶段/模板 ID 保留为关联标识，名称、类别和规则从快照读取。
- 通用要求在创建项目时解析并冻结；修改通用要求不回写已有项目。

本设计在本次范围内替代 `2026-11-02-项目配置板块图形化改造-架构决策记录.md` 的 ADR-001“仅前端、不新增模型”、ADR-005“影响预览延期”，细化 ADR-003 三步向导，保留其配置与内容解耦原则及 ADR-004 双视图。原文保留为历史，不伪装为已施工的新现状。

## 3. 拟议数据模型

优先采用不可变 JSON 快照以减少新关联表；实施前结合实际 MySQL 元数据验证 JSON、索引和长度约束。下列命名为拟议，不是已存在表。

| 对象 | 字段与约束 | 用途 |
| --- | --- | --- |
| project_config_state | 固定单行 id；epoch BIGINT | 配置写锁与乐观并发版本。初始化后所有配置写入/项目快照创建遵循同一锁协议。 |
| project_type_config_revision | id；type_id；revision；schema_version；definition JSON；created_by/time；唯一(type_id,revision) | 不可变类型配置；definition 保存有序阶段和三模式，CUSTOM 保存完整材料清单快照。 |
| project_type 扩展 | active_config_revision_id；sort 唯一非空 | 当前发布版本指针；位置 1～N。 |
| project_config_snapshot | project_id 唯一；source_revision_id 可空；schema_version；effective_config JSON；config_hash；origin；created_at | 每项目一个不可变运行快照；存量标 LEGACY_BASELINE。 |

effective_config 包含 typeId、创建时 typeName、有序 phases[{phaseId,name,position,mode,requirements[{templateId,name,templateType,required,position}]}]。项目资料仍保存原 projectId/phaseId，业务文件不复制。快照不存密码、业务附件正文或用户材料。

阶段/模板后续停用仅限制新配置选用；删除增加快照引用保护，已引用时以停用代替物理删除。执行查询不能因字典停用过滤掉旧快照节点，名称不能回查公共字典覆盖快照。材料类别含义改变必须保留旧 schema_version 的解析能力，不能简单把未知类别当成完成。

## 4. 原子配置提交与排序

向导草稿只在浏览器内存中，临时新阶段使用 clientKey。刷新/关闭提示未保存，不默认将草稿或业务内容写入本地持久存储。一次请求携带 expectedEpoch、requestId、类型信息/目标位置、有序阶段和每阶段要求模式；新阶段携带 clientKey/name。

服务端事务：权限与请求校验 → 锁定 state 行 → 比较 expectedEpoch → 校验名称与字典引用 → 创建公共阶段并解析 clientKey → 写不可变类型版本 → 调整类型位置 → 更新发布指针与 epoch → 写既有审计记录 → 提交。任一步失败全部回滚。相同 requestId 使用受约束的幂等记录返回第一次结果；相同键不同请求摘要拒绝，不能重复新建。幂等记录需纳入迁移与保留策略，不能只靠前端禁用按钮。

排序由服务器维护，客户端提交“目标位置”或完整 ID 序列，禁止直接盲写任意 sort。持有全局锁后计算最终 1～N。为避免唯一约束在交换中冲突，先将受影响位置写入经溢出检查的临时正整数区间，再写最终名次，同一事务完成；禁止逐条提交。新增、移动、删除以及旧接口适配都必须经过相同路径。删除类型仍先遵守现有项目引用阻拦。

前端只采用提交后的权威结果，不自行叠加顺移。并发过期返回 409，保留草稿并展示差异；不自动覆盖他人的更新。全局锁是本期简单实现，配置操作较少；隔离测试记录锁等待与项目创建耗时，后续有证据再拆锁。

## 5. 统一解析与项目运行

提供 `resolveEffectiveConfig`：按阶段模式选择通用/自定义/空清单，保留全部选填信息，返回一个可预览、可冻结的 DTO。预览和项目创建复用同一解析器；发布前验证阶段非空、阶段不重复、材料引用与类别有效、CUSTOM 非空、NONE 不携带隐藏绑定。

创建项目事务持有 state 锁并读取一致的当前类型版本与通用配置，解析后同时写项目和快照；失败不留下裸项目。快照 hash 基于规范化序列化内容，仅用于一致性校验，不充当权限或认证凭据。

项目详情、阶段列表、默认首阶段、阶段合法性、向前相邻校验、回退、缺失资料提示及材料写入阶段校验统一使用项目快照。阶段推进用快照 position，不再用公共阶段 sort；必填检查读取当前阶段的快照要求。专家/供应商/预算、附件/富文本的完成口径沿用需求第2节，避免借本次改造暗改业务。

所有项目配置读取仍需项目级读取权限；新聚合读接口不直接复用管理员配置接口放宽权限。快照缺失或无法解析应明确返回可诊断错误，不能静默回读实时字典。普通项目编辑不可改变类型并替换快照；旧调用传相同 typeId 可兼容，实际换型返回明确业务错误。此限制及现有换型使用情况需隔离验收和发布审批说明。

重点防止旁路：扫描 ProjectService、项目详情页/API、导出、历史、阶段回退、附件/文本保存、项目复制和批处理的所有配置访问；项目复制如存在，应作为新项目重新解析当前配置，不默认拷贝旧快照。

## 6. 拟议接口与兼容

前缀沿用 `/api/project`；HTTP 状态与错误信封遵守项目已有约定，409 为拟议新增冲突语义。

| 方法/路径 | 用途与关键契约 |
| --- | --- |
| GET /config/types/{id}/definition | 管理员编辑聚合，返回 epoch、当前版本、显式流程、三模式、实际要求。 |
| POST /config/definitions/preview | 验证草稿，返回解析结果和结构差异，不写字典/版本。 |
| POST /config/definitions | 创建类型并一次保存完整配置，返回最终类型/阶段映射/顺序/epoch。 |
| PUT /config/types/{id}/definition | 一次保存已有类型新版本，要求 expectedEpoch/requestId。 |
| PUT /config/types/order | 全局排序；完整 ID 集合及 expectedEpoch，缺失/重复/未知 ID 拒绝。 |
| GET /{id}/configuration | 项目权限校验后返回项目快照及来源说明，供项目运行页面使用。 |

以上路径施工前检查路由冲突和 SecurityConfig 规则。写入沿用 project:manage，项目创建/推进沿用原权限；不扩大字典读权限。预览同样执行管理权限和输入校验。

旧 `/config/types`、`/{id}/phases`、`/phases/{id}/templates` 等写接口不得继续直接改表。兼容适配层将它们转换为当前完整定义的新版本提交，并统一锁、模式和位置处理；无法表达三模式的空绑定旧请求应明确拒绝并引导升级，不能猜测是 NONE 还是 INHERIT。旧客户端兼容窗口、调用方清单和停用方案须在施工时记录。读接口按原响应结构兼容，新字段在聚合接口提供。

## 7. 迁移、发布与回滚设计

后续施工提供独立迁移脚本、只读盘点脚本、迁移结果校验及补偿脚本；本次没有生成可执行生产迁移。迁移前以目标库元数据确认表结构、事务引擎、排序范围、重复名称/位置及历史悬空引用。

1. 隔离库备份恢复演练后执行扩展结构迁移；冻结配置维护与新建/换型写入口的兼容窗口，但保持普通查询在线。蓝绿部署本身不能消除跨版本写入竞争。
2. 按旧有效流程规则固化每个类型的显式阶段列表；无关联类型取迁移时全部启用阶段。保留 phaseId，不改业务材料关系。
3. 当前类型有专属绑定映射 CUSTOM，否则 INHERIT。旧“专属全选填却被后端回退通用必填”的显示/校验矛盾必须列差异清单：既有项目按迁移时实际后台执行清单冻结，新建项目版本按三模式正确解析；差异由负责人复核，不能静默修正历史规则。
4. 为存量项目生成 LEGACY_BASELINE 快照，检查当前阶段、历史阶段/资料引用、异常类别。任何无法确定顺序和规则的项目阻断切换，人工决策后重跑。原始异常报告受控保存，不含附件正文。
5. 按旧 `(sort,id)` 稳定顺序重排 1～N，再添加唯一/非空约束。迁移重复执行保持快照和版本不覆盖；使用迁移批次和唯一键检查，校验数量、hash、业务表前后行数。
6. 部署读取快照的新版本并验证所有入口；停止旧版本写入后切流，观察并完成登录/权限/核心页面/推进回退验证，再开放维护及创建。生产数据库迁移和部署均另行审批。

回滚优先使用支持快照的新后端关闭配置维护功能，继续服务已有快照项目；保留新增结构与数据。旧后端不理解快照和 NONE，不能直接恢复旧包/旧前端后继续写入。若需回退旧逻辑，须先确认新建项目和新配置不存在或完成经批准的数据补偿，备份恢复会影响业务写入，必须单独审批。发布前提供兼容回退构建，不承诺任意旧包可无损回滚。

## 8. 实施拆分、测试与完成门槛

建议依次实施：元数据与调用链盘点 → 解析器和迁移 → 快照运行链路 → 聚合保存/唯一排序 → 向导/预览 → 隔离验收。阶段未全部通过前不对生产开放新入口，不能先单独上线就地新增而保留隐式全阶段规则。

| 测试层 | 必测内容 |
| --- | --- |
| 服务单元 | 三模式、全选填、当前阶段必填、空流程、快照名称稳定、顺序邻接与回退。 |
| 真实 MySQL 集成 | 唯一键交换、并发排序/同名/保存与创建交错、事务失败回滚、幂等重试、迁移重复运行和异常阻断。 |
| 前端组件 | 逐阶段确认、草稿保持、无结果新建、取消、错误定位、冲突保留输入、预览与空/加载失败区分。 |
| 真实隔离端到端 | A1～A9；两个账号并发维护；无管理权限直调写接口；不可读项目直调快照；旧项目与新项目对照推进。 |

## 9. 施工决策补充（2026-11-04）

- 新增离线迁移入口，无启动自动回填或 HTTP 迁移接口；旧全选填与公共 sort 顺序差异须在预检报告中逐项复核。公共 sort 与类型顺序不一致时，迁移不会悄悄改变既有推进行为。
- 旧分步类型写 API 按第6节适配为完整版本：名称/位置更新保留模式，非空流程保留已有阶段规则、额外阶段默认沿用通用，非空专属绑定明确转 CUSTOM。空流程/空绑定拒绝并引导新版明确模式。旧创建将当时启用阶段固化，不跟随新增公共阶段。全部可见类型配置入口共用聚合向导；通用字典维护仍保留。
- 名称上限按隔离库实际字段 varchar(50) 设为50；项目普通编辑不能改阶段，统一走推进/回退校验，避免绕过材料检查。
- 新增 definition-context 管理读接口，提供 epoch、排序列表、通用清单与阶段引用数量；权限与其他管理聚合接口一致。
- 快照读取检查 schema_version 与规范化 JSON 的 SHA-256，缺失、损坏或未知版本明确拒绝，不自动回退实时配置。
- 已有项目的类型名称也冻结；项目类型展示位置仅管理列表生效。首次使用者的人工易用性验收仍待负责人执行。
