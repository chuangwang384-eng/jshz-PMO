## 二、需求 2：新增「管理员设置」一级菜单收拢 6 个管理功能

### 2.1 方案（已确认：方案 A）

新增父路由 `/admin`（title「管理员设置」），将 6 个现有管理页面迁移为其 children，路径统一迁至 `/admin/*` 下。旧路径完全不保留、不加重定向。

### 2.2 路由结构设计

```js
{
  path: '/admin',
  name: 'admin-settings',
  redirect: '/admin/experts/manage',
  meta: {
    title: '管理员设置',
    permissions: ['expert:manage', 'audit:view', 'approval:audit', 'approval:config', 'user:manage', 'role:manage']
  },
  children: [
    { path: 'experts/manage',  name: 'experts-manage',  component: ExpertManage,  meta: { title: '专家管理',   permissions: ['expert:manage'] } },
    { path: 'audit/downloads', name: 'audit-downloads', component: AuditDownloads, meta: { title: '下载留痕',   permissions: ['audit:view'] } },
    { path: 'approval/manage', name: 'approval-manage', component: ApprovalManage, meta: { title: '审批管理',   permissions: ['approval:audit'] } },
    { path: 'approval/config', name: 'approval-config', component: ApprovalConfig, meta: { title: '审批流配置', permissions: ['approval:config'] } },
    { path: 'users',           name: 'users',           component: UserManage,    meta: { title: '用户管理',   permissions: ['user:manage'] } },
    { path: 'roles/manage',    name: 'role-manage',     component: RoleManage,    meta: { title: '角色管理',   permissions: ['role:manage'] } }
  ]
}
```

- 二级菜单顺序：专家管理 → 下载留痕 → 审批管理 → 审批流配置 → 用户管理 → 角色管理（与用户截图一致）
- 父路由 `meta.permissions` = 6 码并集：普通账号无任一权限码 → `buildMenuTree` 整组过滤，侧边栏不出现「管理员设置」；直链访问被路由守卫拦截跳 `/experts`
- 子路由保留各自 `meta.permissions`，页面组件 import 与功能零改动
- 现有 `buildMenuTree` / `SideMenuItem.vue` / 路由守卫 均无需改动（机制已支持）

### 2.2.1 父路由 component 说明

`/admin` 父路由**不设置 component**（与 `/profile` 个人中心先例一致）：子路由组件直接渲染到 `App.vue` 第 70 行全局 `<router-view />` 中。6 个管理页面均为独立整页，无需公共布局包裹；父路由仅作菜单分组与 redirect 载体。

### 2.2.2 空菜单规避说明

`buildMenuTree`（`utils/menu.js` 第 14-33 行）目前**不会**自动隐藏 children 全被过滤的父节点，仅按自身 `meta.permissions` 过滤。因此方案 A 强制父路由携带 6 码并集权限：普通账号在父级过滤阶段即整体剔除，从根本上避免"可点击但内容为空的菜单"出现，无需改动 `buildMenuTree`。
