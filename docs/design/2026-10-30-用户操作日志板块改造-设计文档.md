## 2. 后端设计

### 2.1 自定义注解 `@OperationLog`

文件：`backend/src/main/java/com/jshz/expert/annotation/OperationLog.java`（新建）

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface OperationLog {
    /** 操作类型，对应 OperationLogService.ACTION_* 常量 */
    String actionType();
    /** 描述模板，支持 SpEL，如 "新增供应商：#{#body.name}" */
    String actionDesc();
    /** 目标对象类型，如 SUPPLIER */
    String targetType();
    /** 目标 ID 的 SpEL 表达式，如 "#body.id"；为空则记 null */
    String targetId() default "";
}
```

SpEL 约定：
- `#body` 指方法第一个参数（`@RequestBody` 的 Map/实体），取参走 `#body.字段名`；
- 参数名取自 `pjp.getArgs()` 与局部变量表（`LocalVariableTableParameterNameDiscoverer`），无参数名时按下标 `#p0/#p1` 兜底；
- `create` 等无现成 ID 的方法可传空，`targetId` 记 null（与现状一致）。

### 2.2 切面 `OperationLogAspect`

文件：`backend/src/main/java/com/jshz/expert/aspect/OperationLogAspect.java`（新建）
依赖：`pom.xml` 新增 `spring-boot-starter-aop`（Spring Boot 3 / Java 17 适配）。

核心逻辑（伪代码）：

```java
@Aspect
@Component
public class OperationLogAspect {
    @Around("@annotation(operationLog)")
    public Object around(ProceedingJoinPoint pjp, OperationLog operationLog) throws Throwable {
        Object result = pjp.proceed();          // 先执行业务，仅成功路径记录（与手动埋点语义一致）
        try {
            AuthUser user = findAuthUser(pjp);   // 遍历 pjp.getArgs() 找 @AuthenticationPrincipal AuthUser
            String desc = resolveSpel(operationLog.actionDesc(), pjp.getArgs());
            String targetId = resolveSpel(operationLog.targetId(), pjp.getArgs());
            operationLogService.record(user == null ? null : user.getUserId(),
                    user == null ? null : user.getUsername(),
                    operationLog.actionType(), desc,
                    operationLog.targetType(), targetId, null);
        } catch (Exception e) {
            log.warn("AOP 操作日志写入失败: {}", e.getMessage());   // 降级，不影响主业务
        }
        return result;
    }
}
```

关键设计决策：
- **切点**：`@annotation` 仅命中标注方法，现有手动埋点方法不标注 → 天然零重复；
- **记录时机**：方法正常返回后记录（抛异常不记录），与现状手动埋点语义一致；
- **容错**：切面内 try-catch 降级 + warn，写失败不影响业务；
- **IP 获取**：沿用 `IpUtils`（`request` 为 null 时跳过 IP，与现有部分调用一致）。

### 2.5 AuditController 角色校验

文件：`backend/src/main/java/com/jshz/expert/controller/AuditController.java`

```java
@GetMapping("/operations")
public ApiResponse<?> page(@AuthenticationPrincipal AuthUser authUser, ...) {
    if (authUser == null || !authUser.getRoles().contains("SUPER_ADMIN")) {
        return ApiResponse.error(403, "无权限访问操作日志");
    }
    // ... 原分页逻辑 + excludeActionTypes = ["LOGIN","LOGOUT"]

```

- 判定用**角色编码** `SUPER_ADMIN`（复用 `PermissionService.SUPER_ADMIN_CODE`），**不使用** `isAdmin()`（已降级字段）；

### 2.6 SQL 迁移

文件：`database/migration/20261030_audit_log_refactor.sql`（新建，幂等）

```sql
-- 1) 移除 ADMIN 角色的 audit:view 绑定（幂等：不存在则无影响）
DELETE FROM role_permission
WHERE role_id = (SELECT id FROM role WHERE code = 'ADMIN' AND deleted = 0)
  AND permission_id = (SELECT id FROM permission WHERE code = 'audit:view' AND deleted = 0);

-- 2) SUPER_ADMIN 为代码内全权，无需绑定（不写 role_permission）
```

> 若 `role_permission` 表无 `deleted` 字段或字段名不同，开发时按表结构调整 WHERE；DELETE 天然幂等可重复执行。

### 3.2 路由/菜单权限收紧（仅超管可见）

文件：`frontend/src/router/index.js`、`frontend/src/App.vue`、`frontend/src/utils/menu.js`、`frontend/src/store/auth.js`

方案：
1. 路由 `meta` 增加角色约束：`meta: { ..., permissions: ['audit:view'], roles: ['SUPER_ADMIN'] }`；
2. `router.beforeEach` 守卫：`meta.roles` 存在时，校验 `authStore.hasRole(role)`（`store/auth.js` 已有 `hasRole` getter），不匹配拦截；
3. 菜单构建 `buildMenuTree` 同步支持 `meta.roles` 过滤（App.vue / menu.js），非超管菜单不渲染；
4. `hasRole('SUPER_ADMIN')` 为唯一入口判定，ADMIN 即使拥有 `audit:view` 也看不到入口。

## 4. 权限收紧汇总

| 层 | 改动 | 效果 |
|---|---|---|
| 数据层 | 移除 ADMIN 的 audit:view 绑定 | ADMIN 权限码层面失去该权限 |
| 接口层 | AuditController 校验 SUPER_ADMIN | 直调接口也返回 403 |
| 前端路由 | meta.roles 守卫 | 非超管访问被拦截 |
| 前端菜单 | buildMenuTree 角色过滤 | 非超管菜单不可见 |

四层叠加，确保"仅超级管理员可见"在数据、接口、路由、菜单各层一致。

## 5. ADR 决策记录

| 编号 | 决策 | 备选 | 理由 |
|---|---|---|---|
| ADR-1 | 后端查询排除 LOGIN/LOGOUT，历史数据保留 | 前端过滤 / 物理删除 | 改动最小、可追溯、无数据清洗风险 |
| ADR-2 | AOP 与手动埋点共存，本次仅供应商启用注解 | 全部迁移 AOP | 最小改动、零回归；统一迁移单独立项 |
| ADR-3 | `@OperationLog` 注解 + SpEL 描述，Controller 层切面 | 手动埋点补齐 / 静态描述 | 可动态表达操作对象，与现有 record 语义一致 |
| ADR-4 | 仅超管可见：数据+接口+路由+菜单四层收紧 | 仅前端隐藏 | 防越权直调，体验与安全一致 |
| ADR-5 | 操作级留痕，不做字段级 diff | 记录变更前后值 | 成本低、表结构不变；字段 diff 二期再评估 |
| ADR-6 | 仅成功路径记录（方法正常返回后写日志） | 失败也记录 | 与现有手动埋点语义一致，避免误导审计 |

## 6. 风险与回归清单

| 风险 | 说明 | 缓解 |
