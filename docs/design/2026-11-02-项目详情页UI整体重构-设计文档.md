### 3.3 后端接口与数据模型

- Controller：`<LOCAL_PATH>`（`/api/project`：列表、详情 GET `/{id}`、阶段 PUT `/{id}/phase`、取消 PUT `/{id}/cancel`、预算 PUT `/{id}/budget`、专家/供应商/资料/合同 CRUD、配置 `/config/**`）
- Service：`<LOCAL_PATH>`（1912 行）
- 详情接口 `detail()`（L197-226）返回：`experts / suppliers / docs / contracts / budget / phases / timeline / canManage / canAdvance / canRollback / phaseHistory / missingRequiredTemplates`
- 主表 `Project` 字段：`id / name / category(ONLINE|OFFLINE) / typeId / startDate / endDate / ownerId / creatorId / phaseId / status(ACTIVE|CANCELED|DELETED) / cancelReason / cancelTime / budgetAmount / createTime / updateTime`
- **无"项目编号"字段、无"余额"字段**（`budgetOf()` 仅返回 `budgetAmount / expertFee / supplierFee / actualTotal`）

### 3.4 生命周期与预算逻辑

- 阶段表 `project_phase`：6 阶段（立项/预算/筹备/进行中/结算/已完成），`sort` 排序；
- 推进规则（`ProjectService.changePhase` L373-436）：仅相邻推进，推进前校验必填模板，缺失拒绝；权限 `isOwnerOrExecutor`；
- 回退规则：相邻与跨级均允许，原因必填，取消态回退可恢复 ACTIVE；
- 必填来源：`project_phase_template_rel.required=1`；
- 预算登记：`PUT /api/project/{id}/budget`（负责人/执行人，不可为负）；
- 实际支出：`actualTotal = expertFee + supplierFee`（专家劳务费 + 供应商费用）。

### 3.5 样式现状

- `main.js`（18 行）仅引入 `element-plus/dist/index.css`，**无任何自定义全局 css 文件**；
- `src` 下无 `.css/.scss/.less` 文件，Element Plus 主色**未覆盖定制**（默认 `#409EFF`）；
- `App.vue`：`body { background:#f0f2f5 }`，侧边栏 `#001529/#002140`，`.header` 背景 `#fff`，`.main` padding 16px；
- `.card-block/.stat-box/.template-block` 等公共样式类仅定义在 ProjectDetail.vue scoped 内；`.page-head/.page-title/.page-sub` 各页面各自定义，无全局共享。

### 3.6 标题重复现状

- 顶栏 `App.vue` 统一渲染 `route.meta.title`；
- 11 个页面内容区重复同名标题（明细见需求文档 FR-10），Directory.vue 为卡片级重复；
- 多数页面有 `.page-sub` 说明文字可保留；RoleManage 无说明文字；AnnouncementDetail 无说明文字。

## 4. 设计原则

1. 信息架构优先：先定页面骨架与区块层级，再定视觉细节；
2. 复用优先：组件/接口/权限/数据逻辑全部复用现有实现；
3. 纯展示层改造：不触碰状态流转、权限判定与数据契约；
4. Token 化：视觉规范沉淀为全局 token 文件，避免复制粘贴；
5. 渐进不破坏：不改动其他模块，保持现有功能可用。

## 6. 项目详情页设计

### 6.1 页面信息架构（新布局）

```
┌──────────────────────────────────────────┬──────────────┐
│ ① 概览头部（项目名称/状态/大类/类型/负责人/时间 + 操作）  │              │
├──────────────────────────────────────────┤  ⑦ 右侧辅助栏  │
│ ② 核心数据卡（4 项财务）                  │  · 项目动态    │
├──────────────────────────────────────────┤  · 项目成员    │
│ ③ 生命周期 Stepper（6 阶段横向）          │  · 当前待办    │
├──────────────────────────────────────────┤  · 相关附件    │
│ ④ 阶段任务卡（完成状态/必填/待办/负责人/入口）│              │
│ ⑤ 阶段资料区（模板内容，随所选阶段切换）    │              │
├──────────────────────────────────────────┤              │
│ ⑥ 基本信息（4 分组卡）                    │              │
├──────────────────────────────────────────┤              │
│ ⑧ 预算与实际支出（数字 + 进度条）          │              │
├──────────────────────────────────────────┤              │
│ ⑨ 业务明细（专家/供应商/结算合同/时间线）    │              │
└──────────────────────────────────────────┴──────────────┘
```

- 网格：`grid-template-columns: 1fr 320px; gap:16px`；
- 右侧辅助栏 `position: sticky; top: 72px`；
- 1366px 以下辅助栏可收窄至 300px 或降级为区块下移（断点由实施时确认）。

### 6.2 概览头部

- `el-page-header` 返回按钮保留；项目名称提升为 22px 主标题；
- 状态徽标：当前阶段（蓝）+ 生命周期状态（有效/已取消）；
- 操作区按钮分组：推进下一阶段（primary）、编辑项目（default）、更多操作（下拉：回退阶段 / 取消项目）；
- 取消项目保留现有二次确认弹窗（原因必填、写入时间线）；
- 取消标签与取消原因展示保留。

### 6.3 核心数据卡

- 4 卡片网格（`repeat(4, 1fr)`，小屏自动换行）；
- 数据映射：预算总额 `detail.budget.budgetAmount`；实际支出 `detail.budget.actualTotal`；余额 `budgetAmount - actualTotal`（前端计算）；使用率 `actualTotal / budgetAmount * 100`（保留整数）；
- 使用率进度条嵌入最后一张卡或单独行内展示，超 100% 警示色。

### 6.4 生命周期 Stepper

- 使用 Element Plus `el-steps` 或自绘横向步进条（实施时优先 `el-steps` + 自定义状态样式）；
- 状态判定：遍历 `detail.phases`（按 `sort` 升序），`sort < 当前phaseId.sort` 为已完成、`sort === 当前` 为当前、`sort > 当前` 为未开始；
- 交互：点击阶段 → 设置"查看阶段"状态（本地变量，仅影响展示）→ 阶段资料区切换渲染该阶段模板内容；
- 视觉区分：当前阶段蓝色高亮 + 名称加粗；查看阶段加光圈/描边（如 `box-shadow: 0 0 0 4px rgba(64,158,255,0.35)`）；
- 未开始阶段内容区：`el-empty`「该阶段尚未开始」；已完成阶段：隐藏编辑/上传/删除按钮（原 `canAdvance` 才显示的操作，在非当前阶段一律隐藏）。

### 6.5 阶段任务区域

- 阶段任务卡字段与数据源：

| 字段 | 数据源 |
|------|--------|
| 阶段名称 | 当前/查看阶段 `phase.name` |
| 完成状态 | 三态徽标（已完成/进行中/未开始） |
| 必填配置 | 该阶段模板 `required=1` 的完成情况（`docsOfPhase` / 富文本 / 预算 / 专家 / 供应商） |
| 待处理任务 | `detail.missingRequiredTemplates`（当前阶段）映射为任务项 + 解决入口 |
| 阶段负责人 | 项目负责人 `owner` + 执行人 `project_executor` 列表（标注"项目级"） |
| 操作入口 | 推进下一阶段 / 回退阶段（遵循现有权限与二次确认） |

- 解决入口映射：
  - 预算类缺失 → 唤起"登记预算"弹窗；
  - FILE 附件缺失 → 定位到该阶段上传区域；
  - EXPERT 专家缺失 → 唤起"调派专家"弹窗；
  - SUPPLIER 供应商缺失 → 定位供应商关联入口；
  - RICH_TEXT 缺失 → 定位富文本编辑区。
- 阻塞原因条：复用后端文案生成，展示于任务卡底部。

### 6.6 基本信息分组

- 4 分组卡（`repeat(4,1fr)`）：
  - 项目属性：名称 / 大类 / 类型；
  - 项目人员：负责人 + 执行人头像组（`el-avatar` 或标签，取姓名首字，多色底），“+N”展示其余；
  - 项目时间：开始 / 结束；
  - 项目状态：当前阶段徽标 + 生命周期状态徽标。
- 移除 `el-descriptions` 密集表格样式。

### 6.7 预算与实际支出

- 三数字 + 进度条布局（`budget-row`）；
- 数字卡：预算总额、实际支出、剩余预算；
- 进度条：预算使用率（`el-progress` 或自绘）；
- 空状态：`budgetAmount` 为空/0 时展示 `el-empty`「尚未登记预算」+「登记预算金额」按钮（`canAdvance` 可见）；
- 进度条超过 100%：警示色 + 文案提示超支金额。

### 6.8 右侧辅助栏

| 卡片 | 数据源 | 说明 |
|------|--------|------|
| 项目动态 | `detail.timeline`（operation_log 倒序） | 取最近若干条，时间格式化 |
| 项目成员 | `detail.experts`? 否——项目负责人 + `ProjectExecutor` 列表 | 成员头像+姓名，负责人标注 |
| 当前待办 | `detail.missingRequiredTemplates` | 逐项 + 解决入口，可跳转 |
| 相关附件 | `detail.docs`（全部未删资料） | 文件名 + 下载链接 |

> 注：`detail` 接口当前返回 `experts/suppliers/docs` 等，执行人列表如未在详情返回中直接暴露，实施时优先复用现有已返回字段（`owner` + 执行人来源待实施时核对 `ProjectExecutor` 查询接口），不新增后端改动；若确需执行人列表而详情接口未返回，先与 owner 说明再决定补充方式（默认保持纯前端，缺失时展示负责人）。

### 6.9 业务明细区

- 四个区块沿用现有 `el-table`，容器统一为 token 化卡片：
  - 专家名单：列与操作不变（登记劳务费、移出，`canManage`）；
  - 供应商名单：列与操作不变（填费用、移出，`canManage`）；
  - 结算合同：列与操作不变（上传文件、发起审批、改敏感字段，`canAdvance`）；
  - 项目时间线：`el-timeline` 保留。
