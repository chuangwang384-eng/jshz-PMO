## 1. 现状关键事实（2026-11-09 核实）

- 类型→阶段：配置表 `project_type` / `project_phase` / `project_type_phase_rel` / `project_phase_template_rel`；实体 `Project.typeId`/`phaseId`；配置接口 `ProjectController` L331-400，实现 `ProjectConfigurationService`。
- 阶段推进：`PUT /api/project/{id}/phase` → `ProjectService.changePhase`，权限 `isOwnerOrExecutor`（ProjectService.java L1683）。
- 执行人：`project_executor` 子表，创建/更新时写入（ProjectService.java L344-355 / L448-455）；预算明文可见同权限（L243/L937）。
- 简历解析：`POST /experts/resume/parse` → `ResumeParseService`（pdf/doc/docx/ppt/pptx/jpg/png，20MB；PDFBox+POI+Tesseract 回退；`OllamaService` qwen2.5:7b，`OLLAMA_URL`/`OLLAMA_MODEL`/`OLLAMA_TIMEOUT` 环境变量，`format:json`）→ 前端 `ExpertList.vue` 预填人工确认。**无专家库自动匹配**。
- 文件存储：`ProjectStorageService`（`expert.project.storage-dir`，`project_<uuid>.<ext>`）。
- 日程：现有代码无 schedule/agenda 概念。

## 3. 数据库设计（迁移脚本 `database/migration/20261109_project_schedule_stage.sql`，幂等）

### 3.1 新表

```sql
-- 项目日程文件（一个项目多份历史，current=1 为生效份）
CREATE TABLE IF NOT EXISTS project_schedule (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  project_id BIGINT NOT NULL,
  file_name VARCHAR(255) NOT NULL,        -- 原始文件名（展示用，不参与路径）
  file_path VARCHAR(255) NOT NULL,        -- 项目资料库随机名
  file_size BIGINT,
  mime_type VARCHAR(100),
  parse_status VARCHAR(20) NOT NULL DEFAULT 'PENDING',  -- PENDING/PARSING/DONE/FAILED
  parse_message VARCHAR(500),
  raw_result JSON NULL,                   -- 原始解析输出（回溯用）
  is_current TINYINT NOT NULL DEFAULT 1,
  uploaded_by BIGINT,
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY idx_ps_project (project_id, is_current)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 参会专家（确认后正式记录；confirmed=0 为候选）
CREATE TABLE IF NOT EXISTS project_speaker (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  project_id BIGINT NOT NULL,
  schedule_id BIGINT NULL,                -- 来源日程；手动录入为 NULL
  expert_id BIGINT NULL,                  -- 匹配到的专家档案，NULL=库外
  expert_name VARCHAR(100) NOT NULL,
  role VARCHAR(20) NOT NULL,              -- CHAIR 大会主席/HOST 大会主持/SPEAKER 大会讲者/DISCUSSANT 讨论嘉宾
  segment_title VARCHAR(255) NULL,        -- 议题/段落
  segment_time VARCHAR(100) NULL,         -- 时间段文本
  confirmed TINYINT NOT NULL DEFAULT 0,
  created_by BIGINT,
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY idx_spk_project (project_id, confirmed),
  KEY idx_spk_expert (expert_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 3.2 停用（不删，本版只置 NULL / 下线入口）

- `project.type_id` 全部置 NULL（行数=0，实际无操作）；列与 `project_phase_id`（`phase_id`）保留。
- `project_type` / `project_phase` / `project_type_phase_rel` / `project_phase_template_rel` / `project_executor` / `project_phase_history` 表保留不动。
- 新增内置阶段种子（供后续推进用，仅一条）：`project_phase` 追加 `AGENDA_UPLOAD 日程上传`（幂等 INSERT ... ON DUPLICATE）；本期不再关联类型。

## 4. 后端设计

### 4.1 解析服务 `ScheduleParseService`（新建，复用简历解析组件）

```
入口：POST /api/project/{id}/schedule（上传，multipart）
      POST /api/project/{id}/schedule/{scheduleId}/parse（触发解析）
      GET  /api/project/{id}/schedule（当前日程+候选列表）
      PUT  /api/project/{id}/speakers（确认保存：整表覆盖式提交 confirmed 记录）
      POST /api/project/{id}/speakers（手动补录一条）
      DELETE /api/project/{id}/speakers/{speakerId}
```

流程：
1. **文本提取**：复用 `ResumeParseService` 的格式分发（PDFBox/POI/Tesseract 回退），抽公共方法或直接调用其内部提取器；pptx 逐 slide 提取**表格单元格文本**（示例日程为表格布局，直接按单元格行列还原「时间/主题/讲者/主持」行，优于整页文本）。
2. **规则打底**（不依赖模型，确定性）：按列头关键词（讲者/主持/主席）与「多人同段」规则先行分类——同段内讲者列人数>1 → 全部 `DISCUSSANT`；页脚「大会主席：X」→ `CHAIR`。
3. **LLM 语义兜底**：非表格/复杂版式时调 `OllamaService`，prompt 要求输出 JSON 数组 `[{name, role, segmentTitle, segmentTime}]`，role 枚举受限；`format:json`；超时/失败降级为「仅规则结果 + FAILED 提示可手动录入」。规则结果与 LLM 结果合并去重（同人同名取规则优先）。
4. **姓名归一化**：去空格/全半角/中间点「·」统一；示例中「谭　波」类全角空格必须 trim。
5. **专家库匹配**：归一化后按 `expert.name` 精确等值匹配（一次 IN 查询）；命中填 `expert_id`，未命中 `expert_id=NULL`。不做模糊匹配，避免误绑（AGENTS §6.4 候选原则）。
6. 写 `project_schedule.raw_result` 与候选 `project_speaker(confirmed=0)`；再次解析先清旧的未确认候选。

### 4.2 权限与既有代码改造

| 点 | 改法 |
|----|------|
| `changePhase` 授权 | `isOwnerOrExecutor` → `isOwnerOrCreator`（owner_id=登录人 或 creator_id=登录人）；`canAdvance` 输出同步 |
| 预算/费用明文可见 | 原 executor 集合 → owner+creator+assistants（`project_assistant` 已有） |
| 创建/更新 | 删除 executorIds 写入分支；body 中 `typeId` 忽略；新建 `phase_id` 固定=AGENDA_UPLOAD 阶段 id |
| 类型配置接口 | `ProjectController` L331-400 各 `/config/*` 返回 410 Gone（带提示文案），`ProjectConfigurationService` 停用注入 |
| 导出/列表/详情 | 返回字段移除 type/executor 相关；`executorId`/`typeId` 筛选参数移除 |

### 4.3 安全与合规（对齐 AGENTS §4/§6）

- 上传：类型白名单（同简历解析格式集）、20MB 上限、文件名仅存展示字段、存储走 `ProjectStorageService` 随机名防穿越；下载走现有受控出口。
- 解析全程内网 Ollama，**数据不出公司**；日志不打印简历/日程原文，仅记文件名、大小、状态、耗时。
- AI 输出一律 `confirmed=0` 候选，人工确认后才算业务数据；再次解析不清已确认记录（保留人工成果）。

## 5. 前端设计

| 页面 | 改动 |
|------|------|
| `ProjectEdit.vue` | 移除类型/当前阶段/执行人三控件及其联动（`loadTypeFlow` 等删） |
| `ProjectList.vue` | 移除类型列/筛选、执行人筛选；阶段列显示新口径：`日程上传·{待上传/解析中/待确认/已完成}`（由 `schedule.parseStatus` + 是否存在 confirmed 派生，后端输出 `stageFlag`） |
| `ProjectDetail.vue` | 移除类型/执行人展示、阶段配置入口；新增「日程与参会专家」卡：上传区（格式/大小提示）→ 解析状态与重新解析 → 候选专家表（姓名/角色下拉/议题/匹配档案列可搜索改绑/库外标记+「去建档」按钮预填跳转）→ 确认保存 → 正式参会专家展示（按角色分组）；解析失败提示 + 手动补录入口 |

「去建档」复用简历解析的预填交互：路由带 query 预填姓名/单位（单位日程未必有，仅姓名+备注来源），新建后不自动回绑，用户返回详情页手动改绑（本期简化，回绑列为后续优化）。

## 6. 测试要点

- 解析单测：示例 pptx（单元测试用解包 XML 提取的单元格文本做 fixture）→ 断言 9 人角色分类正确；全角空格姓名归一化；多人同段=DISCUSSANT 规则；页脚主席识别。
- 异常路径：Ollama 停用/超时 → 降级为规则结果+FAILED 提示；非白名单格式/超限 400；重复上传覆盖 current；再次解析不清已确认记录。
- 权限：协助人/普通成员调 `PUT /{id}/phase` 403；owner/creator 可；预算明文对协助人可见。
- 回归：专家/供应商关联、文档、合同、预算、合规挂接不回归（不依赖 type/executor，理论零影响，需跑通验证）。
