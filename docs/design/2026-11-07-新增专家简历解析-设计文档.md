## 2. 后端设计

### 2.1 解析接口

`POST /api/experts/resume/parse`（multipart，字段 `file`）：

1. 校验：扩展名白名单 pdf/doc/docx/ppt/pptx；大小 ≤20MB；登录即可（与新增专家入口一致）。
2. 抽取：
   - 文本：复用 `KnowledgeDocTextExtractor` 的抽取逻辑（该类为静态工具，直接调用；不落库）。
   - 图片：按类型分别抽取内嵌图片字节（PDFBox `PDResources` 遍历页面图片；docx 遍历 `XWPFPicture`；PPT 遍历 `XSLFPictureShape`），转 JPEG 缩略图返回 base64（仅前 3 张候选，单张 ≤200KB）。
3. 文件与解析均在内存/临时文件完成，请求结束即删除；不做任何持久化。
4. 返回：

```json
{
  "fields": { "姓名": "张三", "单位": "…", "科室": "…", "职称": "…", "联系方式": "…" },
  "photoCandidates": ["<base64-1>", "<base64-2>"],
  "hitCount": 3
}
```

### 2.2 字段启发式解析（ResumeParseService）

按行拆分文本后逐行匹配，**首个命中即停**：

| 字段 | 策略 |
| --- | --- |
| 姓名 | ① `姓名[:：\s]` 标签行取值；② 首行若为 2~4 个汉字且不含通用词（简历/个人/求职）则视为姓名 |
| 单位 | `单位\|工作单位\|任职单位\|所在单位\|工作经历` 标签行；或含"医院/研究院/研究所/大学/学院/中心"的首个短行 |
| 科室 | `科室\|所在科室\|科室/部门` 标签行 |
| 职称 | `职称\|专业技术职务\|职级` 标签行 |
| 联系方式 | 全文正则：`1[3-9]\d{9}` 手机号（首个）；否则邮箱正则 |

- 所有候选值修剪空格/冒号残留；超长截断（姓名 ≤20 汉字沿用现有校验）。
- 无命中字段直接不返回（前端不填）。
- 解析整体超时 8s（防止畸形文件拖死线程），超时按失败返回。

### 2.3 头像候选启发式

抽取的图片按以下条件过滤排序，取前 3 张：

1. 尺寸在 80×80 ~ 1500×1500 之间（排除 logo/横幅/背景图）。
2. 宽高比 0.5~1.8（接近方形/竖版人像）。
3. 位于文档前 2 页/前 3 张者优先。
4. 文件体积 >5KB（排除装饰图标）。

不做人脸检测（无 CV 服务），**候选必须经用户点击确认**才写入证件照位。

## 3. 前端设计

- 弹窗顶部（三类照片上传区上方）增加「上传简历自动解析」行：`el-upload`（accept 限定、auto-upload=false）+「解析」按钮 + 解析状态文案。
- 解析响应处理：
  - `fields` 中仅填充**当前为空**的表单字段；已填字段弹出提示"已有内容未覆盖"。
  - 填充后字段 label 旁显示小字「来自简历」（纯样式标记，提交后不存储该标记）。
  - `photoCandidates` 横向缩略图列表 + 「使用此照片」；点击后转为既有证件照 picked 文件/预览逻辑（复用 `onPickPhoto('photo', …)` 的数据流，构造 File 对象走同一链路，审批归档不变）。
  - 失败/超时：红色提示 + 保留手动填写。
- 弹窗其余部分（身份证上传、审批提交）零改动。

## 4. 测试计划

| 类型 | 内容 |
| --- | --- |
| 后端单测 | ResumeParseService：标签行解析（姓名/单位/科室/职称）、手机号/邮箱正则、畸形文本不抛错返回空、超时 |
| 接口测试 | 真实 PDF/Word/PPT 简历各 1 份（隔离环境）：字段命中、头像候选返回、超限/格式白名单拒绝 |
| 边界 | 扫描件 PDF（无文本层）→ fields 空 + 提示；加密 PDF → 失败提示；20MB 边界 |
| 前端 | 填充不覆盖已填字段；头像候选确认后走既有审批照片链路；解析失败不阻塞手动提交 |
| 回归 | 既有新增专家（手动）、审批流、照片归档 |
| 安全 | 权限（登录即可）、文件类型校验、审计日志（不含简历内容）、确认无临时文件残留 |

## 5. 风险与兼容

- **解析准确率**：启发式对"标签行规范"的简历命中率高，自由格式简历可能漏抽——产品定位即"候选填充 + 人工确认"，不承诺全自动。
- **无 OCR**：扫描件/图片简历解析不到文本（fields 为空），UI 明示原因；接入 OCR 是后续独立决策（需求 §5）。
- **隐私**：简历不落盘、不留存、日志不记录内容；候选图片仅在响应中返回给当前登录用户。
- **性能**：同步解析 8s 超时内完成；20MB PDF 抽图片在内存中处理，需关注峰值内存（单请求 ≤20MB，可接受）。
- **遗留**：`expert_info` 无新增字段；无迁移脚本。
