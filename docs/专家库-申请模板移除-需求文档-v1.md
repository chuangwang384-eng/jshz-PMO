## 2. 背景与问题描述

员工在"专家库"板块对专家信息进行修改时，**即使不点选"申请模板"下拉框**（默认值为"不使用模板（展示全部字段）"），提交后依然会触发审批流。

用户据此怀疑：**"申请模板"相关 UI 与需求板块是否没有必要存在，可以删除？**

经代码静态核查（<LOCAL_PATH>

- 员工修改专家信息默认走审批流（审批触发仅取决于角色是否拥有 `expert:edit` 权限 + 审批流启用开关），与模板选择无关；
- `templateId` 允许为空（`null`/`undefined`），为空时跳过模板字段子集校验，照常创建申请单进入审批流；
- 申请模板在整个链路中仅承担"员工表单字段子集过滤器"职责（选了模板只显示模板内字段），不参与审批开关、不参与核心数据落库（仅记录来源 `templateId`，可空）。

### 3.2 审批流触发逻辑（核查结论）

- 触发链路：前端关闭详情弹窗检测 `dirty` → `submitEditChange()` → `submitApprovalRequest`（body 含 `templateId: editTemplateId.value || undefined`）→ 后端 `POST /api/approval/requests` → `ApplicationService.submitRequest`；
- 判定条件（`checkSubmitEligible`，`ApplicationService.java:293-303`）：未登录拒绝 / 拥有 `expert:edit` 权限的用户拒绝（走直编通道）/ 审批流未启用拒绝——**均与模板无关**；
- 模板仅作可选项：`submitRequest` 中仅当 `templateId != null` 时才调用 `checkTemplateForSubmit` 校验"changes ⊆ 模板字段且模板启用"；`templateId == null` 时跳过校验，照常创建申请单进审批流。

## 4. 必要性评估

**结论：申请模板板块无存在必要，可以删除（连根拔除）。**

评估论据：

1. **模板不参与审批流开关**：员工修改/新增专家默认走审批流，触发条件只看角色与审批流启用开关，模板选择与否不影响审批是否触发；
2. **模板不参与核心数据落库**：仅记录 `application.biz_data.templateId` 来源字段（可空），无外键依赖；
3. **模板 UI 只是字段子集过滤器**，且当前默认"不使用模板=展示全部字段"的行为，与删除模板后的行为完全一致，删除后用户体验无损失；
4. **无其他调用方**：模板 API 仅被 `ExpertList.vue`、`ApprovalTemplateManage.vue` 引用，删除无连带影响；
5. **审批主链路独立**：`ApplicationController / ApplicationService / ApprovalConfig / ApprovalRecord` 均不依赖模板，可完整保留；
6. **无明确未来规划**：申请模板当初为字段筛选用途，无既定扩展规划，删除并在文档中记录决策背景即可。

**风险提示**：历史申请单 `application.biz_data.templateId` 字段将**保留不清理**（A 方案），避免破坏历史数据；删除模板不会影响历史申请单（`ApprovalTemplateService.delete` 注释已明确此设计）。

## 5. 需求范围

### 5.1 本次做什么（In Scope）

1. 删除员工端"修改专家"弹窗中的申请模板下拉框及字段显隐联动逻辑；
2. 删除员工端"新增专家（需审批）"弹窗中的模板下拉、覆盖必填校验前端逻辑；
3. 删除管理端模板管理页 `ApprovalTemplateManage.vue` 及路由 `/admin/approval/templates`；
4. 删除前端模板 API（`api/approval.js` 中 6 个模板函数）；
5. 删除后端 `ApprovalTemplateController` / `ApprovalTemplateService` / `ApprovalTemplate` 实体 / `ApprovalTemplateMapper`；
6. 删除后端审批提交链路中 `templateId` 的解析、透传、校验分支与 `biz_data` 写入逻辑；
7. 清理权限 `approval:config` 中模板相关路径规则（新增迁移文件，保留审批流配置路径）；
8. 员工修改/新增表单**固定展示全部白名单字段**，不做其他限制。

### 5.2 本次不做什么（Out of Scope）

1. 审批流本身保持不变：员工修改/新增专家仍默认走审批流；
2. 管理员直编、管理员免审批新增保持不变；
3. `approval_template` 表结构**保留**，历史数据不清理；
4. 审批流配置页、审批管理、我的申请、历史申请单详情不受影响；
5. `ExpertManage.vue` 的 Excel 导入模板、`project/` 模块的模板功能不属于本需求。
