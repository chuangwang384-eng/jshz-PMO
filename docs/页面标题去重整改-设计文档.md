> 项目：jshz-PMO（景帅会展内部管理系统）
> 文档版本：v1.0（定稿）
> 日期：2026-10-31
> 状态：待实施

## 1. 现状分析

### 1.1 标题渲染机制

| 环节 | 文件 | 位置 | 逻辑 |
|---|---|---|---|
| 顶部导航标题渲染 | `frontend/src/App.vue` | L28 | `<div class="header-title">{{ pageTitle }}</div>` |
| 顶部标题取值 | `frontend/src/App.vue` | L67 | `computed(() => route.meta?.title \|\| '景帅会展内部管理系统')` |
| 侧边菜单标题来源 | `frontend/src/utils/menu.js` | L26-30 | `buildMenuTree` 取 `r.meta?.title` |
| 菜单项渲染 | `frontend/src/components/SideMenuItem.vue` | L14 | `{{ item.title }}` |
| 路由标题定义 | `frontend/src/router/index.js` | 各路由 | 各路由 `meta.title` |

**结论：顶部导航标题与侧边菜单标题同源（`router/index.js` 的 `meta.title`）。**
「顶部导航 vs 内容区标题重复」的判定，等价于「页面内容区静态标题文字 vs 路由 `meta.title`」是否一致。

### 1.2 内容区标题结构现状（3 类）

| 类型 | 页面 | 说明 |
|---|---|---|
| 标准 `page-head > page-title + page-sub` | MyApproval / ApprovalConfig / ApprovalManage / ApprovalTemplateManage / DownloadAudit / MessageCenter / AnnouncementList / AnnouncementManage / ProjectList / ProjectConfig / SupplierList（11 个） | 标题 + 辅助描述 |
| `page-title + 返回按钮` | AnnouncementDetail | 标题旁为返回按钮，无 sub |
| toolbar 内嵌 `page-title` | RoleManage | 标题与操作按钮同在工具栏 |

### 1.3 样式现状（4 组不一致）

| 组 | 页面 | 样式 |
|---|---|---|
| G1 | MyApproval 等 7 个 | flex / baseline 对齐 / gap 12px；标题 17px/600 |
| G2 | ProjectList / ProjectConfig | 单行式 margin-bottom 12px；标题 18px |
| G3 | Announcement 3 个 | 无 scoped 样式定义（全局亦无定义） |
| G4 | RoleManage | toolbar 内嵌，无独立 page-head |

### 1.4 顶部间距现状

- 13 个 page-title 页面根容器均为裸 `<div>`（padding-top=0）。
- 顶部间距**唯一来源**：`App.vue` `.main { padding: 16px }`（L286-288）。
- page-head 自身几乎无 margin/padding（仅 Project 两页 margin-bottom:12px）。

### 1.5 其他标题形式核查

- 无面包屑（el-breadcrumb）、无步骤条（el-steps）。
- el-tabs 5 处均为内容分区用途，不构成标题重复。
- ProjectDetail 使用 `el-page-header`，content 为项目名（业务实体），非页面标题。

## 2. 设计决策（ADR）

### ADR-1 删除与顶部导航逐字重复的内容区标题

- **背景**：14 个页面内容区标题与顶部导航逐字重复，浪费垂直空间且造成视觉冗余。
- **决策**：删除与 `meta.title` 逐字相同的内容区标题；保留辅助描述（page-sub）作为页面辅助说明。
- **理由**：顶部导航已是当前页面名称的唯一权威呈现；内容区标题无附加信息则无保留价值。
- **影响**：11 个带 sub 页面删除标题、保留 sub；RoleManage 删除 toolbar 内嵌标题、保留按钮；AnnouncementDetail 删除标题、保留返回按钮。

### ADR-2 顶部留白全局统一为 12px

- **背景**：顶部 16px 由 `App.vue` `.main` padding 统一控制，全部页面共用。
- **决策**：`App.vue` `.main` 顶部 padding 16px → 12px，全局生效。
- **理由**：改动点唯一、规范统一、未来页面天然继承；4px 差异对无标题问题的页面无副作用。
- **影响**：所有页面顶部垂直留白减少 4px，表格获得更多展示空间。

### ADR-3 复杂页面允许保留差异化标题

- **背景**：部分页面内容区标题承载业务差异（如「全局客户关系网络」「客户关系类型管理」）。
- **决策**：内容区标题表达业务实体名/操作对象/业务差异且与顶部导航文案存在明确差异化时，允许保留。
- **理由**：差异化文案有信息量，删除会造成信息损失；保留符合"复杂页面可以有明确信息层级"的规范。
- **影响**：CustomerRelationGraph、CustomerRelationTypeManage 两个页面文案维持现状。

### ADR-4 卡片类页面删除 card-header 重复标题（自明性保障）

- **背景**：Directory（通讯录）、ProfileCard（个人中心）的 card-header 标题与顶部导航重复。
- **决策**：删除 card-header 重复标题。
- **理由**：已核查自明性——Directory 有 muted 副标题与「本部门成员（N）」区块标题；ProfileCard 有 el-descriptions（用户名/角色/账号ID/注册时间）与「修改密码」按钮，删除标题零信息损失。
- **影响**：两个卡片删除 header 标题，卡片直接展示内容。

### ADR-5 动态标题 fallback 防重复

- **背景**：CustomerDetail 无客户姓名时 fallback「客户详情」与顶部导航重复。
- **决策**：fallback 改为「未命名客户」。
- **理由**：保留信息量（说明对象身份未知），同时避免与顶部导航逐字重复。

## 3. 全局设计规范

### 3.1 职责划分

| 区域 | 职责 |
|---|---|
| 顶部导航栏 | 展示当前页面名称（唯一权威来源） |
| 内容区域 | 业务说明、筛选条件、操作按钮、业务数据 |

### 3.2 标题判定规则（可执行）

1. 内容区标题与顶部导航**逐字相同且无附加信息** → 删除。
2. 内容区标题表达**业务实体名 / 操作对象 / 业务差异**且文案有差异化信息 → 保留。
3. 页面无内容区标题 → 不动。
4. 删除标题后，原标题区块若含操作入口（按钮、返回）→ 操作入口保留。

### 3.3 未来页面开发规范（防复发）

1. 新页面**禁止**在内容区写死与 `meta.title` 相同的标题文字。
2. 页面需要标题时，标题必须表达业务实体/操作对象，或在文案上与 `meta.title` 明确差异化。
3. 页面辅助说明使用统一的 `page-sub` 样式（13px / #909399），不与标题抢视觉层级。
4. 页面顶部垂直留白由全局容器控制，页面内不额外叠加顶部 margin。

## 4. 样式规范（统一后）

### 4.1 page-head 容器

```css
.page-head {
  display: flex;
  align-items: baseline;
  gap: 12px;
  margin: 0 0 12px; /* 与下方内容间距统一 12px */
}
```

### 4.2 page-sub 辅助描述

```css
.page-sub {
  font-size: 13px;
  color: #909399;
}
```

### 4.3 顶部留白

```css
/* App.vue .main */
.main {
  padding: 12px; /* 原 16px，顶部压缩为 12px，四边统一 12px */
}
```

## 6. 实施与验证方案

### 6.1 实施步骤

1. 按第 5 节清单修改对应 Vue 组件（git diff 守门，确认仅目标改动）。
2. 前端构建：`frontend` 目录执行 `npm run build`，核验 dist 产物。
3. 判断 Nginx 是否需要 reload，必要时执行。

### 6.2 验证方案

1. **分辨率验证**：1280×720 / 1366×768 / 1920×1080 三档，重点确认表格列不挤压、工具栏不换行、布局无错乱。
2. **功能回归**：审批、撤回、查看进度、查看对比、权限控制走查不受影响。
3. **无回归确认**：无标题问题的页面（专家库、用户管理等）仅受 4px 留白影响，视觉无副作用。

## 7. 风险与回滚

| 风险 | 等级 | 应对 |
|---|---|---|
| 样式回归（G3 组 Announcement 页面无样式定义） | 低 | 删除标题后补统一 page-head 样式或确认无依赖 |
| 全局 12px 影响无标题页面 | 低 | 已评估仅 4px 上移，无副作用 |
| 删除 card-header 标题导致信息损失 | 低 | 已核查自明性（Directory/ProfileCard） |
| 回滚 | — | git revert 单次提交即可完整回滚 |

## 8. 术语表（Glossary）

| 术语 | 含义 |
|---|---|
| 顶部导航栏 | App.vue 顶部 header 区域，展示 `route.meta.title` |
| meta.title | 路由元信息中的页面标题，顶部导航与侧边菜单的唯一数据源 |
| 内容区域标题 | 页面组件模板中写死的 page-title / card-header 标题文字 |
| page-head / page-title / page-sub | 内容区标题区块的统一样式类 |
| 标题去重 | 删除内容区与顶部导航逐字重复标题的整改动作 |
| 差异化标题 | 与顶部导航文案不同且承载业务差异信息的标题，允许保留 |
| ADR | Architecture Decision Record，架构决策记录 |
