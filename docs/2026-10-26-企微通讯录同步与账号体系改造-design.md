# 企微通讯录同步与账号体系改造 — 设计文档（2026-10-26）

> 目标：把企业微信通讯录（组织架构+成员）同步进系统，以企微 userid 作为每个员工的唯一身份锚点，登录标识从"姓名"切换为"手机号"，彻底解决重名账号问题；同时为后续企微 OTP / 扫码登录（均已论证需另行解决备案域名问题，见 §1.3）预留同一套绑定数据。

- 评审安排：2026-10-27（用户到公司后）；评审重点见 §12 待决问题。

## 1. 背景与问题

### 1.1 现状（已核实代码）

- 登录 = **姓名 + 密码**（`AuthService.login`，BCrypt，JWT httpOnly cookie `expert_token`）；查无此用户且姓名符合格式（2-20 汉字）且密码为初始密码 `111111` 时**自动注册**（`autoRegisterAndLogin`）。
- `sys_user.username` 上有 **uk_username 唯一索引**：**同名员工第二名从今天起就无法注册/登录**（唯一索引冲突后按旧密码校验必然失败）。重名不是"将来会麻烦"，是"现在就不可用"。
- 系统无组织架构、无部门概念；角色走 RBAC（`role`/`user_role`/`permission`，默认角色 EMPLOYEE）。
- `sys_user` 实体已预留 `wecom_userid` 字段（`SysUser.java`，`@TableField("wecom_userid")`）；`/api/auth/wecom/**` 占位接口已放行白名单（`SecurityConfig.java`）。
- 后端目前**无任何 @Scheduled 定时任务**（本项目将首次引入）。

### 1.2 用户真实诉求

1. 便捷获取企微中记录的公司组织架构（部门树 + 人员归属）；
2. 账号与个人一一绑定，消除重名歧义。

### 1.3 为什么是"通讯录同步"而不是"扫码登录"

企微 OAuth 扫码/网页授权要求**可信域名**：必须 ICP 备案且备案主体与企业认证主体一致（企微 2022-06 政策，官方帮助 21611/21316）；公司无备案域名，短期内无法满足。而**通讯录同步是纯服务端出站 API 调用，不需要域名、不需要备案、不开放入站端口**——有企微管理后台权限即可立即实施。扫码登录作为后续可选（备案后），届时企微返回的 userid 与本项目绑定的 userid 天然一致，不做重复建设。

## 2. 目标与范围

**本期做：**
1. 企微通讯录拉取（部门 + 成员详情含手机号）落库，支持手动同步 + 每日定时同步 + DryRun 试算；
2. 组织架构树管理页展示；
3. `sys_user` 增加 `wecom_userid`（唯一）、`mobile`（唯一）身份键；存量用户自动/人工绑定；
4. 登录标识三模式（NAME/COMPAT/MOBILE）切换，配置驱动、可回滚；
5. 企微离职成员自动停用（不删除，保历史外键）。

**本期不做（明确排除）：** 企微 OTP 验证码登录、自建扫码登录、官方扫码（等备案）、消息推送、组织架构回写企微、部门级数据权限、头像/邮箱同步（默认最小必要，见 §12）。

## 4. 接口依据（企微现行 API）

> 旧接口 `user/list`、`user/simplelist` 自 2022-08-15 起**新增 IP 禁止调用**（官方文档 90201 公告），新接入必须用新组合：

| 用途 | 端点 | 说明 |
| --- | --- | --- |
| 换取 access_token | GET `/cgi-bin/gettoken?corpid=&corpsecret=` | 有效期 7200s，进程内缓存并提前刷新；errcode 40014/42001 自动重取重试一次 |
| 成员 ID 列表 | POST `/cgi-bin/user/list_id`（cursor 分页） | 返回 `userid + department[]`；**仅通讯录同步 secret 可调用**（正好匹配我们的凭证选型） |
| 部门列表 | POST `/cgi-bin/department/list_id`（cursor 分页，若不可用则实测退回 `department/list`） | 返回部门 id/name/parentid/order |
| 成员详情 | GET `/cgi-bin/user/get?userid=` | name/mobile/department/position/status；**手机号经通讯录同步 secret 可读**（自建应用 secret 需额外敏感权限，故不选） |

- 官方文档：[获取成员ID列表 96067](https://developer.work.weixin.qq.com/document/path/96067)、[成员详情 90201](https://developer.work.weixin.qq.com/document/path/90201)。
- 批量 `user/get` 逐人调用，批间加节流间隔（几百人规模在频率限制内绰绰有余）；`status`：1 已激活 / 2 已禁用 / 4 未激活 / 5 退出企业 → 2、5 视为离职。

## 5. 数据库设计（`database/migration/20261026_add_wecom_contact_sync.sql`，幂等）

**新表 3 张**（沿用 approval_/supplier_ 模块前缀惯例）：

```sql
-- 企微部门（只存快照，不回写）
CREATE TABLE IF NOT EXISTS wecom_department (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  dept_id BIGINT NOT NULL COMMENT '企微部门id（根=1）',
  name VARCHAR(100) NOT NULL,
  parent_dept_id BIGINT NULL,
  sort_order INT DEFAULT 0,
  status TINYINT DEFAULT 1 COMMENT '1正常 0企微已删除（保留快照）',
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_dept_id (dept_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 成员-部门归属（企微一人可属多部门）
CREATE TABLE IF NOT EXISTS wecom_user_department (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id BIGINT NOT NULL COMMENT 'sys_user.id',
  dept_id BIGINT NOT NULL COMMENT '企微部门id',
  is_main TINYINT DEFAULT 0 COMMENT '1主部门',
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_user_dept (user_id, dept_id),
  KEY idx_dept (dept_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 同步审计日志（每次手动/定时同步一条）
CREATE TABLE IF NOT EXISTS wecom_sync_log (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  trigger_type VARCHAR(20) NOT NULL COMMENT 'MANUAL/SCHEDULED/DRYRUN',
  operator VARCHAR(50) NULL,
  status VARCHAR(20) NOT NULL COMMENT 'RUNNING/SUCCESS/FAILED',
  fetched_users INT DEFAULT 0, created_users INT DEFAULT 0,
  updated_users INT DEFAULT 0, disabled_users INT DEFAULT 0,
  bound_users INT DEFAULT 0, unbound_left INT DEFAULT 0,
  error_msg TEXT NULL, detail TEXT NULL COMMENT 'DryRun 变更清单 JSON',
  start_time DATETIME, end_time DATETIME
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**sys_user 变更（information_schema 判列/判索引幂等）：**
- 加列 `mobile VARCHAR(20) NULL`（AFTER wecom_userid）；
- 加唯一索引 `uk_wecom_userid(wecom_userid)`、`uk_mobile(mobile)`（MySQL 唯一索引允许多个 NULL，未绑定用户不受影响）；
- **删除 `uk_username` 唯一索引**（允许企微同步产生重名用户，改为应用层约束：未绑定通道内姓名唯一）。⚠️ 认证路径结构变更，高风险项，回滚见 §10。

**权限种子**（格式参照 `20261026_add_approval_template.sql`）：新增权限码 `wecom:sync`（一码多路径），路径：POST `/api/admin/wecom/sync`、GET `/api/admin/wecom/sync/status`、GET `/api/admin/wecom/departments`、POST `/api/admin/users/*/bind-wecom`；绑定 ADMIN 角色。

## 6. 后端设计

### 6.1 配置（application.yml + 环境变量，沿用 JWT_SECRET 注入模式）

```yaml
expert:
  wecom:
    corp-id: ${WECOM_CORP_ID:}
    contact-secret: ${WECOM_CONTACT_SECRET:}   # 通讯录同步助手·只读
    sync-cron: "0 30 2 * * ?"                   # 每日 02:30
    sync-cron-enabled: false                    # 上线稳定后由运维打开
    login-mode: ${AUTH_LOGIN_MODE:NAME}         # NAME/COMPAT/MOBILE，见 6.4
```

- `sync-cron-enabled=true` 且 corp-id/secret 为空 → 启动 fail-fast（对齐 JWT_SECRET 校验风格）；
- 新环境变量注入点：`start-backend.bat` + NSSM 服务环境（需管理员/UAC，与 1.005 部署同场操作可顺带完成）。

### 6.2 新增 WeComApiClient（纯出站 HTTP 客户端）

- token 获取 + 缓存（提前 5 分钟刷新）+ 40014/42001 自动重试；分页拉部门/成员 ID；逐人 `user/get`（节流）；只依赖 JDK HttpClient 或现有 http 工具（不引新依赖）。
- **日志纪律**：任何日志不得出现 secret/access_token；手机号一律 `138****1234` 脱敏。

### 6.3 新增 ContactSyncService（同步核心，含 DryRun）

```
run(triggerType, operator, dryRun):
  并发护栏：wecom_sync_log 存在 RUNNING 记录 → 抛"同步进行中"（409 语义）
  1. token；2. 拉部门树 → upsert wecom_department（企微已删 → status=0）
  3. 拉成员 ID 全量 → 逐人详情，按 wecom_userid diff：
     a. 命中已绑定用户 → 更新姓名/手机号/部门归属
     b. 未命中，但企微姓名与本系统「未绑定」用户唯一匹配 → 绑定该存量账号（填 wecom_userid/mobile/部门）
     c. 未命中且无唯一匹配 → 新建（username=姓名, is_admin=0, must_change_password=1,
        初始密码 DEFAULT_PASSWORD(111111), status=1, bindDefaultEmployeeRole——沿用现有默认角色逻辑）
     d. user/get status ∈ {2,5} → status=0 停用
  4. 本次全量中未出现的已绑定用户 → status=0 停用（离职）
  5. upsert wecom_user_department（主部门标记）
  6. 写 wecom_sync_log（DryRun 只写"将变更清单"，不落数据）
```

- 手动同步**异步执行**：接口立即返回 logId，前端轮询 status；
- 触发器：手动接口 + `@Scheduled(cron)`（首次引入，需 `@EnableScheduling`）；定时任务读取 `sync-cron-enabled` 开关；
- 同步/绑定/解绑操作写入 `operation_log`（复用现有审计体系）。

### 6.4 登录标识三模式（AuthService.login 最小改造）

| 模式 | 行为 | 用途 |
| --- | --- | --- |
| NAME（默认/回滚档） | 完全等同现状（姓名 + 自动注册） | 上线初始与回滚 |
| COMPAT（过渡） | 输入匹配手机号格式 `^1[3-9]\d{9}$` → 按 mobile 查；否则按姓名查**未绑定用户**（`wecom_userid IS NULL`），姓名自动注册通道仅对未绑定用户保留 | 1.006 上线后的运行模式 |
| MOBILE（终态） | 仅手机号 + 密码；**关闭自动注册**（账号只来自通讯录同步或管理员创建） | 全员绑定率 100% 后切换（管理页显示绑定率） |

- 停用检查、BCrypt、JWT、cookie、强制改密流程**全部不动**；
- 前端识别模式：接口 `GET /api/auth/wecom/config` → 返回 `{enabled, loginMode, message}`（已在白名单），loginMode 为 NAME/COMPAT/MOBILE 三模式之一（与 AuthService 归一化一致），前端据此切换输入框文案，**前端不写死模式**。

### 6.5 新增接口（新 Controller：WeComContactController，/api/admin/wecom）

| 接口 | 权限 | 说明 |
| --- | --- | --- |
| POST `/sync` `{dryRun}` | wecom:sync | 触发同步（dryRun=true 只试算），返回 logId |
| GET `/sync/status?logId=` | wecom:sync | 运行中进度 / 最近一次结果 |
| GET `/departments` | wecom:sync | 部门树（含每部门人员数） |
| GET `/unbound` | wecom:sync | 未绑定存量用户 + 企微侧未匹配成员（人工指认数据源） |
| POST `/users/{id}/bind-wecom` `{wecomUserId}` | wecom:sync | 管理员人工指认绑定（重名/改名场景兜底） |

### 6.6 存量迁移与绑定策略

- 自动：同步时按「企微姓名 ↔ 系统未绑定用户姓名」**双方唯一**才自动绑定；任何歧义（企微侧重名/系统侧已有同名绑定）→ 进人工指认清单；
- 手动：管理员在管理页为存量账号指认企微成员（测试账号如"张三/测试"可指认或保留不绑定）；
- 不绑定不阻塞登录：COMPAT 模式下未绑定用户仍可姓名登录。

## 10. 风险与回滚

| 风险 | 缓解 |
| --- | --- |
| 删除 uk_username 后重名数据进入 | 唯一性改由应用层保证（未绑定通道内姓名唯一）；回滚重建索引前需确认无重名（已绑定重名数据存在时重建失败——此时回滚为"保持 COMPAT"而非强回 NAME） |
| 企微接口/字段政策再变化 | 端点封装在 WeComApiClient 单点；实施时以实测响应为准 |
| 成员手机号为空（极少数） | 该成员无法手机号登录，COMPAT 下走人工绑定/管理员补录；进同步结果报告 |
| 服务器出口 IP 被企微 IP 可信拦截 | 前置条件里用公司网络出口 IP 配置可信名单 |
| 定时同步失败 | 记 log 不告警中断服务；管理页红色标记最近失败 |
| 出站依赖公网 | qyapi.weixin.qq.com 不可达时手动同步报错提示，不影响正常登录使用 |

**回滚步骤（按层）：** ① 登录回滚：AUTH_LOGIN_MODE=NAME（改 NSSM 环境变量重启后端）；② 功能回滚：sync-cron-enabled=false，同步功能停用（已同步数据无害保留）；③ 结构回滚（可选）：新表 3 张可保留或 DROP；uk_username 仅在无重名数据时可重建。数据库变更均有幂等迁移脚本，无不可逆操作。
