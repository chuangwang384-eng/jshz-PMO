# 项目配置板块图形化改造 ADR

- 日期：2026-11-02
- 状态：已接受
- 范围：<LOCAL_PATH> 项目配置板块（ProjectConfig.vue 及关联前端组件）

---

## ADR-001：图形化改造定位为「辅助理解 + 轻量图形化交互」

- 背景：用户反馈项目配置板块理解难度过高；现状核查确认类型流程配置存在「类型 → 阶段 → 模板」三层关联、全局兜底与类型专属「双层回退」等隐性语义，纯表格/弹窗难以表达。
- 决策：以辅助理解为主，辅以轻量图形化交互（阶段/模板拖拽排序），不新增数据模型，不改后端接口。
- 理由：风险最小、工作量可控；现有 5 张配置表与 `/api/project/config/**` 接口已完整承载业务。
- 后果：前端为主改造；后端零改动；未来如需复杂编排（分支、审批流）再另行评估。

## ADR-002：引入 vue-flow 作为流程可视化库

- 背景：需要横向流程图 + 阶段内模板卡片 + 拖拽排序；项目内已有 ECharts 6.1.0 但非流程编排专用。
- 决策：引入 `@vue-flow/core` 及配套，仅用于流程图形展示与排序；不引入 LogicFlow。
- 理由：vue-flow 轻量（约 30KB）、Vue3 原生、拖拽/连线开箱即用，满足线性阶段流程；LogicFlow 功能更强但体积更大，留待审批流等复杂场景再评估。
- 后果：新增 1~2 个前端依赖；节点/边数据与 `type_phase_rel` / `phase_template_rel` 的 sort 字段双向映射。

## ADR-003：向导化三步配置 + 配置与内容解耦

- 背景：用户提出按「新建项目」流程组织配置：① 定义新的项目类型 → ② 绑定所需的项目流程 → ③ 定义各流程的必填内容。
- 决策：主界面新增「项目类型流程总览图」；新增/编辑类型均复用三步向导（类型信息 → 流程绑定与排序 → 各阶段必填模板）；配置体系严格只做「规则绑定」，模板内容的创建与编辑在模板管理侧完成，运行时内容提交在项目侧完成，均独立于配置体系。
- 理由：与用户诉求一致；消除「内容创建/提交与配置混在一起」的认知负担。
- 后果：向导各步保存仍走现有接口；不在配置体系内新增内容录入能力。

## ADR-004：双模式并存（图形默认 + 表格备选）

- 背景：激进重构会冲击现有操作习惯。
- 决策：图形视图为默认；保留现有表格/弹窗交互作为可切换模式；至少一个版本周期后再评估是否下线旧交互。
- 理由：平滑过渡、可回退。
- 后果：前端需要维护两套视图（共享同一数据源与保存逻辑）。

## ADR-005：影响面预览推迟至 v1.1

- 背景：删除拦截、级联清理、双层回退等约束目前仅在提交时以错误/确认提示出现，操作前不可见。
- 决策：影响面预览（删除/修改前显示受影响类型与项目清单）列为 v1.1 增强项；本期实现迷你流程缩略图与全局总览。
- 理由：控制 MVP 范围，避免一次改动过大。
- 后果：本期删除/修改仍走现有校验与确认提示，设计上预留 v1.1 扩展位。

## ADR-006：显式流程、三种材料模式与项目快照（2026-11-04）

- 状态：已接受（需求人已明确批准D1～D4和方案施工）；实现及隔离技术验收完成，生产未迁移。
- 背景：就地新增公共阶段不能隐式改变其他类型；无材料与沿用通用必须可区分；配置维护不能改变已有项目的执行规则。
- 决策：类型流程显式保存；采用INHERIT/CUSTOM/NONE；创建项目时解析并冻结配置，推进/回退和资料校验统一使用快照；类型排序为事务维护的唯一连续位置。向导完整提交一次事务，旧接口按可确定语义适配为完整版本。
- 关系：本任务范围内替代ADR-001的“仅前端/不新增模型”边界和ADR-005的影响预览延期，细化ADR-003；保留配置与内容解耦、现有技术栈、双视图原则。旧ADR对应2026-11-02历史阶段，不能据其绕过本轮快照链路。
- 后果：必须离线预检并回填存量项目、复核公共排序与全选填差异；新后端不允许缺快照时自动回读实时规则。旧后端不能直接解释新规则，生产发布需要单独审批和兼容回退演练。
