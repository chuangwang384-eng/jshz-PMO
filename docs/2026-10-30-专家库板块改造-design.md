# 专家库板块改造 - 实现设计文档

- 项目：景帅会展内部管理系统（jshz-PMO）
- 日期：2026-10-30
- 版本：v1.0
- 关联需求：专家库板块改造需求文档 v1.0（2026-10-29，已与项目负责人确认）
- 开发遵循：karpathy-guidelines（Surgical Changes、最小改动、不重构无关代码）

## 一、总体结论

后端公告接口已就绪：`GET /api/announcement/effective`（置顶优先+时间倒序，上限 5）、`GET /api/announcement`、`POST /api/announcement/{id}/read`（幂等）。本期不改后端，仅做前端改造 + R-2 前端原子发布。

## 二、需求1：公告栏全局化

### 1.1 新建 AnnouncementBell.vue

- 位置：`frontend/src/components/AnnouncementBell.vue`
- 参照现有 `NotificationBell.vue` 的 el-popover + el-badge 交互范式，数据源用公告接口
- 行为：
  - 打开面板时调用 `getEffectiveAnnouncements(10)` 拉取公告（后端保证置顶优先+时间倒序）
  - 列表项：标题 + 发布时间 + 未读红点（`read === false` 时显示）
  - 点击公告项：先 `await markAnnouncementRead(id)` 再跳转 `/profile/announcements/:id`
  - 面板底部「查看全部」→ `router.push('/profile/announcements')`
  - 公告为空：展示空态提示
- 样式：与 NotificationBell 并列于 `user-area`（已有 gap:12px），保持全局风格

### 1.2 App.vue 挂载与全局未读弹窗

- `user-area` 中 NotificationBell 旁新增 `<AnnouncementBell />`
- onMounted 增加全局未读公告检查（从 ExpertList.vue 迁移）：
  - 非超管且非公告管理员（`!authStore.isAdmin && !authStore.hasPermission('announcement:manage')`）才检查
  - 沿用 sessionStorage key：`jshz_announce_popup_shown_${authStore.id ?? 'anon'}`，存已弹 id 数组，避免会话内重复
  - `listAnnouncements({ page: 1, size: 50 })` 过滤未读且未弹且未过期 → 弹 ElMessageBox → 记录已弹
  - 点击弹窗条目：`markAnnouncementRead` 后跳详情
- import：`listAnnouncements / markAnnouncementRead`（对齐现有 import 风格）

### 1.3 ExpertList.vue 移除

- 删除模板 announcement-banner 区块及样式 `.announcement-banner`
- 删除未读公告弹窗 el-dialog
- 删除 `fetchAnnouncements / checkUnreadAnnouncements / openUnreadAnnouncement / goAnnouncement`（若仅公告使用）及相关 onMounted 调用、sessionStorage 逻辑
- 清理因删除变为未使用的 import（`getEffectiveAnnouncements` 等），避免遗留孤儿代码

## 三、需求2：弹窗视图统一

- 以员工弹窗（editForm + editFieldVisible + handleDetailClose）为基底，删除 `v-if="canEditExpert"` 的管理员独立弹窗
- 合并后：
  - 标题统一「专家详情」
  - 字段渲染统一走 editFieldVisible 模板控制（管理员/超管与员工一致）
  - 保存/编辑：`canEditExpert` 时保存直写免审批（沿用 submitAdminEdit 的 updateExpert FormData 直写逻辑）；普通员工沿用现有提交申请/变更检测流程（handleDetailClose）
  - 「删除专家」按钮：仅 `v-permission="'expert:delete'"` 时展示，删除确认文案与现有 handleAdminDelete 一致（提示照片文件一并物理删除、不可恢复）
  - 照片上传预览等管理员专用控件合并进统一表单（表单模型按角色初始化）
- 注意：保存逻辑分支务必清晰，回归验证管理员直写与员工审批两条链路不串线

## 四、需求3：复制图标

- 每个可复制字段：label 区恢复纯字段名；输入框内使用 el-input 的 suffix 插槽渲染复制小图标（el-icon + CopyDocument 或等价 SVG）
- 图标悬停提示「复制」（el-tooltip 或 title）；点击调用 copyFieldValue 逻辑（navigator.clipboard 优先、execCommand 兜底），成功 `ElMessage.success('已复制')`，空值提示「暂无可复制的内容」
- 覆盖字段：姓名、单位、科室、职称、联系方式、简介、身份证号、银行卡号、银行卡开户行
- 兼容窄屏：suffix 图标固定宽高，避免遮挡输入内容

## 六、发布方案（R-2 前端原子发布）

- 实现完成后 `npm run build` 验证（不重启生产）
- computer-agent 执行 `.\scripts\deploy-frontend.ps1`：先 `-DryRun` 预演，再正式执行
- 禁止 `nginx -s reload`；保留 releases 备份习惯
- 部署后浏览器实测验收

## 七、验收清单（摘自需求文档验收标准）

1. 任意页面右上角可见公告铃铛，可查看列表/未读标记/跳详情并标记已读
2. 存在未读公告时进入任意业务页面弹出提示；超管/公告管理员不弹
3. 专家库首页不再展示公告卡片栏、不再单独触发未读弹窗
4. 管理员/超管与员工详情弹窗字段集合一致；管理员保存免审批直写；员工走审批流
5. 仅拥有 expert:delete 可见删除按钮；删除确认流程不变
6. 复制为输入框内右侧小图标，悬停提示、点击复制成功提示、空值提示
