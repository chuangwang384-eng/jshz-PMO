# 专家库系统正式版开发设计文档

- **日期**：2026-10-20
- **项目**：景帅会展内部管理系统（专家库）
- **状态**：需求已确认（2026-10-20）
- **技术栈**：Spring Boot 3.2.5 + Java 17 + MyBatis-Plus + MySQL 8 / Vue 3 + Vite 5 + Element Plus / Nginx

---

## 1. 背景与目标

一期 Demo（Python server.py + SQLite）已交付并完成多轮增强：15 中文字段、148 条数据、139 张照片、导入导出/脱敏/选中下载、UI 精简与修复。现进入正式版开发。

**目标**：以 Demo 为功能蓝本，重构现有正式版骨架（backend/frontend），补齐登录鉴权、角色权限、照片上传 UI、审计留痕、数据迁移等正式版要素，并保持员工页/管理页交互与 Demo 一致。

**推进方式（已确认方案 A）**：重构正式版骨架，一步到位对齐 Demo 全部能力并补足正式版要素，不保留两套并行代码。

## 3. 总体架构

```
浏览器（Vue3 SPA）
   │  Nginx（/ → 静态资源，/api → 8080）
   ▼
Spring Boot 3.2.5（0.0.0.0:8080）
   ├─ Controller（REST /api/*，输入校验）
   ├─ Service（业务规则：脱敏、审计、权限）
   ├─ Repository（MyBatis-Plus Mapper）
   └─ MySQL 8（expert_system 库）
```

- 分层：Controller → Service → Repository，业务逻辑不进 Controller。
- 目录结构：按 feature-first 组织（auth / expert / user / audit / common）。
- 统一响应结构 `{code, message, data}`；全局异常处理。
- JWT 认证中间件 + RBAC 角色校验（管理员接口加 @RequireAdmin）。

## 5. 认证与权限

### 5.1 一期：账号密码登录

- `POST /api/auth/login`：校验 username + password（BCrypt），签发 JWT。
- 初始密码 `111111`，管理员在用户管理中重置；**建议首次登录强制修改密码**（后端标记 must_change_password，登录接口返回后前端引导改密）。
- Token 传递：推荐 httpOnly cookie（防 XSS）；一期可接受 Authorization: Bearer，但**不存入 localStorage**（前端内存变量 + 刷新后重新登录或 cookie）。

### 5.2 二期：企业微信扫码登录（预留）

- 申请清单：corpid、自建应用（agentId / secret）、可信域名（网页授权回调）、回调地址 `/api/auth/wecom/callback`。
- 流程：前端扫码 → 企微 OAuth 回调 → 后端用 code 换 userid → 校验为本公司员工 → 自动登录并带入姓名 → 直入系统。
- 员工映射：一期以姓名/手机号匹配 sys_user；二期以 wecom_userid 精确绑定。
- 一期代码中预留接口占位（`/api/auth/wecom/qrcode`、`/api/auth/wecom/callback` 返回"未配置"提示），应用申请下来后启用。

### 5.3 RBAC

- 角色：`EMPLOYEE`（普通员工）/ `ADMIN`（管理员）。
- 管理员名单 = sys_user.is_admin=1（系统内固定名单，管理页「用户管理」维护）。
- 管理接口（写操作、用户管理、审计查询、完整数据）要求 ADMIN；员工页查询要求登录即可。

## 9. 脱敏与下载规则

- **查看脱敏**：身份证号、银行卡号前 3 后 4（员工角色；管理员全量）；身份证正反面图片与银行卡开户行**不在查看页展示**（员工与管理员的查看页均不展示，仅管理页维护）。
- **下载全量**：所有登录员工可下载完整身份证 / 银行卡 / 银行卡开户行数据（CSV / ZIP / MD / 选中导出均全量）。
- **下载包含图片**：ZIP 下载内容包含证件照、身份证正面、身份证反面三张图片，图片按第 8 章业务命名规则导出（姓名 + 单位 + 科室 + 类型后缀）。
- **审计留痕**：所有下载接口写入 download_log（谁、何时、专家、类型、IP）。
- **下载次数展示**：专家卡片显示 `COUNT(download_log.expert_id)`，实时查询。
- 一键复制功能：保持 Demo 行为，排除身份证号、银行卡号。

## 10. 数据迁移（SQLite → MySQL）

1. 备份原 SQLite（`experts.db`）。
2. 迁移脚本（Python 或 SQL）：
   - 读 SQLite 15 中文字段 → 映射英文列名 → 写入 MySQL expert_info；
   - 保留 id 或重建 id（需维护照片引用映射）；
   - 照片文件从 demo/uploads 复制到 `<LOCAL_PATH>`，按新 id 重命名 `avatar_<id>_<时间戳>.<ext>`，并回写 photo 字段；
