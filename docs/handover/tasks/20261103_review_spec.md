## Spec

### 1. P1 默认开启的个人提醒实际上不会覆盖首次收藏且未操作的用户
- 需求：docs/requirements/2026-11-02-企业合规板块个人关注驱动待办改造V3-需求文档.md:159、269，所有我的待办默认提前3天与当天提醒。
- 代码：backend/src/main/java/com/jshz/expert/service/ComplianceService.java:414，缺少个人记录时仅向界面返回 remindEnabled=1；KnowledgeFavoriteService.java:35 收藏未建立个人进度。scheduler/ComplianceDueScheduler.java:100 仅遍历已存在的 compliance_user_progress。
- 触发：用户只收藏文档，从未修改进度或提醒。界面显示默认开启，调度却没有此用户记录，个人提醒漏发（责任人全局提醒是另一条路径）。
- 验证建议：新用户收藏带到期事项，查询个人记录，再在隔离时钟运行调度并断言通知。

### 2. P1 取消收藏后个人提醒仍会发送
- 需求：同文档:226 明确取消收藏暂停个人提醒。
- 代码：scheduler/ComplianceDueScheduler.java:100-123 没有查询收藏关系；KnowledgeFavoriteService.java:59 取消收藏与 ComplianceService 的历史保留语义不会移除个人记录。
- 触发：先修改个人进度建立记录，再取消收藏，事项仍公开且到期落在窗口。调度仍发送。
- 修复方向：发送前按收藏/责任人规则重新检查资格，保留历史记录；不能用删除个人记录解决。

### 3. P2 提前提醒变成窗口内每天提醒，文案日期也不准确
- 需求：同文档:159、269 规定提前3天一次、当天一次。
- 代码：scheduler/ComplianceDueScheduler.java:112 的 window 接受整个提前天数窗口；116/117 以每天08:30为幂等节点，因此提前3/2/1天均发送；118 文案始终写配置天数，而非实际剩余天数。全局路径77同样按窗口发送，且未排除过期事项。
- 验证建议：固定连续四个日期运行同一事项，预期恰好两次，而非四次。

### 4. P1 所谓失败重试实际上被唯一键拦截
- 需求：同文档:229、257、289 发送失败允许有上限重试。
- 代码：scheduler/ComplianceDueScheduler.java:130-155 每次先插入日志，DuplicateKeyException 直接返回；失败日志保留 PENDING/retryCount=1，下次同节点插入冲突即退出。未找到扫描PENDING日志重试的其他任务。
- 影响：瞬时发送失败可能永久丢失该提醒；retryCount>=3 分支在正常重跑路径无法到达，属于疑似无效恢复分支。
- 验证建议：通知依赖首次抛错、后续成功；重复运行同节点，应最终SENT且不重复通知。

### 5. P2 责任人编辑会重复通知新责任人，并再次通知旧责任人
- 需求：同文档:236 仅通知新责任人，旧责任人记录保留但不通知。
- 代码：service/ComplianceService.java:123-130 在保存后对新增uid通知；saveAssignees:617-630 删除重建全部关联且对每个uid通知。新增者通知两次，保留者也收到分配通知。
- 验证建议：已有A，改成A+B；断言A零条、B一条分配通知。
