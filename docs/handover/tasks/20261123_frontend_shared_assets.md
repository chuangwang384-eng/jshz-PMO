# 前端快照瘦身与共享静态资源

## 目标与基线

- 任务 20261123-frontend-shared-assets，主责 Codex，2026-11-23。基线 `main` 的 `31cd1d6`。生产开始时为 1.0.133，Nginx 入口在 `1.0.133-idcard-risk`。
- 用户批准定点清理前端旧发布目录，保留五个正式快照和当前回滚副本。共享资产兼容窗口为七天，此轮提交实现及隔离验证，生产切换单独审批。
- 现网清理前核实主目录、HTTP 首页及回滚配置。两条回滚路径为 `1.0.132-expert-idcard-expiry` 和 `1.0.133-idcard-risk.rollback`。预演列出 158 个候选，约 86.9 GiB 逻辑大小。
- 生产清理已完成。原脚本逐目录清理 31 个，验证隔离并发清理后续跑 127 个。D 盘可用空间由约 37.5 GiB 增至 126.1 GiB。最终仅保留 1.0.129 至 1.0.133 五个正式快照和 1.0.133 的回滚副本。
- 清理后确认生产首页和主脚本的 HTTP SHA-256 与磁盘一致，回滚入口与 1.0.132 入口一致，后端 1.0.133 健康。日志 `logs/frontend-storage-cleanup-20261123-verified.log`。续跑外层命令因旧版脚本未设置进程退出码误报失败，随后直接逐项核验确认清理已完成。修订版脚本显式返回退出码。

## 实现和验证

- `frontend-shared-assets.ps1` 建立共享目录、硬链接、快照清单和七天兼容记录。同名资源冲突以内容 SHA-256 拒绝，所有存放目录须在同一 NTFS 卷。
- `deploy-frontend-graceful.ps1` 构建正式与回滚快照。Nginx 沿用现有根目录及 URL。既有旧快照按原方式服务。
- `release-full.ps1` 校验线上主脚本的 HTTP 哈希，验证通过后清理。共享快照回滚时保留仍在窗口内的浏览器依赖。回滚验证失败时恢复切换前的 Nginx 配置。
- `prune-frontend-releases.ps1` 同时保护现网根目录、配置所指回滚目标及最近的正式快照，删除过期兼容链接。月度任务仍由 `prune-all.ps1` 调用同一清理入口。PowerShell 7 可在已经预演的情况下并发清理。
- Windows PowerShell 5.1 及 PowerShell 7 均使用 `scripts/tests/frontend-shared-assets-regression.ps1` 做隔离回归，覆盖硬链接身份、旧快照迁入、资源冲突、锁、七天回收、回滚兼容和保留规则。初次运行发现 5.1 不能用空备份路径调用 File.Replace，修正后通过。
- 本轮不涉及数据库、项目 API、权限及应用版本变更。部署说明见 [前端保留策略](../../deployment.md)。
- 共享实现通过 Windows PowerShell 部署 HTTP 回归。生产目录尚未启用共享存储。月度计划任务查询返回拒绝访问，实际注册和最近运行结果待授权核实。

## 下一步与回滚

- 待单独批准生产切换后，先复核 Nginx root、NTFS 卷、前后端版本和审批范围，尤其区分待发布的应用功能与本次部署工具变更。
- 首次切换需验证入口和主包哈希、旧页面动态加载和回滚快照入口。需撤回工具变更时回滚该 Git 提交。已启用共享时，先保留可用旧快照与硬链接，按发布说明切回后再处理共享文件。
