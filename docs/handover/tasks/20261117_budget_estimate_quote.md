## 业务与使用

- 线下预算输入参会人数、外埠人数、场次、城市档位、工作人员数和天数。另选大交通及地面交通方式。首次预览只补当前空白字段，已录入值和明确的零保留。应用之后再次预览默认不选择任何行，由用户确认行级变更。应用依据随预算保存。现有物料单价提示核对，估算不会把历史单价当作数量。
- 住宿按外埠人数预留房间，无外埠人员预留两间。茶歇取参会人数的 70%，向上取 5 的倍数。机票按外埠人数和 2000 元/人估算，高铁按一等座询价。车队数量按参会人数乘 2，单价待询。平台专车一线和其他城市分别按 200 和 100 元/人。人员费用为人天乘收费标准的参考单价。
- 项目配置的线下收费标准标出数量规则和参考单价。日程为参会人数加区间下限，台卡同理。展架按场次乘每场数量。单位为张、张、个，三项单价由用户填写。管理员调整标准后，已有草稿在重新加载标准和预览时可选择应用。
- 线上和线下预算内部确认后，可以生成带版本号的对客 XLSX。版本及文件同时登记到预算阶段资料。下载遵循项目阅读权限。项目成员可以登记该版本的客户确认人、确认时间、备注和已有项目凭证。相同登记重试返回原记录。更正报价可从现有版本另存草稿，再内部确认和生成新版本。客户确认不影响现有的阶段推进条件。

## 接口和数据

基路径为 `/api/project/{id}/meeting-budget`。原 PUT 可选 `estimateInputs` JSON 对象，用于持久化输入和应用依据。确认后的预算通过报价版本恢复为草稿后可继续编辑。

| 方法和路径 | 行为 |
| --- | --- |
| GET /quotes | 项目可读人员查询报价版本及客户确认状态 |
| POST /quotes | 项目成员在当前会议预算阶段生成报价，参数为 UUID `requestKey` 和可选 `clientNote`，同请求标识幂等 |
| GET /quotes/{versionId}/file | 校验项目读取权限后下载指定版本 XLSX |
| POST /quotes/{versionId}/customer-confirmation | 项目成员提交 `customerName`、`confirmedAt`（本地 ISO 时间）、可选 `remark` 和 `evidenceDocId` |
| POST /quotes/{versionId}/restore | 项目成员在当前会议预算阶段从指定版本另存草稿，已有草稿时拒绝覆盖 |

`project_budget.estimate_inputs` 保存估算输入、应用状态和规则依据。旧数据保持 NULL，无业务回填。 `project_budget_quote` 按项目及版本号唯一，另以项目及请求标识唯一。 `doc_id` 关联阶段资料，`snapshot` 保存预算备注、估算输入及原明细供恢复使用。确认字段保存客户确认人、业务确认时间、备注、可选项目资料 ID、系统登记人和登记时间。
