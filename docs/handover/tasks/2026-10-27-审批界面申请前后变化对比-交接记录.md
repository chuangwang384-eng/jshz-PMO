## 8. 风险与回滚
- 已知问题：管理员直编/删除专家仍会物理删除旧照片文件，历史快照照片可能失效 → 前端 PhotoImage 降级为「已清理」占位。
- 数据风险：回填已执行完毕（幂等可重跑）；rollback 路径 = `UPDATE application SET biz_data = JSON_REMOVE(biz_data, '$.oldData')`（非破坏性，可逆）。
- 兼容性风险：/api/files-tmp/** 新增临时照片可读面（登录即可读），文件名随机不可枚举，未放开匿名。
- 回滚步骤：代码 revert → 后端重跑 deploy-backend.ps1（UAC 提权）→ 前端 rollback-frontend.ps1（回滚点 frontend/releases/1.005-20261027_140358）→ biz_data.oldData JSON_REMOVE。后端旧 jar 无独立归档目录（wrapper 直接覆盖 target/expert-system-1.001.jar），回滚需 git revert 后重新 mvn package 再走发布流程。
- 回滚限制：若已执行回填且后续有新建专家，JSON_REMOVE 不影响 changes 主数据。
