## 第一部分：后端审查结果

### 1.1 已排除的项（排查后确认无问题）

- **SQL 注入**：未发现 `${}` 拼接，`apply()` 均用 `{0}` 参数化，注解 SQL 全部参数化
- **路径穿越**：各存储服务均有 `safeName + startsWith` 双重防护
- **CORS**：固定 3 个内网来源 + credentials，配置正确
- **密钥管理**：application.yml 无明文密钥，全部走环境变量且 JWT 密钥空值时启动 fail-fast（唯一瑕疵：`MYSQL_USER` 默认回退 `root`）
- **日志脱敏**：企微 secret/access_token/手机号脱敏纪律良好

### 1.2 高危（High）

|---|---|---|---|
| H1 | `service/ApplicationService.java:419,477,495,517` | **审批流核心多表写无事务**：submit/approve 等入口（申请单+合同状态+快照+审批记录+操作日志 5 处写）均无 `@Transactional`，中途失败产生半提交脏数据 | 写入口统一加 `@Transactional(rollbackFor = Exception.class)`；照片 IO 移到事务提交后 |

### 1.5 后端总体评价

**建议修复顺序**：H1/H2 → H3 → M6 → H4 → 其余排期。
