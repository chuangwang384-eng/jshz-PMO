## 三、发现的问题与风险

### P1 — 需跟进，不阻断本次验收

**P1-1｜并发双批与合同联动缺少真实数据验证**
- 现状：`application` 中 `status=0`（待审批）为 **0 条**，`project_contract` 为 **0 条**，生产无可用单据。
- 影响：`claimPending` 的 409 抢占、合同状态联动（`syncContractByApproval` 抛异常回滚）在真实库上未被触发过；已验证的只有反射/单测与字节码存在性。
- 建议验证：出现新的待审批单时，让两名审批人**同一秒点「通过」**，预期一方成功、另一方收到 409「该申请单已被其他审批人处理」；再核对 `application.status` 仅被推进一次、`approval_record` 仅 1 条 APPROVE、专家/合同不重复。

**P1-2｜`logs/expert-backend.err.log` 存在 Java Agent 启动失败与关停异常**
- 现象：`*** java.lang.instrument ASSERTION FAILED *** ... Agent failed to start!`（1 次），`com.baize.aegis`（安全代理）在 shutdown 时 `destroy()` 报错，以及 `SpringApplicationShutdownHook` 中 `NoClassDefFoundError: ch/qos/logback/classic/spi/ThrowableProxy`。
- 归因：`NoClassDefFoundError` 同类块在 err.log 中**重复 11 次、跨越多次发布**，属既有现象（JVM 关停瞬间 jar 已被替换/关闭导致嵌套 jar 类读取失败，进程即将退出，不影响业务）。Agent 失败仅 1 次，err.log 无时间戳，**无法确定归属进程**（可能是被强杀的 8081 影子进程）。
- 影响：不影响当前 12680 进程健康（Tomcat 正常、DB 连接正常、无业务异常）。但若该 Aegis 代理属公司要求的终端安全组件，需运维确认此机器是否为既定豁免。
- 建议：给 err.log 加时间戳前缀；部署脚本停止服务后增加「等待进程真正退出」再替换 jar，消除关停期类加载竞争。

## 五、改进建议（按性价比排序）

1. **发布脚本日志统一 UTF-8**（`Out-File -Encoding utf8` 或 `[IO.File]::WriteAllText`），并把 .cmd/.bat 生成规则固化为「纯 ASCII + CRLF」，避免再出现本次的解析乱码事故。
2. **发布记录改为追加表格行**：`| 时间 | 版本 | 结果 | jar |`，不再重复写二级标题。
3. **版本单一来源**：由 `version.txt` 注入 `pom.xml` 的 `<version>`，让启动日志、`/health`、归档目录名三者一致。
4. **`/health` 增加 `buildTime` 与 `gitShort`**，验收时可一眼确认「跑的是哪个提交」，不必反编译。
5. **发布后自动巡检**：健康、版本、无 token 401、首页资源 200、关键表行数，任一异常即告警。
6. **日志轮转**：logback `RollingFileAppender`（按天 + 单文件上限），并给 `err.log` 加时间戳。
7. **停止服务后轮询进程消失再换包**，消除关停期 `NoClassDefFoundError`。
8. 清理 `.build-h1h2-20261106`（保留 jar 与日志即可），并按既有清理清单推进第 1 档。
