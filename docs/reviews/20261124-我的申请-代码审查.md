## 1. 结论摘要

1. 1.0.138 的修复（通知补齐、本人判定双条件、照片重传、轮询驱动收口、合同单误报历史数据）经代码核对**确已落地**，主链路状态机（0→1/2/3/4，4→0）无越权与并发重复审批缺口，`claimPending` 的原子抢占是正确设计。
2. 仍存在 **3 个 P1 级缺陷**：`biz_data` 解析失败静默降级且审批仍可通过（会导致"审批通过但字段没生效"）、列表接口分页参数无边界叠加逐行 N+1 查询、合同退回后重提未回写合同状态（存在同一合同两张在审单的路径）。
3. 存在 **6 个 P2 级缺陷**，集中在输入校验口径不一致（修改申请无姓名/单位校验）、脱敏口径自相矛盾（变更前脱敏、变更后明文且注释已过期）、前端请求并发/边界处理缺失、申请原因长度口径不一致。
4. 存在 **1 处"文档声称已修但代码未修"** 的偏差：`docs/architecture.md:167` 写"biz_data 异常不再静默吞掉"，实际 `readBiz` 仍为空 `catch` 无日志。
5. **CONTRACT 类型整体无 UI 入口**：`POST /api/approval/contract-request` 全前端零调用，`MyApproval.vue` 与 `ApprovalDiffDialog.vue` 中的合同分支目前是"提前实现但不可达"代码。

## 2. 现状基线（接口面 / 状态流转 / 展示面）

### 2.1 本板块实际调用的接口

| 动作 | 方法与路径 | 入口 | 鉴权 |
| --- | --- | --- | --- |
| 列表 | `GET /api/approval/my-applications?page&size&status` | 页面挂载、筛选、轮询、操作后 | 登录即可，Service 内 `applicant_id OR applicant` 双条件限本人 |
| 撤回 | `POST /api/approval/requests/{id}/withdraw` | 列表行内（status=0） | 登录即可 + `isApplicant` |
| 重提 | `POST /api/approval/requests/{id}/resubmit` | 列表行内（status=4） | 登录即可 + `isApplicant` + status=4 |
| 临时照片 | `POST /api/approval/photo-upload` | 重提弹窗「重新上传」 | 登录即可 |
| 上传限额 | `GET /api/meta/limits` | 页面挂载（`ensureUploadLimits`） | 登录即可 |
| 深链取单 | `GET /api/dashboard/focus/application/{id}` | 工作台/通知深链 `?applicationId=` | 登录即可 + 本人校验 |
| 照片预览 | `GET /api/files-tmp/*`、`GET /api/files/*` | 对比弹窗 `PhotoImage` | 登录即可 |

权限路径核对：`permission` 表中 `my-applications` / `withdraw` / `resubmit` 均**无规则行**，按 `DbPermissionFilter` 第 28 条语义"未命中规则=登录即可"，与设计一致（不扩大权限面）。

### 2.2 状态流转（实测代码路径）

| 动作 | 前置 | 后置 | 执行人 | 关键校验 |
| --- | --- | --- | --- | --- |
| 提交修改/新增 | — | 0 | 申请人 | 非 `expert:edit`、流程启用、白名单、照片 `TMP:`+临时文件存在 |
| 提交合同 | 合同 DRAFT/REJECTED | 0 | 申请人 | 流程启用、仅身份证/银行卡 |
| 通过 | 0 | 1 | 审批人 | `checkAssignee` + 快照 + `claimPending` 原子抢占 |
| 驳回 | 0 | 2 | 审批人 | 意见必填 + 抢占 |
| 退回 | 0 | 4 | 审批人 | 意见必填 + 抢占 + 保留临时照片 |
| 重提 | 4 | 0 | 申请人本人 | 流程仍启用 + 字段/照片校验 + 条件更新防并发 |
| 撤回 | 0 | 3 | 申请人本人 | `claimPending` + 抢占 |
| 转办/加签 | 0 | 0 | 审批人 | 目标须有 `approval:audit` |

**缺口（无出口的状态）**：`4`（退回修改）不可撤回、不可放弃；`2`（已驳回）不可复开；`3`（已撤回）不可恢复。其中 `4` 是唯一"既不能前进也不能终止"的状态，见 R3。

## 5. 新需求建议（均限于本板块，不改其它板块）

### R1 列表筛选与检索增强（状态 + 类型 + 时间范围 + 关键词，URL 回存）

- **价值**：当前仅有"状态"一个筛选。`application` 自 2026-10-26 迁移起持续累积（迁移一次性 31 条 + 新增），个人单据随时间增长，靠翻页定位成本高；URL 回存可让"某状态视图"被通知/工作台/他人分享复用。
- **实现边界**：仅给 `GET /api/approval/my-applications` 增 `type/keyword/startDate/endDate` 参数，**仍强制 `applicant_id OR applicant` 本人过滤**（不得放宽）；不新增权限码、不改表结构（`JSON_EXTRACT` 用法在 `listRequests:402` 已有先例）。
- **改动范围**：`ApplicationController.myApplications`（参数+校验）、`ApplicationService.myApplications`（wrapper 条件）、`MyApproval.vue`（筛选条 + query 同步 + 重置页码）。2 个后端文件 2 处、1 个前端文件。
- **风险**：`biz_data` 的 `JSON_EXTRACT` 无索引，个人数据量级可控（千级），若未来超万级需引入普通列或虚拟列；关键词检索需明确"只搜专家姓名还是也搜申请人/原因"。

### R2 列表展示"当前处理人 + 停留时长"（时效可视化）

- **价值**：现在只有处理完成后才有"审批人/审批时间"，待审批期间申请人不知道单子卡在谁手里、卡了多久；这是 `docs/reviews/20261117-产品审查-04` 已登记的"审批时效纯缺口"的最小可用补充，且**不改状态机**。
- **实现边界**：只做只读派生字段（`currentAssigneeName` + `pendingHours`，或签场景取快照首个可见审批人）；数据源已有（`current_assignee`/`extra_approver`/`approver_snapshot` 均已在实体中、前端尚未使用）；不新增接口。
- **改动范围**：`fillView` 增加派生计算、`MyApproval.vue` 增 1–2 列（或状态列内 badge）。1 后端 1 前端。
- **风险**：或签/加签下"当前处理人"定义需产品确认（多审批人时展示"张三等 3 人"还是首位）。

### R3 退回修改单支持「放弃/终止」（4 → 3）

- **价值**：`status=4` 是目前唯一"既不能前进也不能终止"的状态（不可撤回、不可重提则永久滞留）。人员更替、信息失效、申请人放弃时无出口，"退回修改"筛选项会长期堆积脏单。
- **实现边界**：仅申请人本人、仅 `status=4`；复用 `withdraw` 的 `claimPending` + `isApplicant` + CONTRACT 回 `DRAFT`；**建议先复用状态 3（已撤回）并在文案区分**，不新增状态值（新增 5 需 DB 迁移 + 全链路字典 + 报表口径，成本远高于收益）。
- **改动范围**：`ApplicationService.withdraw` 前置状态放开为 `{0,4}`、`addRecord` 节点文案区分、`MyApproval.vue` 增按钮与二次确认。1 后端 1 前端，无 DB 变更。
- **风险**：复用状态 3 会让"已撤回"含义扩大（含主动放弃），若报表按 3 统计需同步口径；需 product 确认是否接受语义合并。

### R4 我的申请导出（CSV，仅本人）

- **价值**：个人留痕、跨部门核对、审计取证；审批记录与变更明细已在库中完整，属"纯查询即可交付"。
- **实现边界**：只导出本人数据；**敏感字段默认脱敏**（先在 Q5 口径确定后实施）；限制时间范围与最大行数（如 5000）并写 `operation_log`；登录即可，不新增权限码。
- **改动范围**：`ApplicationController` 增 `GET /my-applications/export`（复用 `downloadFile` 前端 helper），`MyApproval.vue` 增按钮。1 后端 1 前端。
- **风险**：导出会把身份证/银行卡带出系统，必须与 Q5 的脱敏口径一起决策；建议默认脱敏 + 超管才可明文。

### R5 移动端卡片视图（企微内打开）

- **价值**：现有表格 9 列最小宽度约 1490px，手机端只能横向拖动；本系统在企微内使用频率高，查看审批结果/退回意见是移动端高频场景。
- **实现边界**：仅在 `MyApproval.vue` 增加 `≤768px` 的卡片布局（复用 `SupplierList` 双视图模式），字段精简为 专家/类型/状态/时间/操作；接口零改动。
- **改动范围**：1 个前端文件（模板分支 + 样式）。
- **风险**：两套展示需同步维护；卡片必须保留"重新编辑提交/撤回"入口，否则移动端无法处理退回单。
