# AI 能力现状与产品化机会评估（ai-product）

> 来源：分析师子代理（run 707215ec participant 4）2026-11-17 完成，因子代理无写盘权限，由主 Agent 代为落盘。只读评估，无代码/数据库/配置变更。

分析人：AutoClaw，2026-11-17。基线：`version.txt=1.0.50`（今晨已发布，交接文档核于 1.0.46，AI 代码为本日现读，无漂移迹象）。证据分档：确定=本轮核对代码/文档原文；高置信=多迹象一致未逐字核对；推测=逻辑推出。

## 1. 问题定义

在单机本地模型（qwen2.5:3b）约束下，判断哪些 AI 产品化机会值得投入、哪些现在不该做。判断标准：用户价值 × 本地模型能力边界的匹配度 ÷ 数据边界风险。

## 2. A. 现状事实清单

### AI 已落地的链路（4 条 LLM + 2 条非 LLM）

| # | 链路 | 形态 | 证据 |
| --- | --- | --- | --- |
| 1 | 简历解析语义层 | 启发式打底 + LLM 抽取 5 字段，带原文回指校验（值须在归一化原文、单位须组织后缀），候选字段人工确认 | `ResumeParseService.java` L280-305 |
| 2 | 日程解析兜底 | 规则打底 → 未解析块送 LLM：角色限 4 枚举、姓名回指、议题/时间覆盖率≥60、超时重试 1 次、按出场去重 | `ScheduleParseService.java` L336-375 |
| 3 | 合规 LLM 标记 | 事项草稿提取 + 表格碎片结构化（上限 100 条、isDraft=1）；幻觉过滤=对原文覆盖率<80% 整条丢弃；重要性标记 priority=HIGH，失败静默回退全 MEDIUM | `ComplianceParseService.java` L136-235、`ComplianceService.java` L450 |
| 4 | AI 问答/助手 | **不是生成式 QA**：bigram 关键词打分 → 权限过滤 → 强匹配出人工维护卡片（答案+步骤+深链，行动意图仅路由导航）；弱匹配走 3b 闲聊（20s 超时、150 字、禁编造路径）；候选歧义时 LLM 仅做 entryKey 选择。前端全局抽屉 + ai:manage 管理页，种子 20 条全为系统操作 | `AiAssistantService.java`、`AiAssistantController.java`、`init.sql` L1995-2030、`AiAssistantDrawer.vue` |
| 5 | 非 LLM：OCR/抠图 | PP-OCRv5+Tesseract；U²-Net 抠图逐图起 Python 进程（单图 ~6s，进程启动是常态瓶颈），全链热解析 7.7-10s | 20261113_ai_model_migration.md 实测 |

**通用模式（确定）**：所有 LLM 链路都是"规则打底、LLM 增强、失败回退、人工确认"——模型是可选增强层，不是依赖项。这是本产品最重要的架构资产。

### AnythingLLM 与 RAG 现状

- AnythingLLM 已本机部署（127.0.0.1:3001，Docker，用宿主 qwen2.5:3b）但**未接入产品**："无应用代码、数据库迁移、接口和权限改动。未导入公司资料，未验证嵌入或端到端检索"（20261116_anythingllm_local.md 原文）。
- bge-m3 已装入 Ollama（1024 维），**首次单条嵌入实测 58.5 秒**（keep_alive:0）——冷态完全不可用于在线查询路径；常驻延迟未实测。
- RAG 可行性结论（20261116 评估）：小规模系统操作知识库具备本地试点条件；建议 bge-small-zh-v1.5 CPU ONNX + 内存余弦（1 万向量 ≈19.5 MiB）；30-50 条真实问法对照评测；独立开关。**原型、延迟、并发、精度全部待验证。**
- 后端无任何向量/嵌入代码（grep embedding/vector/cosine/lancedb = 0）——RAG 是绿地。

### 本地模型约束

- 硬件（11-16 实测）：4C8T / 16 GiB（检查时可用仅 ~2.4）/ GTX 1650 4 GB（已用 2846 MiB，3b 驻留 2.0 GiB）——显存与内存余量均已见底。
- 冷启动：D 盘加载 5.9s、首请求 8.6s；已有缓解（启动预热 + keep_alive 60m + 5 分钟探测自动重启，deployment.md L758）。
- 并发：未实测（高置信单卡串行排队）；交互场景靠 20s 短超时+回退保可用。
- 3b 能力边界（高置信，从产品设计反推）：严格 JSON 抽取+枚举+覆盖率过滤=已验证；自由生成弱（闲聊被限制在 150 字无链接）；长文汇总/多跳推理零验证。

## 4. 矛盾与隐藏假设

1. **产品承诺 vs 代码**：种子条目 KNOWLEDGE_SEARCH 宣称"知识星球支持…语义问答"，但 `KnowledgeDocumentService` L123-127 只有 LIKE——承诺未兑现。做 O2 或改文案，二选一。
2. **代码默认 vs 实装**：`OllamaService` 默认模型 qwen2.5:7b，机器实装仅 qwen2.5:3b（11-16 /api/tags）；生产 11-13 正常工作过 → 高置信 NSSM 已注入 OLLAMA_MODEL=3b，但仓库无法证实（start-backend.bat 无 OLLAMA 行）。**若该注入丢失，全部语义层静默失效**（available() 只查 OLLAMA_URL）。
3. 时间差非矛盾：交接核于 1.0.46，今晨 1.0.50 已发布。

## 5. C. 明确不建议现在做

1. **AnythingLLM 接入产品**：独立账号体系 + 库外 LanceDB/SQLite 绕过产品权限模型与审计；未导入资料、嵌入器未切换、端到端未验证。保持"评估沙箱"定位。
2. **外部大模型/API**：AGENTS §6.1 默认禁令；本地栈已覆盖已验证场景。
3. **自然语言查库**：3b+101 表，幻觉与越权双高危。
4. **会议纪要/ASR**：无数据源、无基建、硬件边际。
5. **AI 自动执行/写入**：违反产品既有"候选+人工确认"模式（§6.4）。
6. **为更大模型升硬件**：显存已满，但已验证场景的瓶颈不在模型尺寸（抠图=进程启动，检索=没建索引）；先拿试点数据再谈硬件。

## 6. 推荐

**首选**：O1+O2 合并为"合规语料优先的 RAG 问答试点"主线，O3 内容运营并行。**前提**：按可行性文档执行（隔离环境、30-50 问、独立开关、对照评测）；嵌入走 bge-small-zh CPU（bge-m3 的 58.5s 冷测不可接受）；查询时按 status+category+项目权限过滤。**最强反方**：若评测显示 3b 带出处准确率不达标（如 <80%）或 P95>5-8s，RAG 应降级为"纯检索+原文定位"（去生成）——最早信号是评测中无出处断言的比例。**备选**：O3 独立先行，不依赖任何模型验证。
