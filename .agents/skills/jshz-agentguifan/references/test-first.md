# PMO 测试先行

适用于新增或修改业务行为、修复可自动化复现的缺陷。先从需求、业务规则或真实症状确定可观察结果。若验收规则存在实质歧义，按仓库约定先确认。测试入口可沿用同类模块已经验证的接口。

1. **写测试并见红。** 选择一个业务切片，从公开的 API、Service 契约或用户操作入口断言结果。优先复用项目已有测试和合成数据。预期值依据规格或可独立核算的样例。先运行目标测试，确认失败来自待实现行为或原缺陷，记录实际失败原因。环境、构建或认证设置错误应先排除。
2. **最小实现并见绿。** 只实现该切片需要的行为。重跑同一测试确认通过，再跑受影响的相关回归。随后进入下一个切片。需要重构时，在测试通过后进行，并保持断言的业务含义。
3. **验证适用的边界。** 依变更覆盖旧数据、空值、异常、权限拒绝和并发。例如结算资料删除测试先断言删掉当前批次最后一份后，必填仍待提交，历史批次未恢复为当前。涉及项目间数据隔离时配合防御性安全审查清单核对允许与拒绝路径。
4. **保留证据。** 交接记录写明测试入口、见红原因、见绿和回归命令。无法自动化时提供可复现的手工验收步骤及原因。纯文档、纯配置或发布检查依实际风险验证。
