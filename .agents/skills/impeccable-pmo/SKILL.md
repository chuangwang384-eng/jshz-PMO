# PMO 界面审查与改进

本技能是 [Impeccable](https://github.com/pbakaus/impeccable) 四项工作流的项目级改编。取材于上游提交 `b49177d32788f2dc585c42831d845dacf1ebed2c`，采用 Apache-2.0，原许可证和 NOTICE 随附。

开始时确定目标页面或组件、用户任务、数据状态和本次授权。以当前 `AGENTS.md`、Vue 组件和 `frontend/src/styles/ui-tokens.css` 为准。改前端时沿用仓库的 `modern-web-guidance` 流程。优先复用 Element Plus、现有组件和令牌，保留 Dashboard 与供应商模块受保护的配色，并按仓库约定验证。

## 四种工作方式

- **critique（可用性审查）**：沿一个真实任务检查入口可发现性、信息优先级、完成状态、操作反馈、错误恢复和危险操作距离。用实际用户角色走读顺序。输出按影响排序的问题，逐条注明位置、观察到的行为和修改建议。
- **audit（技术审查）**：检查语义和控件名称、键盘与焦点顺序、对比度、窄屏溢出、状态播报、主题令牌和可复现的性能问题。优先用代码定位及浏览器观测。只读输出严重度、证据、修复建议和待验证项。
- **harden（边界状态）**：用合成数据检查空、加载、失败、重试、重复提交、禁用态和长文本。经用户授权时修复已确认问题，并验证主要流程和异常恢复。表单以服务端返回和实际保存结果支撑成功反馈。
- **adapt（响应式适配）**：在宽屏及窄屏核对主任务、表格、操作按钮、内容换行和触屏可操作性。专门验证长项目名、长文件名与结算细项。经用户授权时实施局部改动，并在相应尺寸复验。区分视口模拟、触控模拟和物理设备结果。

审查默认只读。实现以任务授权为准。用本机源码和受控浏览器检查，记录实际范围与限制。该项目改编不使用上游自动钩子、Live 模式、引擎、联网探测或自动报告落盘。
